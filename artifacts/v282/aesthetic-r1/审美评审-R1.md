# CatOS v2.82 界面与观感评审 · 第一轮（审美 R1）

> 评审日期：2026-11-27 · 对象：release 镜像 `kernel_v25/catos-v2.82.iso`、自启动镜像 `kernel_v25/catos-v2.82-test.iso`
> 方法：QEMU 实机抓屏（screendump → PPM → PNG），共 18 张，同目录 `screen-text-dump.txt` 留存逐屏文本。
> 边界：本轮**不改代码**，只出评审、截图与清单。功能正确性已由第一关核查通过；本文只在观感与交互表层落锤，凡涉及功能交叉项均单独标注，留待功能关复核。

## 0. 总评

**一句话结论：** 终端壳的配色骨架与信息层次已经站得住（深色高对比、角色色分工明确、主题可跨重启持久化），但块桌面仍是「单 Demo 窗口 + 占位块」的原型状态，且 shell 与 GUI 两套配色不同源、实时切换不刷新，light 主题下出现半明半暗；本轮优先修「主题一致性」与「桌面任务栏/窗口基础对齐」，图标、圆角、阴影属可排期的下一层打磨。

## 1. 必改清单

### P0（本轮必须修：观感上"没接好"的一致性硬伤）

#### P0-1 · shell 与 GUI 主题不同源，且 `theme light` 后已构建的桌面不刷新
- **现象：** 控制台切到 light 后（`13-shell-light.png`：底 `#F6F6F4`、前景 `#24292F`、报告 `current theme: light`），`gui` 重进桌面仍是整套暗色（`14-desktop-light.png`：底 `#1E1E26`、面板 `#2A2A34`、任务栏 `#3A3A48`）。冷启动同一磁盘才出 light 桌面（`15-desktop-light-reboot.png`）。
- **证据：** `13-shell-light.png`、`14-desktop-light.png`、`15-desktop-light-reboot.png`；源码 `src/gui/chrome.c:730-741`（`gui_demo_build()` 读 `cdeconf_scheme()` 才选 token）、`src/gui/tokens.c:10-31`（GUI 自有暗/亮两套色）、`src/palette.c:50-59,207,219`（shell 自有暗/亮色与强调紫 `#8250DF`）。
- **期望改成什么：** 二选一，建议前者：
  1. 进桌面/切主题时让 GUI 重新读一次当前 scheme 并重绘 token（`gui_theme_set(TOK_LIGHT/TOK_DARK)` 随 `gui_demo_build()` 或重入路径生效）；
  2. 若本轮不做实时刷新，至少在 `theme light` 输出里明确提示「桌面需重启/重新构建后生效」，避免用户看到 shell 变亮、桌面仍暗的割裂画面。
- **为什么：** 这是评审范围第 4 条「主题切换一致性」的直接命中点；半明半暗是同类桌面 OS（Haiku/Serenity）里不会出现的基础缺陷，比配色好不好看更伤信任。
- **红线核对：** 纯绘制层 token 选择，不新增 CE ABI 槽、不动 syscall 表；`cdeconf` 既有接口可复用。

#### P0-2 · 重启后 shell 报告 light，画布却仍是暗底（半明半暗残留）
- **现象：** 第二次引导进入控制台，`theme` 自报 `current theme: light / background #F6F6F4 foreground #24292F`，但整帧画布是暗底 `#0A0E14` 系，文字角色色也落在暗主题上（`16-after-reboot-shell.png`）。
- **证据：** `16-after-reboot-shell.png` 与同目录文本 dump `16-after-reboot-shell` 段；对照 `13-shell-light.png`（light 正确落地时应为浅底）。
- **期望改成什么：** 启动/切后端时，把当前 scheme 的角色色一次性刷到整帧（含画布底色），不要只更新角色表不清旧帧；与 v2.72「`con_set_style_rgb()` 后必须 `con_repaint_frame()`」同类修法（见 `src/shell.c:715-723` 注释）覆盖到 text 后端与从 GUI 退回控制台的路径。
- **为什么：** 同 P0-1，属「半明半暗区块」明确条目；当前画面是"文字说 light、底色是 dark"，比纯暗色更显故障。
- **待功能关复核：** 该现象出现在「test ISO 自启动 GUI → Esc 退控制台 → force_text 切后端」路径，建议功能关确认是否为后端切换未重放 palette；本轮按观感缺陷记录。

### P1（本轮应修：可见的对齐 / 文案 / 可读性问题）

#### P1-1 · 任务栏时钟未右对齐，紧贴 Start 按钮
- **现象：** 任务栏全宽，但「Start」在最左，时钟 `19:26:19` 落在 Start 右侧约 90px 处，任务栏右半条全空（`12-desktop-dark.png`、`14-desktop-light.png`、`15-desktop-light-reboot.png`）。
- **证据：** 源码 `src/gui/chrome.c:766-778`：`clk_s` 虽设 `align_main = ALN_END`，但任务栏行内 Start 与时钟之间没有弹性间隔块，子项按主轴依次左排，END 对齐未把时钟推到右缘。
- **期望：** 时钟块钉到任务栏右缘（右侧留 4–8px 内边距），Start 保持最左；与 KolibriOS 底栏右置托盘、Haiku Deskbar 右侧 tray 的惯例一致。
- **为什么：** 任务栏左右分区是桌面外壳最基础的几何约定；当前观感像两个控件随手摞在一起。

#### P1-2 · 窗口缺基础标题钮，桌面「文件夹」无图标、常驻选中态
- **现象：** Demo 窗口标题栏只有文字「CatOS Sample」，看不到最小化/关闭等窗口控件；正文左上是棋盘格占位块；右上角「Desktop folder」是纯文字标签，套着一块常驻灰底高亮，没有文件夹图标，也看不出可点（`12-desktop-dark.png`、`15-desktop-light-reboot.png`）。
- **证据：** 同上两张；源码 `src/gui/chrome.c` `demo_add_sample()` 与桌面标签绘制段。
- **期望：** 本轮最低限度：① 给标题栏补一个关闭钮（哪怕方块占位），与拖拽区形成可识别的窗口 chrome；② 文件夹标签配一个 16×16 内置图标（`icons.c` 已有图标基础设施可复用），去掉常驻灰底选中框，选中态只在 hover/聚焦时出现。
- **为什么：** 对照 KolibriOS 窗口标题栏三钮齐全、每个桌面图标带像素图标；当前桌面元素可辨识性偏弱，用户无法判断哪些可交互。

#### P1-3 · help 右列描述在 80 列边缘折行/截断
- **现象：** `help` 直通输出中，长描述第二行顶到右缘被切掉，如 `crashlog --full for raw`（`04-help.png`）、`mount <1..4|hd0pN> DIR` 参数串在列宽内拥挤（`18-help-header.png` 同屏尾部）；折行第二行缩进与命令列不齐。
- **证据：** `04-help.png`、`18-help-header.png`、dump `04-help` 段。
- **期望：** 描述列按固定右边界折行（80 列内），超长描述截断加 `…` 或整体缩短措辞；折行续行缩进到描述列起点对齐。
- **为什么：** help 是新用户第一入口；右缘掉字会被读成命令说明残缺。

#### P1-4 · 陈旧版本号：help 标题与 `uname` 输出仍写 v0.3
- **现象：** `about` 的 Version 行正确显示 `CatOS v2.82`（`03-about-banner.png`），但 help 页首标题与 `uname` 命令输出仍是 0.3 旧标；同屏/同系统出现两个版本号。
- **证据：** 源码 `src/shell.c:322`：`pager_line(trhelp("CatOS v0.3 (five-pillar kernel) - commands:"))`；`src/shell.c:1195` `cmd_uname()`：`CatOS i386 0.3 (grub-multiboot, 5-pillar kernel)`（中/英两串均 0.3）。注：help 首页在实机上快速滚出 25 行可视区，本轮未截到首屏图，结论以源码为准。
- **期望：** 版本号改为由单一版本来源带出（与 `about` 的 `CatOS v2.82` 同一处常量），不再硬编码 0.3。
- **为什么：** 同一系统两个版本号是可信度硬伤；改动量极小，属文案收口。

#### P1-5 · `echo -c COLOR` 被参数校验拒绝，但 help 宣传支持
- **现象：** 实机执行 `echo -c green ...` 等四条，均返回 `echo: invalid option -- 'c'` + `Try 'echo --help' for more information.`（`08-colors-sample.png`）；help 行却写 `echo TEXT (-n no newline, -c COLOR)`。
- **证据：** `08-colors-sample.png`、dump `08-colors-sample` 段；源码 `src/shell.c:1680` `cmd_echo()` 自身支持 `-c`，但前置 `cli_validate()`（`src/posix.c:266-290`）对 echo 的首token `-c` 按短选项解析并拒绝，`SPECS` 表（`src/posix.c:117`）未登记 `-c`。
- **期望：** 二选一：① 在 CLI 规格里给 echo 登记 `-c`（及 `-n`）选项透传；② 或从 help 文案撤下 `-c`。建议①，因为内置解析器已实现。
- **为什么：** 文档承诺的着色样例一跑就报错，直接影响终端配色演示与观感自评；**此项为功能/界面交叉，转功能关复核**，本轮不擅自定性为回归。

#### P1-6 · 切 light 后旧文本格前景色未随方案重刷，浅底上残留亮绿
- **现象：** `theme light` 落地后画布已是浅底 `#F6F6F4`，但屏幕上残留的旧行（`current theme`/`background`/`usage` 等）仍是暗主题的亮绿（实机采样约 `#57FF57`）压在浅底上，发飘、角色层级混乱；底部新提示符反而是深绿/深蓝（符合 light 方案）。
- **证据：** `13-shell-light.png`（同屏残留旧行亮绿）；`src/palette.c:207-224` light 方案已定义前景 `#24292F`、prompt 深绿 `#116329`、success `#1A7F37`，问题不在方案取值，而在切方案时存量单元格的前景属性没有跟着重刷（与 v2.72 修过的"画布底色未重刷"同类，见 `src/shell.c:715-723` 注释，该处只补了底色）。
- **期望：** 方案切换后除重刷画布底色外，把存量文本格的角色前景按新方案重印一遍（或直接清屏重绘当前行），不要让暗套前景留在浅底上。
- **为什么：** 同屏出现两套主题的文字色，是"半明半暗"在终端内的表现；浅底亮绿对比不足且角色误读。

#### P1-7 · 字模 `|` 与小写 `l` 视觉混淆
- **现象：** 用法行 `theme dark|light|solarized|mono`、参数 `<1..4|hd0pN>` 中的竖线渲染成与 `l` 几乎相同的细竖笔，肉眼难以区分（`13-shell-light.png`、`04-help.png`、`18-help-header.png`）。
- **证据：** 同上三张；8×16 字模 `src/font_ascii.inc` 中 `|` 槽位无上下衬线/宽度区分。
- **期望：** 给 `|` 字模补横衬线（上下短横）或加宽 1px，与 `l` 区分；至少在 help/usage 串里把分隔符换成不易混的写法（低优先）。
- **为什么：** 分隔符读错会直接导致命令拼错。

#### P1-8 · 中文报错/提示串半翻译，中英杂糅
- **现象：** zh locale 下一批报错串夹着未译英文动词，例：`ls: 无法read 目录`、`edit: 无法create/打开 文件`、`cp: 无法create target 目录`、`useradd: 无法grant capabilities you do not hold`、`rm: 拒绝 to remove /`、`挂载: 失败 to probe a FAT32 volume there`、`pkg：权限不足 writing to /bin` 等（源码核实，未逐条触发截图）。
- **证据：** `src/shell.c` trs 中文分支扫描结果（`无法read`、`无法create`、`无法grant`、`拒绝 to remove`、`失败 to probe`、`writing to` 等）；另见 dump 中 `catos: 未知 命令:` 这类语序欧化。
- **期望：** 按命令分组把中文分支补译完整，命令名/路径/能力位保留英文，其余动词名词中文化；统一「命令: 中文说明」语序。
- **为什么：** 半翻译串比全英文更显半成品；属文案批量收口，不动逻辑。

#### P1-9 · gfx 演示帧样式样例行叠压、单词中途折行
- **现象：** `gfx` 进入 40×12 样式文本帧，`underline/italic/bold` 挤在同一行；`inverse` 块与 `strike` 行上下叠压；底部提示 `'gfx rgb/palette/display'` 在 `di/splay` 处单词中间折行（`11-gfx-console.png`）。
- **证据：** `11-gfx-console.png`；源码 `src/shell.c:855-880` `cmd_gfx()` GFX 分支逐行 `vga_write`，行距按单行高排版。
- **期望：** 每个样式样例独占一行或放宽行高；长提示按词折行，不拆单词；该帧是内置展示页，观感代表系统文字排版水平。
- **为什么：** 对照 SerenityOS/Haiku 终端样例页，样式对比块都是分行留距的。

## 2. 可接受 / 可选优化（P2/P3，不阻塞本轮）

### P2（建议排期）
- **P2-1 · `ls` 单列浪费横向空间。** 80 列下列表一项一行（`05-ls-root.png`、`06-ls-bin.png`）；可按名称长度分 2–3 列，目录/`.ce`/`.cfg` 着色规则沿用现状。参照 FreeDOS `DIR` 多列、KolibriOS 文件管理器网格。
- **P2-2 · `about` ASCII 艺术首行被屏幕上边缘裁掉。** `03-about-banner.png` 顶部点阵第一行贴边；about 输出前留一行上边距，或整体下移一行。
- **P2-3 · 开机诊断噪音残留在 prompt 上方。** `02-console-gfx24.png` 顶部留有 `net: no usable NIC...`、PCI 枚举等长行；落 shell 前清屏或把诊断归到滚动区首屏之外。
- **P2-4 · 桌面空态文案未上屏。** 源码有 `Desktop folder is empty` 空态串（`src/gui/chrome.c:695`），当前桌面只显示「Desktop folder」标签；空目录时应把空态提示画到桌面区。
- **P2-5 · light 桌面标题/标签对比与选中框。** `15-desktop-light-reboot.png` 标题栏浅灰底上标题文字层级偏弱；文件夹标签常驻灰底（同 P1-2）。
- **P2-6 · solarized/mono 无对应 GUI token。** 源码注释明确只有 light 映射 `TOK_LIGHT`，其余回落 dark（`chrome.c:733-740`）；shell 切 solarized/mono 时桌面仍暗，属已知功能缺口，建议在 `theme` 输出里注明「桌面仅支持 dark/light」。

### P3（记录在案，远期打磨）
- **P3-1 · 圆角 / 阴影 / 动效全为 0。** `tokens.c` 中 `radius=0, elevation=0, anim_ms=0`，属 v1 有意取舍（注释「v1 无 radius/elevation/动画」）；本轮不要求做，待桌面组件稳定后再统一开 token。
- **P3-2 · 图标体系仍是占位。** 棋盘格块、文字标签为主；待 `icons.c` 扩充 16×16 像素图标集后统一替换。
- **P3-3 · 控制台缩进风格。** v2.73 起命令输出统一两格缩进（`shell.c:7444` 注释），与传统 Unix 顶格输出不同；当前内部自洽，记录为风格选择，不强制改。
- **P3-4 · 分辨率/后端混用。** 实机截到 800×600（vbe24/gui）与 640×400（80×25 text / 40×12 gfx）两种画幅；属后端能力差异，建议在 `gfx mode` 查询输出里标明画幅，减少评审与自测混淆。

## 3. 明确认可的部分（下一轮不要重复挑）

1. **主题可跨重启持久化，冷启动生效正确。** 切 light 后断电再引导，桌面出 light 方案（`15-desktop-light-reboot.png`），shell 报告 `light #F6F6F4`（`16-after-reboot-shell.png`）；与 v2.82 P1-4（cdeconf）探针 7/7 结论一致。问题只在「实时重进 GUI」与「退控制台后端重刷」两条路径（P0-1/P0-2），持久化链路本身是通的。

## 4. 同类项目对照小结

对照项目均为真实存在的开源/免费 OS；公开可核对链接见附录 B。截图为本轮实机 CatOS 帧，对照项引用各项目官网/文档公开截图与页面。

### 4.1 FreeDOS（命令行 + 对话框外壳参照）
- **对照画面：** FreeDOS 默认 COMMAND.COM 提示符白字黑底，FDIMPLES 安装器为蓝底白字双列列表框 + 底部 `OK/Cancel`，菜单条 `File Edit Search...` 顶置（官网 press kit 截图）。
- **CatOS 对比：**
  - 持平：CatOS 深色 shell 的角色色分工比 FreeDOS 单色白字更细；提示符路径表达同样直白。
  - 差距：FreeDOS 对话框左列命令/包名、右列说明，两列边界整齐，无右缘掉字；CatOS help 描述列折行截断（P1-3）。FreeDOS 空卷/驱动提示单行结束、不留长诊断噪音；CatOS 开机诊断残留 prompt 上方（P2-3）。
- **可借鉴：** help/列表类界面的固定双列边界与短描述写法。

### 4.2 KolibriOS（小型 OS 桌面外壳参照，体量最接近）
- **对照画面：** 桌面左右两列像素图标各带 16×16 彩色图标 + 文字标签；窗口标题栏深色、带最小化/关闭钮；底栏左侧常驻启动项、右侧托盘/时钟分区明确（官网下载页桌面截图）。
- **CatOS 对比：**
  - 差距 1：KolibriOS 每个桌面项有可辨识图标；CatOS 文件夹仅文字 + 常驻灰底、窗口正文是棋盘格占位（P1-2）。
  - 差距 2：KolibriOS 底栏左右分区清晰；CatOS 时钟贴 Start、右半条空（P1-1）。
  - 差距 3：KolibriOS 窗口边框/标题栏高度全站一致；CatOS 窗口目前只有单 Demo 窗，尚无多窗可比，但标题栏无控件（P1-2）。
- **可借鉴：** 底栏左右分区、桌面图标「图标 + 标签」纵向排布、标题栏三钮布局。

### 4.3 SerenityOS（现代 hobby OS 桌面 + 终端审美参照）
- **对照画面：** 90 年代扁平风桌面，标题栏高度统一、菜单条贴窗顶；Terminal 为独立窗口，配色方案可在设置里切换，文字/光标/ANSI 色分区配置（官网 + Terminal man 页）。
- **CatOS 对比：**
  - 差距 1：SerenityOS 的终端配色与桌面主题是同一套设计语言切换；CatOS shell 与 GUI 两套色板、强调色一紫一蓝（P0-1）。
  - 差距 2：SerenityOS 终端样式样例分行留距；CatOS gfx 演示帧行叠压、词中折行（P1-9）。
  - 持平：两者都是 8px/位图字体路线，CatOS 深色底可读性不差。
- **可借鉴：** 主题单一数据源（终端与桌面共用 scheme）、样式对比块的行距与折行规则。

### 4.4 Haiku（补充参照：成熟外壳的任务栏/窗口度量）
- **对照画面：** Tracker 多窗并存，标题栏带缩放/关闭，Deskbar 左侧应用菜单、右侧托盘时钟；窗口边距与控件高度全站统一（官网桌面截图）。
- **CatOS 对比：** Haiku 即便浅色主题，窗口面板与画布的边框、文字对比都成体系；CatOS light 桌面边框 `#8A8F9E` 与面板 `#DDDDE6` 反差偏低（P2-5），切主题后旧行前景未重刷（P1-6）。
- **可借鉴：** 同主题下面板/边框/文字三级灰度阶梯；任务栏托盘右置。

### 对照结论
CatOS 在「终端壳」这一层与 FreeDOS 同代偏上；在「桌面外壳」这一层距 KolibriOS（小型 OS 完成度）和 SerenityOS/Haiku（主题体系与控件度量）尚有两代差距：先补主题同源与基础对齐（P0/P1），再补图标与控件体系（P1-2/P3-2）。
