CatOS System API v2.2
=====================

CE programs are freestanding i386 binaries loaded by the `run` command.
Before the entry point is called the kernel writes the address of the
system-call table into the __ce_api slot of your image.  Every app must
declare:

    catos_api_t *__ce_api __attribute__((section(".ce_api"))) = 0;

and then call the functions through __ce_api (or the CE_API() helper in
extapp/ce_abi.h).  The entry point receives the command line:

    int ce_main(int argc, char **argv)

`run /bin/app.ce a b c` gives argc=4, argv[0]="/bin/app.ce",
argv[1]="a", argv[2]="b", argv[3]="c".  A legacy ce_main(void) also
works (the arguments are ignored).  The full table (33 calls):

--- console ---------------------------------------------------------
void write(const char *s);     print a NUL-terminated string
void putc(char c);             print one character
void cls(void);                clear the screen

--- input -----------------------------------------------------------
int readline(char *buf, int max);
                               read one line (Enter), returns length;
                               0 if nothing was typed

--- time ------------------------------------------------------------
void time_str(char *out);      fills "YYYY-MM-DD HH:MM:SS" (24 bytes)

--- filesystem ------------------------------------------------------
int fs_ready(void);            1 when the FAT32 volume is mounted
int ls(const char *path, cb, ud);
                               list a directory; cb(int is_dir,
                               const char *name, uint32_t size, void *ud)
                               is called for every entry; returns 0
int touch(const char *path);   create an empty file if absent; 0 = ok
int mkdir(const char *path);   create a directory; 0 = ok
int cat(const char *path, char *buf, int max);
                               read a file into buf, returns bytes read
int save(const char *path, const char *data, uint32_t size);
                               write a file (max 512 bytes); 0 = ok

--- memory ----------------------------------------------------------
void *alloc(uint32_t size);    8-byte aligned block, 0 when out of memory
void free(void *p);            free a block returned by alloc

--- misc ------------------------------------------------------------
void exit(int code);           return to the shell immediately

--- networking (AMD PCnet-PCI, QEMU user-net) ----------------------
int net_init(void);            init the NIC (idempotent, called at boot)
int net_up(void);              1 when the NIC is running
int http_get(const char *url, char *buf, int max);
                               one-shot HTTP GET.  Returns bytes copied
                               into buf (>=0) or an error code:
                                 -1 NIC down    -2 hostname unsupported
                                 -3 connect     -4 HTTP status not 2xx
                                 -5 response    -6 send failed
                               URL form: http://host[:port]/path  where
                               host may be an IP or a DNS name.
int net_dns(const char *host, char *ip_out);
                               resolve a host name to a dotted IPv4
                               string (via the QEMU user-net DNS,
                               10.0.2.3).  Returns 0 = ok, -1 = failed.
                               IP literals ("10.0.2.2") pass through.
int net_udp_send(const char *ip, int port, const char *data, int len);
                               send one UDP datagram to ip:port.
                               Returns 0 = ok, -1 = failed.
int net_udp_recv(char *src_ip, int *src_port, char *buf, int max);
                               wait (bounded) for one UDP datagram;
                               copies payload into buf, fills src_ip /
                               *src_port.  Returns bytes received,
                               -1 = timed out / no datagram.
int net_ping(const char *ip);  send one ICMP echo and wait for the
                               reply.  Returns 0 = reply, -1 = no reply.
int net_ip(char *out);         copies this machine's IPv4 address as a
                               dotted string into out (e.g. 10.0.2.15).

  Example (see extapp/netinfo.c for a complete program):

      api->net_init();
      if (!api->net_up()) { ...network adapter not ready... }
      char ip[24];
      api->net_ip(ip);                     /* "10.0.2.15" */
      api->write(ip);
      if (api->net_dns("example.com", ip) == 0) api->write(ip);
      if (api->net_ping("10.0.2.2") == 0)  api->write("alive\n");
      char buf[1024];
      int n = api->http_get("http://10.0.2.2:8080/API.txt", buf, sizeof(buf));
      if (n >= 0) { api->write(buf); }     /* n = number of bytes received */

  (QEMU user-net: guest 10.0.2.15, host loopback 10.0.2.2, DNS 10.0.2.3.
   To fetch from the host run `python -m http.server 8080` there and use
   http://10.0.2.2:8080/...  External HTTP may be blocked by the host
   network; DNS and ping are the reliable path for beginners.)

--- beginner-friendly helpers (v2.0+, all NULL-safe / bounds-checked) -
void print_int(int v);         print a decimal integer (handles negatives)
void print_hex(uint32_t v);    print "0x" + 8 lowercase hex digits
void set_fg(int color);        set foreground color 0..15
void delay(uint32_t ms);       busy-wait (CPU loop; good for animations)
int  atoi(const char *s);      decimal string -> int (0 if bad input)
int  strlen(const char *s);    string length
int  strcmp(const char *a, const char *b);
                               -1 / 0 / +1 style comparison
void strcpy(char *d, const char *s);
                               copy string into d
int  getch(void);              blocking single key (ASCII or KB_* code)
int  file_exists(const char *path);
                               1 = exists (file or directory)
int  fsize(const char *path);  file size in bytes, -1 if absent

Error codes (filesystem calls):
    0  ok
   -1  path / file not found
   -2  expected a directory
   -3  bad name
   -4  disk / entry pool full
   -5  already exists

Limits:
   image size   <= 64 KiB
   file writes  <= 512 bytes (via save(); built-in apps are installed
                  directly by the kernel so they can be larger)
   heap         64 KiB static pool
   stack        8 KiB kernel-owned

Built-in apps:
   After `format` (and at every boot as a fallback) the kernel installs
   the CE apps embedded in the ISO image onto the FAT32 volume:
     /bin/hello.ce   first program: strings, time, alloc/free
     /bin/calc.ce    calculator: run /bin/calc.ce, or one-shot with
                     arguments: run /bin/calc.ce 10 + 5  (print 15)
     /bin/sysinfo.ce system information + directory browser
     /bin/demo.ce    API demo: print_int/hex, strings, atoi, colors,
                     getch, delay
     /bin/curl.ce    tiny HTTP client; URL as argument:
                     run /bin/curl.ce http://10.0.2.2:8080/API.txt
                     (with no argument it asks for an URL)
     /bin/netinfo.ce one-shot network report: own IP, DNS lookup,
                     ping, UDP echo (see the networking section above)
   Source code for all of them lives in extapp/ (host side).

Program lookup (shell):
   Every command is resolved in this order:
     1. shell builtin (dir, cd, mkdir, touch, edit, format, run, curl,
        ping, dns, udp, netdiag, help, clear, echo, about, uname, date,
        mem, reboot, hang, color)
     2. a .ce program in the current directory
     3. a .ce program in /bin (the PATH directory)
     4. otherwise: "catos: unknown command: <cmd>"
   So from anywhere you can just type `calc`, `hello` or `netinfo`.

Examples:
   sh build_ce.sh calc.c      (see extapp/build_ce.sh)
   run /bin/calc.ce           (from the CatOS shell)
   run /bin/calc.ce 7 * 6     (print 42)
   run /bin/curl.ce http://10.0.2.2:8080/API.txt


=====================================================================
 CatOS API v2.3 - the five-pillar kernel (ring3 + tasks + permissions)
=====================================================================

Starting with kernel v0.3, CE programs no longer run inside the kernel:
each .ce file is spawned as a RING3 TASK with its own page directory and
reaches the kernel only through the int 0x80 system-call gate.  Old
binaries keep working unchanged - the kernel builds a per-task "vsyscall"
page whose API table has exactly the shape of catos_api_t, so your
api->fn(...) calls are transparently turned into system calls.

New behavior to be aware of:
   * your task has an identity: uid (0=root, 100=user) and a tid.
     Use `sudo prog` from the shell to run as root.
   * writing outside your own memory raises a page fault and KILLS YOUR
     TASK (the system survives).  Touching kernel addresses (e.g.
     0x1000000) or address 0 is fatal - see /bin/crash.ce.
   * delay(ms) is a real sleep now: your task sleeps and other tasks run.
   * readline/getch need the console: while another task owns console
     input, your call blocks until it is your turn.
   * file writes are permission-checked: system areas (/bin, /etc,
     /appdevelop ...) are root-owned; writing them as uid 100 returns
     -13 (EACCES).  /home and /tmp are world-writable.

v2.3 API additions (appended to catos_api_t - old offsets unchanged):

   int  getuid(void)          your user id (0 root, 100 user)
   int  gettid(void)          your task id (as shown by `ps`)
   int  kill(int tid)         terminate a task (only your own uid or root)
   void yield(void)           give up the CPU to other tasks

New shell commands:
   ps               list tasks (tid, uid, ring, state, name)
   kill TID         terminate a task
   sudo CMD         run a program as root
   uptime           seconds since boot + task count
   CMD ... &        run a .ce program in the background

New built-in apps (source in extapp/):
   /bin/spinner.ce  multitasking demo (sleeps + prints; try `spinner 10 &`)
   /bin/crash.ce    isolation demo (deliberate kernel-memory write)
   /bin/perms.ce    permission demo (try it, then `sudo perms`)


=====================================================================
 CatOS API v2.4 - hardware properties (hw_num / hw_str syscalls)
=====================================================================

Modeled after Android's HardwarePropertiesManager: ring3 programs can
query the machine through two new API calls (int 0x80 numbers 37/38):

   int hw_num(int what);                    /* numeric property */
   int hw_str(int what, char *buf, int max); /* string property, returns length */

hw_num selectors:
    1  HW_CPU_MHZ      calibrated TSC frequency (TSC vs PIT, at boot)
    2  HW_CPU_CORES    CPUs managed by this kernel (1: BSP only)
    3  HW_CPU_FAMILY   CPUID signature: family
    4  HW_CPU_MODEL    CPUID signature: model
    5  HW_CPU_STEPPING CPUID signature: stepping
    6  HW_MEM_TOTAL_KB low-64MiB memory reported by the bootloader
    7  HW_MEM_FREE_KB  free 4 KiB frames from the page allocator
    8  HW_MEM_USED_KB  allocated frames
    9  HW_MEM_KERNEL_KB kernel image size (text+data+bss)
   10  HW_DISK_MB      first IDE disk capacity (MB)
   11  HW_DISK_LBA48   1 = the drive supports 48-bit LBA
   12  HW_NIC_UP       1 = PCnet initialized
   13  HW_UPTIME_MS    ms since boot
   14  HW_TASKS        tasks alive right now
   15  HW_TICKS        timer ticks since boot

hw_str selectors:
    1  HW_CPU_VENDOR_S   CPUID vendor ("GenuineIntel" / ...)
    2  HW_CPU_BRAND_S    full brand string ("QEMU Virtual CPU ...")
    3  HW_CPU_FEATURES_S notable CPUID feature flags
    4  HW_DISK_MODEL_S   ATA IDENTIFY model   ("QEMU HARDDISK")
    5  HW_DISK_SERIAL_S  ATA IDENTIFY serial  ("QM00001")
    6  HW_DISK_FW_S      ATA IDENTIFY firmware ("2.5+")
    7  HW_NIC_MODEL_S    NIC model / "none"
    8  HW_NIC_MAC_S      NIC MAC address
    9  HW_NIC_IP_S       our IPv4 address
   10  HW_PCI_LIST_S    lspci-style inventory (multi-line)

Shell side: `hwinfo` prints the whole dump, `top` is a live task
monitor with per-task CPU% (the kernel charges every timer tick to the
task on the CPU) and per-task memory (page-table walk).

New built-in app: /bin/hw.ce (source extapp/hw.c) - the listing above
is exactly what it prints from ring3.


=====================================================================
 CatOS API v2.7 - display front-end (mode / info / text style)
=====================================================================

Rendering is now split into a mode-independent FRONT-END (render.c) and
pluggable BACK-ENDS (VGA text 80x25 / Mode 13h 40x25).  Ring3 sees only
styled text.  There is NO drawing API: no putpixel, no fillrect, no
framebuffer pointer.  0xA0000 is supervisor-only in every user page
directory, so a program cannot draw even by writing memory directly.

Three new slots (49..51, append-only, old binaries keep working):

   int display_mode(int mode)
       -1  query: return current mode (0 = text, 1 = graphics)
        0  request TEXT mode
        1  request GRAPHICS mode
       TEXT -> GFX is open to every ring3 program.
       GFX  -> TEXT ALWAYS asks the human at the console for a physical
       'Y' keypress.  There is no parameter, token or syscall that can
       supply consent; a program can only REQUEST, never force.
       Returns the resulting mode (>=0), or -13 (EACCES) on denial,
       -3 (EINVAL) for an unknown mode.

   int display_info(int what)
        0  mode            4  supported style bitmask
        1  columns         5  physical pixel width
        2  rows            6  physical pixel height
        3  colours (16/256)
       Unknown selector -> -8 (ENOSYS).

   void set_style(int fg, int bg, int attrs)
       fg / bg are palette indices 0..255.  In text mode values >= 16
       are mapped onto the nearest of black/dark-grey/light-grey/white.
       attrs is a bitmask:
          0x01 BOLD       0x02 DIM        0x04 ITALIC
          0x08 UNDERLINE  0x10 BLINK*     0x20 INVERSE
          0x40 STRIKE     0x80 HIDDEN
       Text mode supports BOLD/DIM/BLINK/INVERSE/HIDDEN; the software
       graphics back-end supports the rest.  BLINK is accepted but not
       animated yet (needs a timer-driven repaint).
       The existing set_fg(int) call now accepts 0..255 (was 0..15).

   Graphics mode is a TEXT mode with more colours and styles, not a
   drawing surface.  The 40x25 cell grid is a logical terminal; on a
   mode switch the front-end re-wraps the screen contents, so text is
   not lost.  No hardware cursor exists in graphics mode.

Shell side:
   gfx          switch to graphics mode (styled-text welcome)
   text         switch back - physical Y confirmation required
   style SPEC   bold+underline+inverse ... / off / decimal mask
   display      backend, grid, colours, style bits, policy
   color 0..255 set foreground palette index
   vdiag        raw VGA register / glyph diagnostic

New built-in app: /bin/gfxdemo.ce (source extapp/gfxdemo.c) - switches
to graphics mode from ring3, paints only styled text, then requests a
return to text mode so the consent gate can be exercised.
