## 三、实现要点

### 3.1 内存探测链路排查（除两处截断外无其它截断点）

链路：GRUB multiboot `mbi.mem_lower/mem_upper` → `kernel.c` 透传 →
`hw_mem_boot()` 存 `hw.c`；`paging_init(lo, hi)` 建 PMM。显示侧：
`hwinfo`/`top` 走 `hw_num(HW_MEM_*)`；`mem` 命令直读 `mbi`。

原截断点：
1. `hw.c` `HW_MEM_TOTAL_KB`：`hi` 钳到 `63u<<10`（63MiB）——已去除，
   改为 `1024 + mem_upper_kb + mem_lower/1024`，封顶 `4096*1024` KB。
2. `paging.c` `paging_init`：`top` 钳到 `MEM_TOP=0x4000000`（64MiB）——
   已去除，`top` 跟随 `mem_upper`。

`kernel.c` 在 multiboot 信息缺失时的回退值 `63u<<10` 保留（仅无内存映射
兜底，不是对真实报告的截断）。ring3 ABI 不暴露内存大小，无需改。

### 3.2 分页与分配器（paging.c）

- 沿用既有“内核虚拟 = 物理”恒等映射假设（未做内存动态化重构，符合
  ROADMAP 诚实清单暂缓项）：用 4MiB PSE 监督页恒等映射 `[0, top)`；
  尾部不足一个 4MiB 的块整块映射（沿用旧 16-PSE 行为），分配器只发
  `< mem_top` 的帧，尾块内不存在的 RAM/hole 不会被触达。
- KB→字节用 `uint64_t` 中间量：`0x100000 + (uint64_t)mem_upper_kb*1024`，
  避免近 4GiB 时 `<<10` 在 32 位回绕；超 4GiB 封顶 `0xFFFFF000`（4GiB
  本身不可由 32 位字节地址表示）。
- 位图按全 4GiB 预留：`1MiB 帧 / 32 = 32768` 字（128KiB BSS）；
  `mark_frame` 加帧序号上界检查；`frame_free` 边界改为 `pa >= mem_top`。
- `task_space_create` 由“只拷前 16 个 PDE”改为镜像全部 1024 个内核 PDE；
  高 LFB PT PDE 随 kdir 一起镜像且保持监督态（无 US 位），用户 PDE 8/9
  仍替换为任务私有页表。
- DMA 预留区（PCnet 0x500000..0x510000、SB16 0x510000..0x528000）
  隔离逻辑保持不变。

### 3.3 遗留项处置

- **#123（ata_read_sectors DRQ 失败静默继续）**：确认是真实缺陷。读路径
  原空分支吞掉 `ata_wait_drq()` 错误继续时钟数据口，会把陈旧/垃圾扇区当
  成功交给调用方；改为 `return -1`，与 `ata_write_sectors` 对称。
  已核对全部调用方（fat.c 三处）均检查 `!= 0` 并上抛，改动安全。
- **#122（非 root 可改全局 env / 字号默认值）**：env 表为全局唯一、落盘
  `/etc/env`；`/etc/size` 为全局持久字号。按问题清单建议在落盘路径加
  admin 闸门：
  - `export KEY=...` / `unset KEY`：非 root 直接 `permission denied`
    （无参 `export` 列环境变量为只读，仍放行）。
  - `size`：当前会话仍可临时切字号；仅写 `/etc/size` 要求管理员，非 root
    不持久化。
  - 说明：本内核尚无会话级 env 存储，故未做“会话内可改、仅不落盘”的
    折中；这一产品语义可在后续引入 per-session env 时再调整。

## 六、遗留问题与已知限制

1. **本机无法实跑 `-m 4096`**：云端主机 cgroup `memory.max=4GiB`、总内存
   3.9GiB，QEMU 启动 4096MB 客户机即 `Cannot allocate memory`；实测可行
   上限约 3840MiB。代码已按 4GiB 边界做封顶与 64 位换算，但 4GiB 整档
   实机未在本机验证。
2. **PCI hole 之上的第二段 RAM 未枚举**：multiboot `mem_upper` 只统计
   1MiB 以上连续低内存；hole 之上的 RAM 仅出现在 mmap 表，本内核未解析。
   因此大内存客户机显示总量小于 `-m` 标称值（3840MiB 标称 → 报告 ~3071MiB），
   这是如实反映，不是内存泄漏。
3. **真 4GiB 客户机的 MMIO 避让**：当前恒等映射未按 multiboot mmap 避让
   PCI BAR/MMIO 区间；若 BAR 落入最后 4GiB 块，PSE 恒等页会覆盖 MMIO。
   本机测试矩阵 RAM 顶 < BAR0(0xfd000000)，无冲突；彻底解决需后续每帧
   内核窗口方案（ROADMAP 内存动态化 deferred 项）。
4. **size_regress 绿带常量陈旧 / 未挂盘**：见 4.3，建议主代理后续更新
   检测色值或给该脚本挂磁盘镜像。
5. **#122 产品语义**：当前对非 root 直接拒绝 export/unset；若后续引入
   per-session env，可改为“会话内可改、全局落盘才需 admin”。

## 2. 实现设计

### 2.1 块设备层（`ata.c` / `ata.h`）
- 启动时探测 4 个 IDE 槽位（主/从总线 × 主/从设备），每槽记录 `base/ctrl/dev/sectors/present`。
- 新增按盘读写：`ata_read(drive,...)` / `ata_write(drive,...)` / `ata_drive_sectors(d)` / `ata_drive_count()`。
- 保留旧单盘包装 `ata_read_sectors` / `ata_write_sectors` / `ata_identify`（走 drive 0），`hw.c` 等旧调用点无需改动。

### 2.2 分区表（新增 `part.c` / `part.h`）
- `part_scan()`：遍历已识别硬盘，校验 `55AA`，解析 4 个主表项（类型、活动位、起始 LBA、扇区数）。
- FAT32：`0x0B/0x0C`；扩展：`0x05/0x0F/0x85/0xEE/0xC5` 标记不支持。
- `part_lookup(spec)`：接受裸分区号（drive0，1 基）或 `hd<d>p<e>`；`part_devname()` 生成 `hd0p2` 这类设备名。

### 2.3 FAT 多卷上下文（`fat.c` / `fat.h`）
- 几何参数从单一全局变量改为按卷槽位保存：`g_vol[FAT_VOL_MAX=4]`（drive、分区起点、FAT 大小、数据区起点、根簇、分配提示、簇数、FAT 容量、总扇区、每簇扇区）。
- FAT 缓存与写日志仍为共享静态区，归“当前活跃卷”所有；`fat_activate(slot)` 切卷并从磁盘重载该卷 FAT #1、复位日志。这样避免每卷再占一份 4 MiB 缓存撑大 BSS。
- 抽出 `probe_volume(slot, drive, part_lba)`；新增 `fat_mount_partition(...)`（找空闲槽位探测）、`fat_activate()`、`fat_active_slot()`、`fat_release_slot(slot)`（卸载后归还槽位以便重挂）。
- 所有簇读写/镜像校验/FSInfo 都改走活跃卷所在盘（`cur_drive`），不再写死 drive 0。

### 2.4 VFS 挂载表（`fs.c` / `fs.h`）
- `g_mnt[3]`：挂载点绝对路径、卷槽位、盘符、设备名；根卷为隐式槽位 0（盘符 `A:`）。
- `mount_for(path)`：最长前缀匹配，判定路径归属哪个挂载点。
- `resolve_path()`：命中挂载点先 `fat_activate()` 切到对应卷，再在该卷内解析剩余相对路径；未命中走根卷。fs 层其余打开/读/写/列目录接口都经 `resolve_path`，天然跨卷。
- 挂载校验：目标存在、是目录、非已有挂载点、目录为空；卷探测失败返回细分错误码。
- 卸载保护：当前工作目录位于挂载点内则拒绝（busy）；卸载归还卷槽位。
- 展示：`list_cb` 对目录项按 `父路径/名字` 反查挂载表，命中则追加 `(X:)`，普通目录仍带 `/`；长格式同理。
- `fs_df()`：逐挂载点激活卷，输出 total/used/free/use%/挂载点。

### 2.5 shell 命令表（`shell.c`）—— **合并冲突预警**
- 新增 `cmd_mount` / `cmd_umount`；`cmd_df` 改为直接调用 `fs_df()`。
- 调度分支：`mount` / `umount` 接入命令分发；补全表 `sh_cmds` 增加 `mount`、`umount`；`help` 文件系统段补 4 行帮助。
- **冲突预警点**：命令分发 else-if 链、`sh_cmds` 补全数组、`cmd_help` 帮助表这三处其他分片很可能也在改，合并时需手动对齐。

## 6. 遗留问题 / 未覆盖项

1. **扩展分区（EBR 链）不遍历**：类型 `0x05/0x0F/0x85/0xEE` 仅标记不支持并由 `mount` 报错；没有解析 EBR 链式主分区。
2. **多物理盘仅代码路径验证**：ATA 扫描与分区扫描支持多盘，但金属测试只跑了“单盘双分区”；第二块 IDE 盘的挂载未在真机上验证。
3. **挂载表不持久**：`mount` 状态在内存，重启后需重新挂载；没有写回磁盘的挂载配置。
4. **卷上限**：含根卷共 `FAT_VOL_MAX=4`，即最多 3 个额外挂载卷；切卷时共享缓存从磁盘重载 FAT，卷很多时会有重复读 FAT 开销。
5. **根卷设备名硬编码**：挂载表/df 根卷固定显示 `hd0`；若根卷实际来自其他槽位，标签未动态化。
6. **挂载点权限模型**：复用既有 `fs_perm_check` 路径，没有为挂载目标单独建立属主/权限策略。
7. **不支持嵌套挂载**：往已有挂载点内再挂载会被拒绝（`mount_for` 命中即报错）；这是有意的简化，非 Linux 完整语义。
8. `qemu_regress` 的 `boot-shell` 亮度 WARN 为基线既有现象，本次未处理。

## 2. 彩蛋实现明细（均为 shell 内建）

### 2.1 `cowsay [-f tux] MSG` —— 文本 cowsay

- 实现：`cmd_cowsay()`，内建。
- 角色：默认奶牛（`COW_ART`）；`-f tux` 切换企鹅 Tux（`TUX_ART`），共两种角色。
- 气泡：按消息长度画上下横线 + 左右尖括号；消息为空时奶牛说 `Moo!`、Tux 说 `Hello, I am Tux!`；消息截断到 42 字符。
- 用法实测：
  - `cowsay Hello CatOS` → 奶牛气泡 `Hello CatOS`（截图 `p3_01_cowsay.png`）
  - `cowsay -f tux Hello Tux` → 企鹅气泡 `Hello Tux`（截图 `p3_02_tux.png`）
  - `cowsay`（无参数）→ 默认 `Moo!`（截图 `p3_16_cowsay_default.png`）

### 2.2 `sl` —— 字符画小火车动画

- 实现：`cmd_sl()`，内建。
- 16 帧动画：机车从右侧（列 64）逐帧左移，每帧 `task_sleep_ticks(6)`（tick=10ms，约 60ms/帧）。
- 细节：烟囱上方三态循环烟雾 `SL_SMOKE`；前 5 帧打印 `* CHOO CHOO! *` 鸣笛；机车含烟囱、双车窗、侧梁、两轮。
- 截图：`p3_03_sl.png`、`p3_15_sl_v2.png`（动画中途帧）。

### 2.3 `fortune` —— 随机格言库

- 实现：`cmd_fortune()`，内建。
- 内置 **32 条**格言：20 条英文 + 12 条中文（UTF-8），中英混排。
- 随机熵：RTC 秒/分 + `timer_ticks`（10ms 刻度）+ 单调序列计数器（乘 2654435761 散列），避免同一秒内连续调用重复。
- 截图：英文 `p3_04_fortune.png`、`p3_14_fortune_0/1/2/4/5.png`；中文 `p3_14_fortune_3.png`（只要功夫深，铁杵磨成针）、`p3_14_fortune_2.png`（不积跬步…）、`p3_14_fortune_5.png`（业精于勤…）。

### 2.4 `cal [YEAR]` —— 月历 / 全年历

- 实现：`cmd_cal()` + `cal_build_month() / cal_print_one() / cal_print_year()`，内建。
- 无参数：按 RTC 显示当月（实测 Nov 2026，1 号周日，30 天，正确）。
- 带年份参数（1970..2099）：全年 4 组 × 每月 3 列并排布局。
- 算法：
  - 星期：Sakamoto 公式；
  - 闰年：`(y%4==0 && y%100!=0) || y%400==0`；
  - 宿主侧用 Python `datetime` 对 2020–2026 各月 1 号逐日比对，星期全部一致；闰年判定 2024/2000 为闰、2026/1900 非闰，Feb 2024=29 天、Feb 2026=28 天，全部正确。
- 截图：当月 `p3_05_cal.png`；全年 `cal 2026` → `p3_06_cal2026.png`（Oct/Nov/Dec 三列对齐，Oct 1 周四、Nov 1 周日、Dec 1 周二，正确）。

### 2.5 `yes [TEXT]` —— 连发输出（可 Ctrl+C 中断）

- 实现：`cmd_yes()`，内建。
- 默认重复 `y`；可传自定义文本。
- 中断：每行后 `kb_getkey_timed(1)` 轮询键盘，收到 `0x03`（Ctrl+C）即打印 `^C` 退出；另设 600 行安全上限兜底。
- 截图：`p3_07_yes.png`（满屏 `y`，末行 `^C`，确认 Ctrl+C 可中断）。

## 3. 设计要点

### 3.1 本地包仓库（客户机侧）

- 仓库目录：`/pkg/`；索引：`/pkg/PKGS.TXT`，行式 `name|version|desc|file`。
- 包容器 `.catpkg`（定长 140 字节头 + 原始 CE01 负载）：

  | 偏移 | 长度 | 字段 |
  |------|------|------|
  | 0 | 8 | magic `CPKG01\0\0` |
  | 8 | 16 | name |
  | 24 | 16 | version |
  | 40 | 16 | cmd（安装后命令名 → `/bin/<cmd>.ce`） |
  | 56 | 80 | desc |
  | 136 | 4 | payload_len（uint32 LE） |
  | 140 | … | payload（原始 `.ce`） |

- `pkg install`：校验 magic → 长度一致性 → 负载写入 `/bin/<cmd>.ce`（截断替换，ACL 0755）。
- `pkg remove`：删除 `/bin/<cmd>.ce`，保留 `/pkg/` 仓库副本。

### 2.3 瓶颈定位

1. **GRUB 菜单倒计时 ≈5s（pre-kernel 主项）**

2. **ATA 空槽自旋 ≈1.65s（kernel 主项）**
   `ata.c` 探测路径两轮等待各跑满 10,000,000 迭代兜底。槽1 / 槽3 无设备时状态端口恒定 `0x00`（无 BSY 0x80 / ERR 0x01 / DRQ 0x08），每槽空转 820–830ms；槽2 靠 ERR 位立即跳出。两轮各空转满迭代（诊断计数 `wait_it=10000000`）。

3. **其余固定小项（非瓶颈，未改）**
   - CPU 校准固定 100ms 窗口（K4）。
   - 内建命令 resolve 30ms、pkg 仓库 seed 30ms。
   - FS / 用户 / 语言 / CE 初始化各 ≤10ms，均为单小文件读，无重复扫描。
   - pkg 逐包 stat（PKGS.TXT）发生在 `pkg list` 命令惰性路径，**不在启动路径**；启动时 pkg 仅做仓库 seed resolve。

## 五、VMware 与 QEMU 差异分析（本节未在本环境实测）

> **如实注明**：本环境无 VMware hypervisor，以下结论基于源码启动路径审计，未在 VMware 真机上复跑；VMware 侧实际耗时需按第七节指引复测回传。用户反馈的"开机慢"发生在 VMware 真机。

### 5.1 逐路径审计

| 启动路径 | QEMU 行为（`-net none` / 无附加设备） | VMware 潜在差异 | 本轮处置 |
|---|---|---|---|

| USB UHCI | probe 扫 PCI；`usb_reset_port` 100ms+50ms 延时仅在有设备连接（PSC_CONNECT）时发生；枚举 `usb_delay_ticks(2)` | VMware 接 USB 键盘会按设计支付端口复位 + 枚举延时；未连接设备时不进入延时 | 未改 |
| PS/2 初始化 | `kb_init` 只清空输出缓冲，无等待循环 | 无差异风险 | 未改 |
| 无光盘 / 无硬盘回退 | `fat_probe` 在 ATA 扫描后快速返回 -1，shell 种默认环境 | 无盘组合下 ATA 空槽路径是主要差异点，已随 3.1 修复 | 已覆盖 |

### 5.2 既有 VMware 兼容逻辑（代码内已存在）

- `net.c`：MAC `FF:FF` 开放总线拒绝；vlance / LANCE 回落固定 MAC。
- 音频：ES1371 作为 VMware 音频回落后端。

### 5.3 未改项及原因

- **CPU 校准 100ms 窗口（K4）**：MHz 仅用于 `sysinfo` 显示（`HW_CPU_MHZ` 唯一消费者 `shell.c:1521`），不参与定时；缩短会降低 MHz 显示精度，留作后续可选优化。
- **读写 PIO 等待循环**：在已探测存在的盘路径上，改动回归风险高，本轮不动。
- **pkg 逐包 stat**：命令时惰性发生，不在启动路径。

## 2. 上一轮 4 个已知问题：验证结论与修复

### #144 `tool_read_whole` 1 字节越界写 + 空文件误判（head/tail/wc 共用）

- **源码确认（HEAD b2c7251）**：`tool_buf[TOOL_BUF_MAX]`（49152），当文件恰好 49152 字节时 `tool_buf[rd] = 0` 写在索引 49152，越界 1 字节；同时 `fs_read_at` 在 `max=0` 时返回 -1，工具把 `rd<=0` 一律判为读取失败，空文件被报成 `no such file`。
- **修复（v2.44，`shell.c`）**：
  - 缓冲改为 `tool_buf[TOOL_BUF_MAX + 1]`，留尾 NUL 位；
  - `fs_resolve_file` 成功且 `sz == 0` 直接返回 0（空缓冲），仅 `rd < 0` 报错；
  - 读满路径 `tool_buf[rd] = 0` 不再越界。
- **实机验证**：`tests/review_fix_verify.py`（日志 `tests/audit_logs/review_fix_verify.log`）—— touch 空文件后 `wc` 输出 `0 0 0`，`head`/`tail` 空文件不报错不崩溃；截图 `V_completion.png`。
- **回归**：fsrec / heap / size 回归全绿，未引入新故障。

### #142 同一分区可挂载到两个挂载点

- **源码确认**：`fs_mount` 只检查挂载点占用与目录非空，未按分区归属去重；两个卷槽打开同一 LBA，各自缓存 FAT，写入后两份缓存可能分叉。
- **初版修复**：挂载前扫描 `g_mnt[]` 同设备名拒绝，返回 `-15`（`mount: partition already mounted elsewhere`）。
- **审查追加（#146）**：初版去重只覆盖附加卷槽，根分区（卷槽 0）仍可被二次绑定到另一挂载点，风险同类。v2.44 新增 `fat_volume_owns(drive, lba)`（`fat.c`/`fat.h`），遍历全部卷槽（含槽 0）按「ATA 驱动号 + 分区 LBA」判归属；`fs_mount` 据此拒绝。
- **实机验证**：
  - `tests/audit_logs/review_fix_verify.log`：P2 二次挂载被拒，挂载表仅一条 `hd0p2 /docs`；截图 `V_mount_dedup.png`。
  - `tests/review_root_remount.py`：`mount 1 /docs2`（根 P1 重绑）被拒；`mount 2 /docs` 正常；`mount 2 /docs3` 重复 P2 被拒；`mount` 表只剩 `hd0 /` 与 `hd0p2 /docs`，4/4 PASS。

### #145 TAB 补全表漏收新命令与 df

- **源码确认**：`sh_cmds[]` 只并入了 P4 工具，P3 彩蛋（cowsay/sl/fortune/cal/yes）与 `df` 漏收；help 行与建议表 `BUILTIN_NAMES` 都在。

- **实机验证**：`review_fix_verify.py` 实测 TAB `cows`→cowsay、`df` 可补全；`review_round2.py` 实测 `cl`→候选栏 `clear cls`、`su`→`su sudo`，均 PASS。

### #143 `cal` 月历表头/单元格残留与个位杂符

- **源码确认**：年视图三个月块复用同一组 7 行栈行，只清首字节，上一组月的数字残留；单日个位用宽度 2 `itoa` 补零，把 `'0'` 写进个位格，渲染成 `?`/`?,` 杂符。

## 六、TTF 交叉核对结论（v2.55-ttf）

### 6.1 核对口径与结果

- 参考字体（宿主全量）：`DejaVuSans.ttf`、Liberation Sans；入库子集资产：`kernel_v25/fonts/DejaVu-subset.ttf`（16.8KB）、`kernel_v25/fonts/LiberationSans-subset.ttf`（27.4KB）。
- 核对字符：`A`（U+0041）、`g`（U+0067）、`é`（U+00E9，复合字形）。
- 判据：解析轮廓点与 fontTools 4.68.0 地面真值**逐点 byte-exact**（坐标 ≤1 font unit 误差内），advance width 相等；畸形/截断/垃圾缓冲全部安全拒绝。
- 结果：**4 字体 × A/g/é 全部逐点一致，宿主单测 ALL PASS**（含 unitsPerEm/numGlyphs 度量核对与畸形输入拒绝用例）。
- 复跑：`gcc -std=c99 -I kernel_v25/include tests/ttf_host_test.c kernel_v25/src/ttf.c`；期望表由 `tests/ttf_gen_expect.py`（fontTools）生成入 `tests/ttf_expect.h`。

### 6.2 调试累计修复的 7 个解析 bug

1. **rd8 字节偏移**：复合/简单字形字节参数初版误取 rd16 高字节；改为按低地址字节直读。
2. **cmap 子表相对偏移**：子表偏移相对 cmap 表起点（非文件绝对偏移），初版按绝对地址定位导致 format4 子表查找错位。
3. **REPEAT 标志展开循环条件**：标志字节 `REPEAT`（0x08）后随重复计数字节，展开循环的计数/推进条件初版错误，点位数与标志数组错位。
4. **复合 BYTE 参数分支**：无 `CF_WORDS` 标志时偏移量应为 `rd8×2` 共 2 字节；初版误按 `rd16×2` 共 4 字节推进，后续组件字段全部错读。
5. **零 delta 规则**：`X_SAME`/`Y_SAME` 在无对应 `X_SHORT`/`Y_SHORT` 时 delta 为 0、占 0 字节；初版漏该分支，多吃字节导致坐标流错位。
6. **scale 标志位错位**：复合变换标志 `WE_HAVE_A_SCALE=0x0008`、`WE_HAVE_AN_X_AND_Y_SCALE=0x0040`、`WE_HAVE_A_TWO_BY_TWO=0x0080`；`0x0100` 是 `WE_HAVE_INSTRUCTIONS`（指令跟随所有组件之后），初版被误判成 TWO_BY_TWO。
7. **期望发射循环漏发**：交叉核对期望生成器逐字符发射循环漏发部分字形，子集 cmap 缺字未跳过；修正为按每字体 nchars 迭代、缺字符跳过。

### 6.3 TTF deferred（如实登记）

- **内核集成未做**：`build.sh` 尚未接入 `ttf.c`，gfx24 `glyph_render` API 未对接；解析层目前仅在宿主单测验证。
- scale / 2×2 复合变换的实机渲染用例未做；CFF（PostScript 轮廓）字体不在本批范围，仅做 sfnt 目录识别与表存在性标注。

## 2.1 v2.57 滚动返工（线性逐行视口，2026-11-19 05:45 合入）

首轮回溯实现是「归档行贴底生长 + 顶部恒定反色提示条」，与验收口径不符。返工（clone `CatOs-b`，commit `ee4c2f8`，merge `02c77e3`）改为：

- 行序列 = `arch[count-1]…arch[0] | live[0]…live[rows-1]`，视口偏移 v 决定每行取 arch 还是 live；
- `sb_step_older()`：**整屏逐行 memmove 下移一行**，顶行从归档补入；`sb_step_newer()` 反向、底行从序列补回；**无 `cell_blank` 全屏清空、无 `redraw_all`、无提示行**；
- PgUp/PgDn = 循环 `con_rows()-1` 次单行位移（页高运行时读取，无硬编码 24）；到顶/到底停止，不重复不空行；离开回溯恢复 `sb_live` 快照；
- 关键 bug：新填入行必须清 `painted_valid[y][x]`，否则 paint 脏跟踪跳过后归档行上不了帧缓冲（表现为顶上空白行）。

证据：`shots-scrollfix-20261119/step0..3.png`（text，连按 3 次 Ctrl+↑，顶行 hl24→hl23→hl23…逐帧下移一行、顶行补入归档、无提示条无空行）、`gfx24_step3.png`（gfx24 同行为）；`mouse_regress` 的 `K=3 single-line steps shift rows by K`、`top boundary: no duplicate/blank history row` 两条断言直接比对行内容。

### 2. 后台任务输出管理 —— 拆为任务 #59

### 5.1 环境结论（云主机构建链）

## 六、2026-11-13 Windows 侧：v2.20 VMware SVGA II 24 位真彩

用户反馈「下载文件夹有最新版。顺便做 VMware 24 色真彩支持。我输入 vbe 和 vbe24
都不行」。两条都是真问题：

| 症状 | 根因 | 处理 |
|---|---|---|
| `vbe24` 不识别 | shell 只注册了 `gfx24`，没有 `vbe24` 别名 | 分发链加 `vbe24` 别名 + help 文案 |
| `vbe` / `gfx24` 报 no VBE/Bochs-dispi | VMware 显卡是 `15AD:0405` SVGA II，没有 0x01CE dispi 端口；后端只有 Bochs 一条路 | 新增 `src/svga.c` + `include/svga.h`，按 PCI 身份选择后端 |
| QEMU `-vga vmware` 实测黑屏 | QEMU 的 vmware-svga 复用通用 VGA 核，**仍会应答 dispi ID**，旧代码因此走 Bochs 路径把像素写到不存在的 `0xE0000000` | 改为「PCI 上发现 SVGA II 就优先 SVGA」，dispi 只作兜底 |

实现要点：

- BAR0 I/O（index=base+0 / value=base+1）、BAR1 LFB、BAR2 FIFO；
  寄存器号对齐 VMware `svga_reg.h` / QEMU `vmware_vga.c`。
- SVGA II 是 32bpp XRGB 设备（DEPTH 读回 24，BPP 只有 32）。CatOS 保持
  **RGB24 公共绘图 ABI 不变**，按设备给的 `BYTES_PER_LINE` 与颜色掩码在
  运行时决定 pitch / 每像素字节数 / 通道偏移，第 4 字节写 0xFF。
- 启用 FIFO 后宿主停止 VGA dirty tracking，直写显存不会自动上屏；
  IRQ0 的 `svga_tick()` 以 25 Hz 推送全屏 `SVGA_CMD_UPDATE` 并写 SYNC。
  `fifo_init()` **只初始化 guest-owned 的 MIN/MAX/NEXT/STOP**；CAPABILITIES /
  FLAGS 是 host-owned advertisement words，真实 VMware 可能在其中发布 RESERVE，
  guest 清零会破坏协商。CatOS 用 legacy plain ring（写 NEXT + SYNC），
  不需要任何 capability 协商，因此保持这两字原样。
- `paging.c::vbe_lfb_map()` 改为累积 PDE 区间，让 FB 与 FIFO 两个 BAR
  同时镜像进每个任务页目录（PTE 仍是 supervisor-only，#84 不破）。
- `extapp/gfx24.c` 不再硬编码 `pitch==2400`（改为 `pitch >= w*3`），
  否则 ring3 探针在 SVGA 上会拒绝绘图。
- 新命令 `svgainfo`；`display` 增 `graphics HW` / `last gfx24 hw` / `hw_bpp` / `stride`；
  `gfx_info` 追加三个只读选择器（BACKEND / HW_BPP / STRIDE，ABI append-only）。

验证（`tests/svga24_regress.py`，QEMU 11.1 `-vga vmware`，monitor 4467）：
**34 项全绿**，含 gfx24/vbe24 演示图逐像素（红/绿/蓝/白/渐变/8 色条）、
ring3 `gfx_rect`/`gfx_blit`、FIFO UPDATE 计数、`vbe` 真彩文本 RGB 断言。
QEMU `-vga std` 老路径 `gfx24_regress` 仍 0 failed；qemu 12/12、user 15/15、
security 17/17、disk 5/5、宿主 test_mkce 48 / test_cc 10 / ce_regress 11P /
test_app_list 24 全绿。
**真实 VMware Workstation 尚需用户开 VM 复测**（本机 VM 当前未运行）。
开机后依次执行 `svgainfo` → `vbe` → `text` + `Y` → `vbe24` → `text` + `Y`
→ `gfx24` → `text` + `Y` → `display`。四条图形命令都应进入 800x600 真彩
且画面完整（不是黑屏）；`svgainfo` 应报 `SVGA II adapter : present` /
`0x90000002` 且 `updates > 0`（FIFO 刷新在工作）。若真机黑屏但 `updates`
在涨，优先怀疑 32bpp 通道序与 `fifo_sync()` 的 BUSY 轮询时序。
