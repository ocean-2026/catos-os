# experience.md - 开发经验记录

格式：[所属项目][经验]内容

- [ot][经验] 黑盒探测优先于猜测：execve 实现前用 argv_probe.c 实测内核 CE 调用约定（argv@0x0147c500/字符串@0x0147c540/esp/ce_main@0x02000000/api 表@0x0101c280），所有常量来自实测而非文档推导
- [ot][经验] 裸函数（naked）内无操作数 asm 用**单 %** 寄存器，扩展 asm（有操作数）用 **%%**；混用报 "bad register name"（exec_tramp 踩过）
- [ot][经验] QEMU sendkey 数字参数（0xNN）语义在 QKeyCode/PS/2 扫描码间不可靠（实测 0x2d 时 x 时 v），**键名模式（sendkey c）更稳定**；长 hold 参数（sendkey o 1000）不改善 CatOS 接收率
- [ot][经验] 跳板/桩代码用 `__attribute__((naked))` + 纯汇编 + `exec_tramp_end` 取长度差拷贝，避免内联函数地址问题；用 objdump 反汇编核对每条指令机器码再进 VM
- [ot][经验] exec 场景（覆写自身镜像）的调试节奏：先在宿主侧完成全部静态验证（CE01 头解析、跳板寄存器契约、反汇编），VM 只做最终确认，减少对脆弱键盘通道的依赖
- [ot][经验] 内核栈 8KiB 限制下，跳板/argv 区选在探测到的固定安全区（0x0147c500-0x0147c800），避开镜像（0x02000000）与内核栈（esp≈0x0147e658），先算布局再写代码
- [ot][经验] 镜像预算管理三原则：① bss 不占镜像（static 大缓冲随意用，如 4KB 分配器池/2.5KB 快照缓冲）；② text/rodata 才占镜像，入镜像前先算余量（65536 减当前体积）；③ 余量不足时优先外置 /BIN/*.csc 脚本（自动注册机制已有，calc/wc/time 已验证），或写设计文档延后（L3/⑩ 即此策略）
- [ot][经验] 键盘失效（#34）时的验证分层：① 静态（构建+bss/镜像体积核验）② 符号（objdump -t 核验新函数入镜像）③ 反汇编行为（objdump -d 核验关键逻辑如递归下降求值器）④ VM 交互（键盘好时才做）；③④ 都可覆盖时如实汇报验证方式，不长时间卡键盘
- [ot][经验] 复用小机制胜过新机制：swap 直接复用 csc_save_shards（512B 分片写）+ csc_snapb（分片读回重组），仅 +56B 就打破 save 512B/cat 8KB 双限制；改造现有原语而非另写文件 IO
- [ot][经验] 大 rodata 资产外置省镜像：像素画 banner（~460B）移到 /BIN/BANNER.TXT 由 cmd_banner 读文件渲染（复用 csc_index_lines/csc_fetch_row 逐行输出），缺文件时降级纯文本标题——净省 ~288B 镜像，且用户可编辑 banner；外置边界：启动路径依赖磁盘（缺文件有降级即可）
- [ot][经验] swap 旧分片残留绕行：CE 无 delete API 无法清旧 .A0x 文件，改为 swapin 按 RAM 页表 g_swap_n 只读主文件+前 N-1 片（起始片 .A00 对应 page1），陈旧分片被边界自然忽略——用状态计数代替文件清理
- [ot][经验] L3 子程序帧栈放 bss 不占镜像：8 帧 × (10×40B argv + 4B argc + 4B ret) ≈ 3.2KB 全在 bss（静态），实现 func/call/ret 代码仅 ~700B 入镜像；$ret 返回值直接复用变量表（csc_set("ret")）零新增展开逻辑
- [ot内核v2.5][经验] 大文件读写绕行 FS_DATA_MAX：新增独立 syscall（SYS_FILE_READ/WRITE/DELETE）走 FAT 链簇定位，不经 512B save 上限；offset 读 = offset/簇大小 跳链 + 簇内偏移，写 = mode0 截断/mode1 从链尾续接（fat_append_file）
- [ot内核v2.5][经验] CE 镜像上限提升套路：CE_MAX_IMAGE/BSS 常量提升 + 移除内核临时大缓冲（ce_bounce）+ spawn 改为"读首簇解析 header + 沿 FAT 链直写已建立页的映射"（避免整镜像进内核缓冲），256KB 镜像成本=页表页数
- [ot内核v2.5][经验] 管道 EOF 语义：read 读到空但 writer 仍开 → 阻塞；读到数据读空即返回（不因 got<max 死等）；writer 关闭（open_w=0）→ read 空时返 EOF（got=0）——"有数据即返回 + 无数据等" 两态正确实现避免死锁
- [ot内核v2.5][经验] 内核调试三件套：objdump -t 找崩溃 eip 符号 → objdump -D -b binary 看指令（pop gs=0f a9）→ 比对 cpu.s 源码理解帧布局；QEMU monitor sendkey + screendump + tesseract OCR 全自动回归
- [node解释器][经验] 微型解释器调试三层递进：token 流 → AST dump → 求值追踪；AST dump 与运行时错误点打印**节点地址+op**，地址对比可直接区分"解析建错节点"vs"运行期节点被污染/链表越界"（本轮 callee-op 2→3 之谜最终是 tok_kw 前缀误判，n_new 垃圾节点是另一族）
- [node解释器][经验] 解释器 bss 预算：大头 = token 数组(2048×16B) + arena + srcbuf；递归 fib(10) 每调用分配 scope ~144B，两遍调用 ~50KB → arena 按最坏脚本路径留量（96→160KB）；TOK_MAX 4096→2048 省 32KB；CE bss 控制在 256KB 内（当前 0x32180=205KB）
- [ot内核][经验] FAT 共享介质一致性：#48 根因=整扇区重写抹掉宿主注入表项；修法=脏表项 journal + 脏扇区 RMW（先读盘再补丁）+ 分配前核对磁盘真 0；教训：FAT 表是"多写者共享"资源（宿主工具+内核），任何整块覆写都必须基于磁盘真值而非内存缓存
- [node解释器][经验] 错误恢复健壮性：递归下降解析器每个循环（p_stmt_list/实参/声明符）都要有 token 前进不变量，否则任何 perr 路径都可能变成无限分配；加 ti0 对比 + 强制推进是通用保险
- [ot内核v2.5/工具链][经验] 单一真值源治常量漂移：构建脚本不要复制内核常量，运行时解析 `include/ce.h` 的 `#define CE_MAX_IMAGE/CE_MAX_BSS`（找不到头文件时回退内置值），再用回归测试断言「脚本读到的值 == 头文件值」+「两份副本字节相同」；以后提升上限只改一处
- [ot内核v2.5/工具链][经验] 把加载器校验前移到构建期：内核 `task_spawn_ce` 的三条早退（image / bss / api_offset）在 mkce.py 同步实现，报错直接给出违反的上限和来源头文件；QEMU 不可用的环境下，构建期能拦住的错误不要留到实机再排查
- [ot内核v2.5/工具链][经验] 重复脚本必然腐烂：同一构建链出现 `extapp/build_ce.sh` 与 `tests/build_ce.sh` 两份副本后只有前者被持续维护，后者路径全失效；修法是让后者成为薄包装（解析源文件绝对路径 + exec 转发），并在注释里写清产物落点
- [ot内核v2.5/工具链][经验] 边界值要用真实产物校准：新增 api_offset 校验时先跑一遍真实 `spawn_fail.ce`，发现 `api+4 == image_size` 恰好相等，因此判定必须用 `>` 而非 `>=`；先测真实产物再定边界，比凭代码生成逻辑推断可靠
- [ot内核v2.5/工具链][经验] 构建工具的校验允许「比内核更严」但不允许更松：内核 `task_spawn_ce` 用 `uint32_t` 算 `api+4`，`api=0xFFFFFFFC` 回绕成 0 会绕过校验并在映射区外写 API 表指针；mkce.py 用无限精度整数并显式拒绝 `api > UINT32_MAX-4`。发现内核侧缺陷时先记入问题清单、明确交给主工作树合流处理，不在隔离分支擅改他人活跃文件
- [ot内核v2.5/工具链][经验] 复核要专门验证「测试能不能失败」：新回归套件写完先做独立只读复核，重点问「如果被测机制完全失效，这条断言还会不会绿」；本次正是靠这个提问抓出回退值假阳性，比再加十条正常路径用例更有价值
- [CatOS/#90][经验] **逐字节同构复刻内核 mkfs 到宿主工具**是免改内核的应用解耦路径：`mkdisk.py` 复刻 `fat_mkfs()` 布局 + import `gen_builtin.py` 的文件清单保单一来源，内核 `fat_probe()` 只认 DBR 字段所以零改动即挂载；比 GRUB module + multiboot info 解析简单一个数量级，且绕开了"本机无 GRUB 工具链"的硬约束
- [CatOS/#91][经验] **能力检查放内核 syscall 分发处，不放 shell 层**：shell 可以被绕过（直接写 CE 程序调 syscall），只有分发处强制才构成安全边界；代价是零——现成 prologue 加一行判断。配套需要探针区分「-1 硬件缺失」vs「-13 能力拒绝」（captest.ce 打印原始返回码），否则拒绝会被误诊为没硬件
- [CatOS/#86][经验] **用户指针的统一心法是"快照进内核"而不是"校验后裸写"**：逐边界补页校验（validate 1 字节）靠人手维护、漏一处就是停机级故障；`copy_from_user()` 页表拷贝天然对跨页/未映射页健壮。字符串这种未知长度场景用 `u2k_str()` 内核快照，按真实上界校验而不是按 1 字节
- [CatOS/#91][经验] 权限语义重构时保留旧默认行为作底：新 Unix 三段位 ACL 查不到表项时回退到旧白名单（/home、/tmp 可写），老应用（perms.ce）合同不变，回归不用重写——重构兼容层的验证成本由此减半
- [CatOS/流程][经验] 每轮交付后**同步问题清单状态列**是硬约定：清单是后来者的唯一事实源，代码改了状态不改，「待修复」会误导下一轮重复排查（#75 的教训）；API.txt 与 apps.list 同理，改 ABI/应用集必须同轮同步文档
- [CatOS/v2.14][经验] **收编老项目的原则是"内核已有的从 ot 去掉，没有但有价值的内核态实现"**：ot 的 30 个与 shell 重复命令直接从命令表删除（而不是留着兼容），独有价值（脚本引擎/文件管理器/十六进制编辑/搜索/版本控制）保留；当年在用户态做 workaround 的根因（无非阻塞按键、无文件四件套）在内核态补齐后，应用侧 hack 一行不留
- [CatOS/v2.14][经验] **修用户态 hack 要修到 API 层而不是给 hack 发护照**：adofai 屏蔽 IRQ1 + 直读 0x64/0x60 的"解法"本质是 ring3 篡改中断控制器；正确路径是内核补 slot 64 `pollkey()`（`kb_getkey_timed(0)`，nargs=0 沿用单参 thunk），游戏删光 IMR/端口代码——能力进内核，应用只管调用
- [CatOS/v2.14][经验] **测试 flaky 先怀疑测试节奏再怀疑内核**：ot_regress 三处 FAIL 手动复现全部成功，根因全是测试侧（y 没跟 Enter、format 后等 2.5s 不够、读屏竞态）；诊断方法是手动脚本逐步二分"哪一步之后 faultinfo 有记录"，定位后修测试而非内核
CatOS[经验] UHCI 轮询式 HID 键盘驱动最小实现：PIIX3 UHCI（BAR4 I/O）+ 4KB 帧表全指向单 QH + 单中断 IN TD，10ms 定时器轮询 TD status，免 EHCI/OHCI 复杂度即得 USB 键盘；控制传输（SETUP/IN/OUT 深度链）仅用于枚举三步，之后设备地址固定，无需 SET_IDLE/SET_PROTOCOL。
CatOS[经验] 判定"内核某路径是否真的执行"：不要相信源码里有调用就等于运行——先核实调用点是否处于可达路径（CatOS case 0 教训），再用一次性串口 breadcrumb（static flag 打一次日志）做存在性验证，成本远低于反复推断。
CatOS[经验] 审查 ring0 shell 权限面的高效手法：按 fs_touch/fs_mkdir/fs_write_raw_mode/fs_copy_file/fs_delete/fs_rmdir 全量 grep shell.c，逐个确认该命令在写盘前是否经过 perm_write_on_parent 或 fs_perm_check；未经过的就是 syscall 层守卫罩不住的缺口（本轮由此定位 touch 漏网）。
CatOS[经验] QEMU UHCI 热插拔时序：monitor device_add usb-kbd 后，内核靠 100 tick 轮询挂起 pending_attach、由键盘等待循环里的 usb_service() 触发扫描+端口复位；枚举/复位需要 1~2s 窗口，探针延迟太短会读到 "no device found" 误判为驱动缺陷。端口状态 bit7(0x0080) 在 QEMU 实连时置位，可作端口有效位判据。
CatOS[经验] 终端现代主题整改的最低风险路径：以 16 色 CLUT 为唯一语义映射层——bg=#0C0C0C、正文=#DCDCDC、次要=#8B949E、强调绿=#7EE787、路径蓝=#60A5FA、语义红=#F85149/黄=#E3B341/青=#39C5CF/成功绿=#56D364，分别映射到 CON_BLACK/LIGHT_GREY/DARK_GREY/LIGHT_GREEN/LIGHT_BLUE/LIGHT_RED/YELLOW/LIGHT_CYAN/GREEN；shell 侧提示符/错误/成功只引用索引，不改硬编码 RGB，换肤只需改一张表。
CatOS[经验] 帮助/清单两列对齐：写一个 help_row(cmd,desc) 小助手，先把命令左对齐补齐到固定宽度（24）再写分隔与描述列（第 26 列起），比在超长静态字符串里手工数空格稳健；命令超宽时补齐循环自然跳过、描述退一格不崩溃。
CatOS[经验] 扩展恒等映射覆盖范围时，把“映射上界”和“分配器上界”分开维护：PSE 尾块可整块映射（沿用旧 16-PSE 行为），但分配器只发 < mem_top 的帧，尾块内不存在的 RAM/hole 永远不会被触达；任务目录镜像要复制全部 1024 个内核 PDE（不能只拷前 16 个），高 LFB PT PDE 随 kdir 一起镜像且保持 supervisor-only（无 US 位），ring3 仍不可触达。
CatOS[经验] 排查内存类回归先画探测链路再动手：GRUB mbi.mem_lower/mem_upper → kernel.c 透传 → hw_mem_boot/hw_num 显示 → paging_init 的 PMM 上界；逐段确认有无二次截断（本轮截断点在 hw.c 总量钳到 63MiB、paging.c top 钳到 64MiB 两处），其余消费方（shell mem 命令直读 mbi、hwinfo/top 走 hw_num）无需改。
CatOS[经验] 区分“既有环境问题”与“新引入回归”的最快办法是 A/B：git stash 源码改动 → 重建 iso → 同一条回归脚本跑基线 → 比对失败集合；本轮 size_regress 三档 band 在基线同样 FAIL，根因是检测色值常量滞后于现代主题配色，与内存改动无关。
CatOS[经验] 为新二进制格式写内核加载器时，先在宿主侧用 Python 按磁盘偏移逐字段解包并跑一遍全部边界校验，再对照内核 C 结构体；字段错位这类问题在宿主模拟器里能立刻暴露，比反复实机重编译截图定位快一个数量级。
CatOS[经验] 跨 guest 会话持久化 FAT 卷的稳妥模式：fresh 磁盘 → 拷到本地 /tmp 暂存 → guest 格式化 → 退出前把暂存盘拷回原始磁盘 → 宿主注入工具写原始磁盘 → 再拷回暂存盘起第二遍；既绕开工作区 fs 的 flock 限制，又保证两遍之间卷状态连续。
CatOS[经验] 给内核加第三条二进制轨道（CE01/ELF32 之外的 PE32）时，分派点先按魔数三分支，再把"镜像/bss/api 槽位注入"这类旧轨道专属条件用 !is_elf && !is_pe 排除；新轨道的段映射/VMA 标记在各自 loader 内部完成，避免污染既有 CE/ELF 路径的页表与 API 槽写入。
CatOS[经验] 多卷 FAT 内核的最小改造路径：几何参数按卷存上下文结构体，FAT 缓存/写日志作为活跃卷共享（避免每卷再占一份 4 MiB 静态缓存撑大 BSS），切卷时从磁盘重载该卷 FAT #1；接口上只加 activate/mount/release 三个动作，旧的 fat_* 操作签名不动，上层 fs 调用方几乎零改。
CatOS[经验] Linux 挂载语义在 VFS 层的落点：路径解析做最长前缀匹配，命中挂载点即切到对应卷再解析剩余相对路径；盘符后缀只在列目录展示时按“父路径/名字”反查挂载表追加，目录本身不改名，umount 后原名自然恢复，无需额外的改名/还原逻辑。
CatOS[经验] 无 sfdisk/mtools 时，宿主 Python 可直接构造双分区 FAT32 测试盘：镜像内核 mkdisk 的 DBR/双 FAT/根目录写入器，按分区 LBA 落盘，MBR 填两个 0x0C 表项（起始 LBA + 扇区数）；分区内预置一个标记文件即可在 guest 里验证跨分区读，cp 一个已有文件进去即可验证跨分区写。
CatOS[经验] ring0 shell 内建是彩蛋类功能的最低成本路径：无需走 CE 编译链（extapp/build_ce.sh + builtin_apps.inc 嵌入），在 shell.c 加分发分支即可；逐帧动画用 task_sleep_ticks(6)（tick=10ms，约 60ms/帧），可中断轮询用 kb_getkey_timed(1)，收到 0x03（Ctrl+C）即退出。

# history.md - 易错点记录

格式：[所属项目][易错点]内容
判定准则：只要是因为管理不当或非技术原因导致的、细心就能避免的意外，就算易错点（2026-10-24 用户定稿）。

- [ot][易错点] execve 加载 CE 时 image 必须**跳过 16 字节 CE01 头**从 fb+16 拷入 0x02000000；若连头一起拷，0x02000000 处是 'CE01' 魔数数据，ce_main 实际在 +16 处，call 0x02000000 执行垃圾指令导致输出乱码（v1.9 乱码根因，已修）

CatOS[易错点] 全量回归一键脚本在 600s 前台预算内会被 SIGTERM（exit 143），size 套件环境侧 PPM 解析/monitor 往返慢（每步约 2 分钟）；长套件必须后台 nohup + 轮询日志，且按日志时间戳确认是本轮新鲜产物——旧基线日志（Nov16）不能复用，被中断的套件只跑了前几个检查点，重跑要数全 PASS 条数。
CatOS[易错点] `screen_text()` 只转储当前 25 行可视区：回放/提示后紧跟长列表（ls 18 条、/bin 三十余条）会把 shell 刚打印的 `-> <cmd>` 回显行滚出屏幕，断言回显标记会假阴性。选单行输出的建议目标（date/whoami）做回显断言；长列表用例改断言列表条目内容（如注入的 pesample.exe），不要追滚动中的提示行。
CatOS[易错点] `pkill -f qemu-system-i386` 会匹配到执行该命令的自身 `bash -c` 命令行（串里含同样的二进制名），把当前 shell 一起杀掉，后台任务瞬间 exit 1、子进程群被连带回收；清残留要先 `pgrep -x qemu-system-i386` 按 PID 精确杀，或命令行里规避该子串。
CatOS[易错点] pending 类交互状态（did-you-mean 待确认）的识别只能挂主提示符循环：命令内部的 y/n 问询（PE->CE offer、format 闸门、gfx consent、useradd wizard）走各自 `kb_readline`/`kb_getkey`，不经主循环，天然隔离；切勿把「输入是 y 就回放」下沉到 readline 全局层，否则会污染所有问询上下文。
CatOS[易错点] extapp/build 残留半成品中间件会让全量重建在某应用上挂掉：上次被中断的 .exe 留下残缺 PE，下次 ld 覆盖前 nm/objdump 报 "file format not recognized"，继而 "ce_main not at image offset 0"；单独重编该 app 又能过，假象是偶发。整盘重建前先清 `extapp/build/*.exe *.o *.bin *.nobss.exe`。
CatOS[易错点] LFN 条目读回保留原始大小写，只有无损 8.3 短条目路径才统一小写展示；回归断言混合大小写文件名时要分两条路径写期望（8.3→小写，LFN→原样），不能一律按小写 substring 匹配造成假阴性。
CatOS[易错点] 公共层把 __ce_api 槽收编成单个 .c 定义时，若用强符号链接进所有 app，未改造 app 本地的槽定义会撞 "multiple definition"；过渡期公共定义必须标 weak，旧 app 强定义自动覆盖，改造一个迁一个，最后再去掉 weak。
CatOS[易错点] `fs_rmdir` 非空判定回调 `rmdir_cb` 旧条件 `!scmp(name,".") && !scmp(name,"..")` 要求名字同时等于 "." 和 ".."，恒假，计数永远 0，非空目录被当成空目录放行；正确写法是 `scmp(name,".")!=0 && scmp(name,"..")!=0`（跳过两个点条目后计数真实条目）。
CatOS[易错点] 严格化目录非空检查后，既有 `rm -r` 递归清空器暴露出 fat 层嵌套 delete-name 潜在重入问题（见问题清单 #155）；本批把 `fs_rmdir` 拆成 strict（rmdir 命令）/force（rm -r 后序清空器）两条路径，force 保持 v2.24 基线行为，不在本批改 fat 内部。
CatOS[易错点] /etc/passwd 长口令记录在 VGA 按 80 列折行，回归抓屏文本里十六进制串会被换行/空格打断；正则匹配前先 `re.sub(r"\s+","",txt)` 归一化，否则 128 位 digest 的 32 hex 断言假阴性。
CatOS[易错点] 任务退出路径先唤醒 parent 再 maybe_autoreap，父进程被置 READY 后 autoreap 判定「无人等待」把僵尸直接回收成 T_UNUSED；等待方若只认 ZOMBIE（如 task_wait_child_or_stop）就永远等一个已回收槽位死循环。退出路径必须「先 reap 判定（parent 仍在 WAIT_CHILD 才保留僵尸）、后唤醒 parent」，且 wait 类循环要防御性接受 T_UNUSED 作为子任务已退出。
CatOS[易错点] QEMU 开机后立刻 sendkey/type_text，PS/2 控制器自检/初始化残留会产生幽灵按键（屏幕出现 18118128138 一类数字噪声）污染第一条命令；开机后先丢弃性 type 一次或等 1-2s 再开始正式断言输入，否则 argv 里混入垃圾尾巴导致 bg 解析、参数断言随机假阴性。
CatOS[易错点] fs_perm_check 里文件 mode 是经典 octal triad（r=4/w=2/x=1），而 syscall need 是独立 PERM_READ=1/WRITE=2/EXEC=4 位掩码；直接 `(have & need)` 相与会把 4xx 读位误拒、把执行位 1 误当成 READ 放行。取出 triad 后必须先翻译成 PERM_* 再比对（见问题清单 #157）；附加组/组位分支挂在组位判定上，掩码翻译错了组可读访问会整体假阴性。
CatOS[易错点] 附加组成员在磁盘 /etc/group 上按用户名存，加载时才对 /etc/passwd 解析成 uid；权限检查路径只能拿 uid 查组库（user_in_group），不能要求任务凭据里带附加组数组。老记录只有主 gid：组判定先比主 gid，未命中再遍历附加组，缺省组库为空时行为与单 gid 基线一致。
CatOS[易错点] 后台/重定向 CE 应用（如 `hello > file`）是异步任务，chown/chmod 紧随重定向下发时应用可能还在写；抓屏断言要给足命令间隔，且 VGA 旧行残留会让上一条 permission denied 污染下一条断言，读取状态行前先 clear 或只取最后一条 jobs/结果行。
CatOS[易错点] 探针驱动后台任务时，任务寿命必须覆盖全部断言窗口：`daemon memlog 6 500` 3 秒自退，dm-3 的 log 检查在 ~4.5s 必拿「no such task」；`spinner 4 &` 2 秒跑完，fg 到达时已被回收报「fg: no such job」。短寿命自退型任务一律换成 ≥ 断言总耗时的参数（memlog 60x500 / spinner 20），或默认无限循环由探针显式 kill。
CatOS[易错点] 隔离实验 stash/checkout 会把未提交的配套改动一并还原：v2.52 期间为 jobctl 放宽的 spinner 上限 8→60→200（未提交），v2.54 隔离验证后 spinner 回到 60，`spinner 180` 被钳到默认 8 tick 约 1-2 秒退出，jobctl 的 jobs-lists-running 随机假失败。从工作树复跑针对性套件前，先核对探针依赖的未提交源码还在不在（git diff 具体文件），而不是只看 HEAD 提交了什么。
CatOS[易错点] TTF 复合字形变换标志位：0x0100 是 WE_HAVE_INSTRUCTIONS（指令块在所有组件之后），不是 TWO_BY_TWO；三个缩放标志正确值是 WE_HAVE_A_SCALE=0x0008、WE_HAVE_AN_X_AND_Y_SCALE=0x0040、WE_HAVE_A_TWO_BY_TWO=0x0080。标志对错位会把后续组件字段当成 2×2 矩阵读，轮廓点整体错位且不报错。
CatOS[易错点] TTF 复合组件无 CF_WORDS(0x0001) 标志时偏移参数是两个字节（rd8×2，游标推进 2），不是 rd16×2 推进 4；再按 CF_XY_VALUES(0x0002) 决定有符号/无符号，缺该标志属点匹配参数（本批解析层直接拒绝）。字节分支多读 2 字节会让后面所有组件的 gid/变换字段连环错读。
CatOS[易错点] 多分支合并前先把已跟踪的构建产物 stash/移出工作树：带 .ce/.catpkg 本地改动的工作树 `merge --ff-only` 会被"本地修改会被覆盖"挡住；产物噪声不进 docs-only commit，打包时统一排除 */obj/*、*.ppm、*.bin、*/night/* 等目录。
CatOS[易错点] TSC 超时计算的单位倍率：cpu_mhz 是 cycles/1e6 秒（MHz），N 秒超时应读 `mhz*1000000u*N`；写成 `mhz*1000*N` 会把 N 秒缩成 N/1000 秒（30 s → 30 ms），进蓝屏立即判超时退出，按键分支根本走不到。定位手段：BSS 调试字在 enter/drawn/key/timeout 各阶段写不同值，monitor `xp` 读回即可看出落在哪条分支；校准值还要加 `mhz>0 && mhz<10000` 闸门防 bogus 除数。
CatOS[易错点] 崩溃屏不要直写 0xB8000 帧缓冲再混前端写：前端 `render_flush()` 在写入 wide CJK 后若挂 `pending_wide` 会调 `redraw_all()`，`be->clear()` + 按 RAM grid 逐格重刷 VRAM；直写内容不在 grid 里，旧网格（prompt/空格）会把直写行整行盖掉，只有经过前端写的行幸存。紧急屏一律走纯前端路径：`vga_set_color` → `vga_clear()` → 全部 `vga_write_at`/`vga_write_at_utf8`，grid 与 VRAM 自洽。
CatOS[易错点] 单行 ASCII 写接口不要喂 UTF-8 CJK 字节：`vga_write_at` 按单字节单格铺，中文三字节被拆成三个半宽格，后续 ASCII 被错位移到行右半截。含中文的行必须走 `vga_write_at_utf8`；纯英文注记行就不要夹带汉字，两段调用分开（前缀 ASCII 定位 + 后缀 utf8）。
CatOS[易错点] 递归遍历目录树时静态簇缓冲不能跨递归调用复用：子目录 `fat_read_cluster(child, buf)` 会覆盖外层同一个 static buf，返回后外层循环 `b = buf + i*32` 读到的是子目录内容，表现为外层目录只扫到前几个条目就中断、后续坏项全部漏报（本轮 fsck 扫描器实测根目录只进了 DEV 就停）。递归扫描必须按深度分缓冲 `bufs[depth]`；非递归的普通遍历器用单缓冲没问题。
CatOS[易错点] 多 clone 并发跑回归时，部分套件的 monitor 端口是写死在脚本里的（size_regress PORT=4492），另一 clone 占用同端口后，本驱动会连到别人的 monitor，HMP 回复为空、`screendump` 落不了文件，报错看起来像「screendump produced no file」而不是端口冲突。先 `ps aux | grep qemu` 核对端口占用；临时把本 clone 套件 PORT 改到空闲口（4526 等）跑完，提交前还原，不要把端口改动带进 commit。
CatOS[易错点] dispi/LFB 图形模式下 0xB8000 文本平面不是可读镜像：be_text 独占的 VGA 文本窗口在 gfx/vbe/vbe24 后端下，CPU 写 0xB8000 的内容 monitor `xp /4000 0xb8000` 读回仍是空白（QEMU 文本平面在图形模式下与帧缓冲不在同一可观测窗口）。前端给图形后端加一层 0xB8000 文本镜像的方案验证不可行（写入落地但读不回），旧文本读屏测试不能靠内核镜像补救，只能：运行时盲发 `text`+Y consent 切回文本后端，或在磁盘上预置 /etc/videomode=text。
CatOS[易错点] 启动早期打印的回退警告会被后面的 boot_autostart banner 滚出 25 行缓冲：先把警告文案存进全局备注，banner 跑完后再补打一行，否则回退原因在屏幕上不可见，验收时读 0xB8000 抓不到 WARNING。
CatOS[易错点] 开机默认改 gfx24 后，面向文本屏的旧回归套件会在 wait_for_prompt/clean_run 处读空缓冲：驱动侧 force_text() 在 shell 就绪后盲发 `text`、回车、`y`、回车，并轮询提示符（最长 20s），首次 `text` 落在 shell 就绪前被吞掉时自动重发一次；不要把固定 sleep 当就绪判据。
CatOS[易错点] 崩溃屏二次异常护栏的「已在 panic」标志只在硬崩溃路径保持；软测试钩子（`bsod --no-reboot` 按键回 shell）退出蓝屏时必须复位 `g_in_panic`/深度计数/记录，否则本次启动内第二次主动蓝屏会被护栏误判为「蓝屏屏内嵌套致命异常」而直接 cli;hlt，后续隔离/诊断步骤全部落空。护栏标志的生命周期要区分「本次崩溃会话」与「整个启动周期」。
CatOS[易错点] 回归磁盘镜像若是全零（MBR 无 55aa 签名），format 阶段 FAT 探测不出卷，shell 看似就绪但内置应用/CE 装不上，后续 ring3 用例全部 "killed=False"。跑套件前先 `xxd -l 512` 或 python 读 MBR 签名核对镜像是否已格式化；坏镜像用同套件已格式化的有效盘 `cp -a` 做种子。
CatOS[易错点] 崩溃路径上的串口断言要在 boot() 传 extra_args `["-serial","file:/tmp/xxx.log"]`；driver 默认不带 -serial，串口面包屑写进了 QEMU 后端但不落盘，事后无法 grep 向量/EIP。断言文件需在 guest 退出后再读（file: 后端缓冲在进程结束时 flush）。
CatOS[易错点] PS/2 鼠标 8042 初始化末尾必须重新 0xAE 使能键盘：开头 0xAD 禁键盘后若不恢复，所有扫描码被 8042 门控，shell 看不到任何键入。IRQ12 与键盘共用 0x60 数据口，读 0x60 前必须先读 status bit5(0x20) 分流 aux/keyboard，否则鼠标包会被当成按键入队、按键被当成鼠标包解析。
CatOS[易错点] 选择反色高亮不出现的根因是脏矩形跟踪器：选择态在绘制时才交换 fg/bg，而 paint() 的跳过比较发生在交换之前，内容未变就被误判为已画而跳过重绘。选择框重绘前必须先把对应格子的 painted_valid 置 0 失效，强制重绘。
CatOS[易错点] 回溯视图内不能用「键入诊断命令」读 sb_view：readline 过滤块规定任意非回溯键都会退出视图并把 sb_view 复位 0，诊断首字符就把视图清掉。测试断言回溯偏移必须走 monitor `xp` 直读内核符号（nm 解析 PE VMA=物理地址），不能回 shell 打命令。
CatOS[易错点] HMP 鼠标诊断行会在屏幕上残留多行，正则取第一个匹配会读到旧基线行；解析必须 findall 取最后一个。read_screen 定位输出行时要排除带提示符 '#' 的命令行（命令行也含标记子串）。
CatOS[易错点] 栈上字符缓冲拼多行文案后必须显式 NUL 终止：`char cand[240]; int n=0; bar_put(...)` 若某分支只填前缀就传给 `con_write_at_utf8`，缓冲尾部残留上一帧栈内容（旧候选串），写出的行会在短前缀后面拖一段旧文本，表现为候选行右侧残影/旧候选编号。每个提前 return 的分支都要补 `cand[n]=0;`；排查时先转储内核镜像行（而非只看 VRAM），镜像有残留即缓冲未收尾，镜像干净才是增量绘制脏格/宽字对问题。
CatOS[易错点] 两行借用状态栏保存/恢复要覆盖两行：新增固定底部两行候选区时，保存槽、恢复循环、后端切换/清屏/改字号/弹屏等失效点都要同步清 `saved2_valid`，与既有单行 `saved_row` 并存；`off()` 先恢复两行再恢复单行，文本模式恢复后 `redraw_all()` 重建 CJK 字槽，否则旧字槽映射会串字。
CatOS[易错点] 分页器不能用「打印完一行就 park」的后置模型：输出正好一屏时末尾会多出一条 More，而块结束时这条 bar 又会停留在屏幕/被 tee 拷进重定向文件。必须用 pending-park 前瞻（写完一行若光标已落到最后一行，只 arm 标记；下一行到来才 park），并且动作键要区分整屏/单行——把 Space 也走游标几何会退化成「按一次只走一行」，表现为 p-5 一路按空格 20 次仍停在 More。
CatOS[易错点] 分页容量不能缓存 `con_rows()`：text 与 gfx24 行数不同，运行期还能 `size normal/compact/large` 改字号，缓存值会让「还剩几行」算错。用 `con_get_cursor()` 的 y 与当次 `con_rows()` 比较，几何驱动天然跟随模式切换。
CatOS[易错点] 分页器接管 `ls`/`help`/`cat`/`tree` 后，凡是「读最后一屏断言尾部」的旧套件都会假失败，症状还带级联：残留的 More 条会吞掉后续按键，状态机错位后连 prompt 都读不到。所有读屏套件统一加 `drain()`（循环见 `-- more` 就发 `spc`），再判定。
CatOS[易错点] 种子镜像 `kernel_v25/catos_disk.img` 会被 `build.sh` 重新生成，测试里对「磁盘上原有目录内容」的期望会随之消失（badname 套件原期望 6 entries/4 visible，重建后只剩注入的 4/2）。注入式测试必须自己在镜像里造齐断言所需的正常项，不要依赖种子盘的历史内容。
CatOS[易错点] 每跑一次 QEMU 套件都会在 `/tmp` 留一份 `catos_qemu_stage_<pid>/` 镜像拷贝（约 65 MB），几百次下来能堆到 3~5 GB 把根盘挤满，表现为后续套件莫名超时/ConnectionReset。`qemu_driver._stage_image()` 里必须 `atexit` 递归删整个 staging 目录，而不是只删文件。
CatOS[易错点] Windows 侧压缩大于 1GB 的目录不要用 `C:\Windows\System32\tar.exe -czf`：本机实测 1.23 GB 的 trash 目录产出 tar.gz 只写完 262 MB 就报 `Truncated input file`，解压时在第 200 项中断（中文/长路径混合下更明显）。改用 `Compress-Archive` 出 zip（1128 条目可正常读取，1.23 GB→313 MB），压缩率差一点但可靠。另外仓库内受控文件 `nul`、以及带 `&&`/`:` 的垃圾目录，`Remove-Item` 会静默失败，必须用 `\\?\` 前缀的扩展路径才删得掉。

## 1. CatOS 现有控制台 / 图形层盘点（源码已核实）

**前端（`src/render.c` + `include/render.h`，模式无关契约）**

- 逻辑单元格网格：`cells[CON_MAX_ROWS][CON_MAX_COLS]`；`tmp_cells` 临时缓冲；v2.25 脏追踪 `painted[]`（只提交实际画出的格，`CON_INFO_CELLS_DRAWN/SKIPPED` 可查）。
- 整屏备份：`ui_backup[]`；瞬态状态栏 `saved_row[]` / `con_status_bar()` / `con_status_bar_at()` 保存并逐行恢复原文。
- scrollback：`sb[CON_SB_ROWS=96]` 环形存档 + `sb_live[]` 全量副本；`con_scrollback(delta)` 只画存档窗、不改活网格。
- 定点写 API：`con_putc_at()` / `con_write_at()` / `con_write_at_utf8()`（UTF-8 感知，汉字占两列）；光标 `con_get/set_cursor()`；样式 `con_set_style/fg/attrs`，CLUT 索引或 `0x00RRGGBB`；256 项调色板可写 `con_set_palette()`。
- 尺寸/模式内省：`con_cols()` / `con_rows()` / `con_info(what)` / `con_backend_name()`。

**后端（`src/be_*.c`，全部画文本格）**

- `be_text.c`：VGA text 03h，80×25，16 色，CJK 走动态 8×16 字体槽。
- `be_gfx.c`：Mode 13h，40×12，8bpp 索引。
- `be_vbe.c`：VBE LFB 800×600×32，100×37 真彩。
- `be_vbe24.c`：VBE LFB 800×600×24，100×37；另导出内核侧 `gfx24_*` 绘图 API（`gfx24.h`：`clear/pixel/rect/blit`），帧缓冲 supervisor-only，用户程序拿不到地址。

**键盘抽象（`src/keyboard.c` + `include/keyboard.h`）**

- 阻塞 `kb_getkey()` / 非阻塞 `kb_peek()`；CE ABI slot 64 `pollkey()`。
- 功能键枚举 >0xFF：`KB_UP/DOWN/LEFT/RIGHT/HOME/END/DEL/INS/PGUP/PGDN/F1..F12`；Ctrl+方向有独立码，修饰状态不泄漏给调用方。
- 缺口：无修饰键（Ctrl/Alt/Shift）状态随事件上报；无事件类型/结构；无鼠标、无 Resize 事件。

**字体（`src/render_font.c`）**

- `font8x8_basic`：ASCII 0x20–0x7E，8×8 点阵；`hz_font`：GB2312 16×16 汉字，GNU Unifont 派生（`font_hz.inc`，`tools/gen_hz_font.py` 生成）；按码点二分查表。
- 纯位图：无轮廓、无缩放、无抗锯齿；字符集受位图表覆盖限制。

**现有 TUI 雏形**

- `extapp/hexedit_port.c`：自定义键码表（含 `KB_CTRL(c)` 组合键），十六进制查看器式布局。
- shell 行编辑器：nano 风格，光标位置以 `con_get_cursor()` 为锚做原地重绘。
- `cmd_fortune`：ASCII `-`/`|` 引文框（按显示宽度对齐 CJK）；`extapp/spinner.c`：后台动画轮询范例；拼音 IME 状态栏。

## 2. 对标组件模型

### 2.1 ncurses（经典 C TUI 库）

- **双层屏 diff**：`stdscr`（虚拟逻辑屏）与 `curscr`（终端实屏）分离；`refresh()` 比对两屏，只把变化的字符与属性写到终端，减少输出量。
- **窗口与面板**：`WINDOW` 独立缓冲 + 起点坐标 + 裁剪矩形；`derwin` 相对父窗口嵌套；panels 库在窗口之上再加 z 序栈，支持遮挡、重排、置顶。
- **按键解析**：`keypad()` 打开终端功能键转义序列解析，方向键/功能键映射为 `KEY_*` 常量；`raw()`/`cbreak()` 关闭行缓冲与回显。
- **备用屏幕**：经 terminfo `smcup`/`rmcup` 能力进场切备用屏、退场恢复原屏，TUI 内容不污染 scrollback。
- **边框与样式**：`box()`/`border()` 用 ACS 制表符画线；属性 `A_BOLD/A_REVERSE/A_UNDERLINE`；颜色对（pair number → fg/bg）。
- **鼠标**：`mousemask()` 订阅事件，`getmouse()` 取坐标与按键。
- **保留模式**：控件状态驻留窗口缓冲，更新时做局部脏矩形重绘。

### 2.2 Ratatui / tui-rs（即时模式 Rust TUI）

- **即时模式 + 中间缓冲**：每帧应用把全部 widget 重绘进中间 `Frame` 缓冲；库做 diff 后只向后端写变化；不保留控件树状态（与 ncurses 保留模式相对）。
- **约束式布局**：`Layout` 水平/垂直分栏，支持比例、固定长度、最小约束；嵌套布局递归产出每个 widget 的 `Area` 矩形。
- **Widget 抽象**：`render(frame, area)` 接口；内置 List/Table/Paragraph/Block/Gauge/Sparkline/Chart 等；`Block` 带标题与边框。
- **事件外置**：库不内含事件处理，由后端（crossterm/termion）`event::read()` 取 Key/Mouse/Resize 事件，应用自管状态机。
- **进出场**：`init()` 进 alternate screen + raw mode，panic hook 保证 `restore()` 执行；`restore()` 回退原终端状态。
- **文本模型**：`Text` = 多行 `Line`；`Line` = 多 `Span`；`Span` = 字符串 + `Style`（fg/bg/修饰）。
- **Resize**：事件驱动重布局，界面自适应终端尺寸。

### 2.3 notcurses（平面叠加现代 TUI）

- **ncplane**：可任意大小、位置、z 序的平面；标准平面铺满物理屏；多平面在每个单元格上按 z 序相交，自上而下取第一个非透明单元。
- **行级 damage map**：每平面每行一个布尔脏标记；渲染分两阶段——先生成场景（确定每物理格的字形簇、颜色、样式），再 blit 合成 UTF-8 序列与转义码输出。
- **颜色与字形**：原生 24-bit RGB，索引色终端量化；扩展字形簇（EGC）处理组合字符；支持透明度与 alpha 混合。

### 2.4 DOS EDIT / QBasic IDE（字符界面经典范式）

- **结构**：顶部菜单栏（File/Edit/View/Help）+ 下拉弹出层；中央编辑区；底部快捷键提示行 / 状态行（行列、编码）。
- **modeless**：无 vim 式模式切换；菜单快捷键 + 鼠标（有驱动时）；双 pane 水平分屏；2.0 支持最多 9 个文档 MDI。
- **字符画框**：菜单条、边框、滚动条全部用制表符/字符排布；无独立 widget 工具箱，界面是一次性字符布局。
- **约束**：颜色方案可配；受常规内存限制，编辑缓冲小。

## 3. 可借鉴的 CatOS 设计要点

### 3.1 双缓冲与面板/窗口抽象

- 现状已有 `cells` 逻辑格 + `painted` 脏追踪 + `tmp_cells`，定点写 API 齐备。
- **借鉴**：在前端之上加 panel/window 层——每面板独立格缓冲（或矩形区域 + 坐标 + z 序 + 裁剪标志）；合成阶段按 z 序把面板格 blit 进 `cells`，透明格不覆盖；再走现有 painted diff 提交后端。
- 落地次序：第一步只做全屏单面板 TUI；多面板栈、遮挡裁剪后置。现有 `ui_backup` 与状态栏逐行保存恢复是同类语义先例，可复用。

### 3.2 备用屏幕（alternate screen）语义

- 现状已有 `ui_backup[]` 整屏备份与状态栏恢复机制，但无"TUI 进场/退场"的统一约定。
- **借鉴**：定义进出场契约——进场备份整屏、清屏；退场恢复 `cells` 与光标位置；TUI 内容不进 scrollback（或入独立存档区）。CE ABI 以 append-only 槽位加 enter/exit TUI 接口，老二进制不受影响。

### 3.3 box-drawing 原语

- 现状：只有 ASCII `-`/`|`（fortune 框）；控制台 API 无 box 原语；Unicode 制表符（U+2500 系列）是否在位图表内需核对。
- **借鉴**：前端提供 `box(rect, style, single/double/rounded)` 原语；文本后端走制表符字形，gfx24 后端走 `gfx24_rect/pixel` 画线；`Block` 组件带标题区（对齐 ncurses box 与 Ratatui Block）。
- 前置：把制表符码点补进位图表（宿主工具烤入，复刻 `font_hz.inc` 生成流程）。

### 3.4 焦点管理与事件路由

- 现状：无控件概念，键盘事件由 shell/应用直读 `pollkey`/`getch`。
- **借鉴**：焦点栈 + 当前焦点控件；Tab/Shift-Tab 循环切换；焦点高亮（反色或强调边框）；事件路由——按键先送焦点控件，未消费再冒泡到容器/应用；模态弹出层独占焦点。
- 数据结构：控件矩形 + 焦点标记 + 事件回调表；CE 用户态可用函数指针表表达。

### 3.5 按键抽象增强

- 已有：>0xFF 功能键枚举、Ctrl+方向独立码、非阻塞/阻塞双读口。
- **缺口**：修饰键状态不随事件暴露；无统一事件结构；无 Resize/鼠标事件；未来接 USB/串口终端需解析转义序列。
- **借鉴**：对齐 ncurses keypad 与 crossterm Event 模型——统一 `KeyEvent { keycode, mods, ch }`；补 Resize 事件；修饰键状态在键盘层跟踪并随事件上报。

### 3.6 事件循环与渲染模式选择

- **建议选即时模式（Ratatui 式）**：每帧 = 读事件队列 → 更新应用状态 → 全量绘制到面板缓冲 → diff 提交。理由：无保留模式控件树的同步负担，契合 32 位小内存与现有双缓冲；ncurses 式多窗口脏矩形作为面板层优化后置。
- 循环原语：现有 `delay()` 睡眠 + `pollkey` 轮询；可演进为事件等待原语（与差距分析 §2.3 守护进程原语共用一套内核机制）。

### 3.7 约束式布局

- 已有 `con_cols()`/`con_rows()`/`con_info()` 尺寸查询。
- **借鉴**：Layout 分栏描述（水平/垂直、比例/固定/最小宽高），递归切出 Area 矩形；控件不自行计算绝对坐标；Resize 事件触发重布局。

### 3.8 文本样式模型

- 已有 `CON_ATTR_BOLD/DIM/ITALIC/UNDERLINE/BLINK/INVERSE/STRIKE/HIDDEN` 位；fg/bg 走 CLUT 索引或 RGB；256 调色板可写。
- **借鉴**：Span/Line/Text 分层（Ratatui）；样式随文本片段走，而非全局设一次写一段；颜色对映射纳入 CLUT。

### 3.9 鼠标（后续项）

- 现状：未发现鼠标驱动或鼠标事件通道。
- **借鉴**：PS/2 鼠标中断 → 事件队列（坐标 + 按键 + 滚轮）→ 控件命中测试（矩形包含）；先支持左键点击切换焦点与按钮，拖动/滚动后置。

## 4. TTF/OTF 轮廓字体渲染铺路

**现位图字体限制**

- 8×8 ASCII + 16×16 GB2312 固定点阵；无缩放、无抗锯齿；字符集受 Unifont 表覆盖；`render_font_glyph()`/`render_font_hz()` 按码点查表返回位图指针。

**轮廓字体管线要点**

1. 容器解析：TTF `glyf`（二次贝塞尔）/ OTF CFF（三次曲线）轮廓表；
2. 光栅化：扫描线填充或 SDF 距离场；hinting 网格对齐；
3. 位图缓存：码点 × 字号 × 样式 的字形缓存；
4. 排版：字距、行距、折行、双宽列宽处理。

**CatOS 约束**：32 位小内存、无 libc、内核/用户态分离、帧缓冲 supervisor-only（绘图经 syscall 进 `gfx24_*`）。

**分阶段路线**

- **阶段 1（今夜可做工具链储备）**：宿主侧预光栅化——把所需码点按目标字号/粗细烤成位图表，复刻 `tools/gen_hz_font.py` 流程；运行时只查表。先补 TTF 选字与位图导出工具链设计文档。
- **阶段 2**：运行时精简位图缓存（按字号缓存已光栅化字形，LRU 淘汰）；像素级字形经 `gfx24_blit` + alpha 混合上屏。
- **阶段 3（设计级）**：精简轮廓光栅器（仅 glyf 二次曲线、不全量 hinting）或 SDF 字形贴图；内存预算需先解 #128 第二段 RAM 枚举与 4G 档限制。

**与现有模型衔接**

- 文本前端单元格模型（8×16 逻辑格）与像素级字形的映射规则；CJK 双宽列宽（`disp_width` 已有先例）；反色/下划线等修饰在位图上的叠加方式。

# 开机耗时打点（v2.57 / 2026-11-19 复测）

数据来自内核 `btime_mark()` 串口面包屑（`[btime]`），采集方式：

```sh
/home/user/bin/qemu-system-i386 -m 256 -no-reboot -net none \
  -cdrom kernel_v25/catos.iso -boot order=d -display none -monitor none \
  -serial file:/tmp/btime.log
grep -o "\[btime\].*" /tmp/btime.log
```

## 实测阶段耗时（本机 QEMU 6.2，-m 256，无磁盘）

| 标记 | 阶段 | 累计 ms | 相对上一标记 |
|---|---|---|---|
| K0 | `kernel_main` 进入 | 0 | — |
| K1 | vga + 键盘初始化 | 0 | 0 |
| K2 | 分页开启 | 0 | 0 |
| K3 | intr/tasks + `sti` | 10 | 10 |
| K4 | 内存 + CPU 校准 | 110 | 100 ← **最大单步** |
| K5 | `snd_init` | 110 | 0 |
| K6 | `usb_start` | 110 | 0 |
| K7 | `net_init`（无网卡立即返回） | 110 | 0 |
| K7b | `mouse_init`（8042 aux 初始化） | 110 | 0 |
| S0 | `shell_run` 进入 | 110 | 0 |
| F0 | `fs_init` 进入 | 110 | 0 |
| A0→A13 | ATA 4 槽探测（无盘，逐槽 0ms） | 110 | 0 |
| F2 | FAT 卷探测完成 | 110 | 0 |
| S1 | `fs_init` 结束 | 110 | 0 |
| S2 | `lang_init` | 110 | 0 |
| S3 | `env_init`（读 `/etc/env`） | 110 | 0 |
| S4 | `ce_init`（应用清单） | 120 | 10 |
| S5 | user/acl/session | 120 | 0 |
| S9 | **shell 提示符就绪** | 120 | 0 |

## 结论与热点判断

- 冷启动到提示符 **≤120 ms**（-m 256，无磁盘、无网卡）。这个数量级没有做优化的必要。
- 唯一超过 10 ms 的阶段是 **K4「内存 + CPU 校准」100 ms**：`cpu_calibrate()` 用 PIT 做
  busy-wait 测 cycles/秒，属**有意等待**，不是浪费——它决定了 TSC 超时（蓝屏 30s、
  watchdog 倒计时）的换算精度。把校准窗口从 100 ms 缩到 20 ms 会让 MHz 估算误差放大
  到 ±5%，蓝屏超时误差 ±1.5 s，得不偿失；本批**不改**。
- 有盘场景的分层（ATA 探测 → FAT → part_scan）在无盘测试里全为 0 ms；真机带盘时
  A0→F3 段的耗时取决于盘速与簇数，属于 I/O 侧，本轮不做专项优化。
- `mouse_init`（新增，8042 aux 协商）**未增加可测耗时**（K7b 与 K7 同毫秒）。
- `boot_apply_videomode()`（v2.56 新增）在 S3 后、S4 前执行；进入 VBE24 后端本身由
  BIOS 提供模式，实测未引入可测延迟（S3 110ms → S4 120ms 的 10 ms 主要是 `ce_init`）。

后续若要再压，可优先看「有盘 + 网络」组合场景的 ATA/net 初始化重试路径（`ata_scan`
在 4 个空槽上各打一次 400ns 的 status 轮询，属于固定成本）。当前无优化项落地，结论：
**保持现状，热点为有意等待**。

# CatOS 回归端口分配与基线豁免登记

本文件记录两件事：①每个回归套件**固定**的 monitor 端口；②与代码无关、长期存在的
**基线豁免条目**（终验判绿时按本表扣除）。

## 1. 固定端口分配（禁止动态抢端口）

套件的 monitor 端口必须固定。并发 clone / 并发子代理在本机同时跑时，一旦某个套件
"抢"到别人在用的端口，症状不是端口冲突报错，而是伪装成代码故障：

- `HMP empty reply`、`screendump produced no file`（size 类）
- `FAIL: prompt never appeared`（qemu_driver 类）
- `ConnectionReset`（长尾套件）
- 个别 ACL/权限步骤莫名 FAIL（组读取等）

| 套件 | 端口 | 备注 |
|---|---|---|
| qemu | 4707 | |
| shell_guess | 4450 | 不接 `--port` 也能跑，但显式传入保持一致 |

# CatOS 异常 / 崩溃分级表（panic tiers）

> 版本：v2.59-crashscreen 增量（基于合流主仓 cbf77c3）
> 口径：可靠性优先。本表核对的是**当前代码实际分级**，与 `intr.c` 异常分发、
> `diag.c` 的 `panic()`、`bsod.c` 崩溃屏一一对应；若后续改动分级，必须同步本表。

## 1. 分发入口

异常统一进入 `isr_exception(int_frame_t *f)`（`kernel_v25/src/intr.c`）。
分发依据两个事实：**故障发生的特权级**（`f->cs & 3`）与**异常向量**（`f->intno`）。

- 入口先写 COM1 串口 breadcrumb（`serial_log.c`，轮询 LSR.THRE，超时丢弃不阻塞）。
- P0-2 护栏：若 `g_in_panic != 0`（已在崩溃屏），直接 `cli; hlt` 死循环，**不再递归进蓝屏**。

## 2. 三级分级（现行实现）

| 级别 | 触发条件（向量 / 特权级） | 现行行为 | 代码位置 | 是否冻结整机 |
|---|---|---|---|---|
| **L0 用户态异常（隔离级）** | ring3（`f->cs & 3 == 3`）的任何致命异常：`#PF(14)` / `#GP(13)` / `#UD(6)` / `#DE(0)` / `#DF(8)` 等 | ① `#PF` 先交 `task_page_fault()` 惰性映射；可恢复则重试指令，**不杀任务**；② 不可恢复则 `fault_record()` 记录最后一次故障，`task_die_fault()` 打印一行简短错误（任务名 / tid / 故障类型 / EIP / CR2），置僵尸、退出码 `-1`、重调度。**不进全屏蓝屏**，shell 与其他任务继续运行。 | `intr.c` `isr_exception()` ring3 分支；`task.c` `task_die_fault()`；`vma.c` `task_page_fault()` | 否，只杀出错任务 |
| **L1 可恢复内核错误（任务级降级）** | ring0 内核路径中**可定位到单个任务**的错误（如用户指针校验失败、VMA 映射失败等受控返回路径） | 打印简短错误行，终止相关任务（僵尸 + 回收 + 唤醒等待方），不冻结整机；内核其余部分继续调度。 | `vma.c` `validate_uaddr()` / `task_page_fault()` 返回 `-14`；`task.c` 退出/回收管线 | 否，终止相关任务 |
| **L2 致命内核错误（全屏蓝屏）** | ring0（`f->cs & 3 == 0`）的致命异常：`#DE(0)`、`#UD(6)`、`#DF(8)`、`#GP(13)`、`#PF(14)`、`#NM(7)`、`#SS(12)`、`#TS(10)`、`#NP(11)`，以及机器检查类（18/19）；另有手动 `panic(msg)` 与 shell `bsod` 命令 | `fault_record()` 记录 → COM1 breadcrumb → `bsod_enter()` 全屏崩溃屏（摘要字段 + 单键诊断页），按缓存的 `/etc/panicmode` 执行 reboot / halt / wait。 | `intr.c` `isr_exception()` ring0 分支；`diag.c` `panic()`；`bsod.c` `bsod_enter()` | 是，整机停机/重启 |

### 2.1 向量到全屏的归属核对（任务书口径对照）

| 任务书点名的全屏向量 | 编号 | 现行是否进全屏（ring0） | 备注 |
|---|---|---|---|
| `#PF` 页错误 | 14 | 是 | ring3 先惰性映射，不可恢复才杀任务；ring0 直接 L2 |
| `#GP` 一般保护 | 13 | 是 | ring3 杀任务；ring0 直接 L2 |
| `#UD` 非法指令 | 6 | 是 | ring3 杀任务；ring0 直接 L2 |
| 双重故障 `#DF` | 8 | 是 | ring0 进入；ring3 双重故障本身极少，走 L0 杀任务分支 |
| 看门狗（watchdog） | — | **deferred** | 当前内核未实现硬件/软件看门狗（`grep watchdog` 无命中）；接口预留：看门狗超时未来应直接走 L2 全屏路径，与 ring0 异常同一入口。 |

其余向量（`#DE 0`、`#BP 3`、`#OF 4`、`#BR 5`、`#NM 7`、`#TS 10`、`#NP 11`、`#SS 12`、`#MF 16`、`#AC 17`、`#MC 18`、`#XM 19`）：
ring3 一律 L0 杀任务；ring0 一律 L2 全屏。

## 3. 与任务书分级口径的差异 / 待办

1. **「可恢复内核错误打印简短错误并终止相关任务」**：现行内核没有独立的「可恢复 ring0 错误」类别——ring0 一旦取到致命异常即 L2 全屏。L1 级目前由**受控返回码**（非异常）承载：用户态指针/VMA 校验失败在 ring0 syscall 内返回负错误，相关 ring3 任务由退出管线终止，不触发异常分发。这与任务书「可恢复内核错误终止相关任务不冻结整机」的**效果一致**，触发方式是返回码而非异常。
2. **看门狗**：未实现，登记 deferred（见问题清单续号条目）。
3. **退出码**：ring3 被杀任务的 `exit_code = -1`（`task_die_fault`），简短消息走控制台一行；退出码细化（按向量区分）留后续。

## 4. 崩溃屏（L2）输出契约

- **双输出**：关键信息先写 COM1（0x3F8，轮询 `LSR.THRE`，守卫超时丢弃字节不阻塞），再写 VGA 文本缓冲；任一路失败不影响另一路。
- **自包含**：蓝屏路径不调用 `kmalloc`、不持阻塞锁、不 `sleep`、不开 FS、不进 IME、不做 UTF-8 框线绘制。FS 调用只出现在 `bsod_init()`（启动期一次性缓存 `/etc/panicmode`），崩溃路径本身不开文件；`con_force_text()` 是内核态应急切文本后端，不经过 shell/FS。
- **字模依赖证据（P0-4 核对）**：内核 CJK 位图来自编译期提交的常量表 `src/font_hz.inc`（`render_font.c` 顶部 `#include "font_hz.inc"` → 静态 `hz_font[]`，`render_font_hz()` 按 codepoint 二分查找），**不是**外部字体文件、不依赖运行时字体加载；ASCII 位图来自同文件内静态 `font8x8_basic[95][8]`。但该表是 GB2312 子集，缺部分常用汉字；崩溃屏又禁止触字体加载器，故标题/提示行按口径降级 ASCII（详见问题清单 #202）。崩溃屏本身不绘制任何 UTF-8 框线字符（`─│┌┐└┘`），全部为 ASCII 标点。
- **护栏**：`g_in_panic` 置位后，任何再次进入的致命异常 / triple fault 直接 `cli; hlt`；panic 深度计数上限 `BSOD_PANIC_DEPTH_MAX = 2`，超限 halt。
- **默认摘要页**：异常类型 + 十六进制向量、CPU 号、FATAL、RECOVER、简短原因、ERR、EIP、CR2（仅页错误）、RSP、EFLAGS、栈顶 3~5 帧、操作提示行、自动重启倒计时；默认**不显示**全量寄存器 / 日志 / 用户输入 / 剪贴板。

### 1. [严重] spawn+wait 后内核 GP 崩溃 —— **已修复**
- 根因 1：**task_spawn_ce 未初始化 t->out_pipe/in_pipe/out_file/out_append**（tasks[] 静态复用残留）→ pipe_task_cleanup 误操作。已加显式初始化（task.c:1333-1340）。

- 修复：① `isr_syscall` 入口 `t->resume_frame = 0`（新 trap 后旧帧失效）；② `schedule_to` park 分支 `prev->resume_frame = 0`（prev 走 cpu_switch_to 协程恢复）。

- 复测：test_ab 管道自测 + shell gen|sink 均通过。

### 3. [中] fat_flush 每次写 8MB（性能）—— **已修复（b31，随 #48 深修一并闭合）**

## 环境/工程易错点（已记录到 history/experience 候选）

1. **云端 Ubuntu 每轮重置**：qemu-system-i386/qemu-img 会消失，需 `sudo apt-get update && sudo apt-get install -y qemu-system-x86 qemu-utils`；/tmp/disk-raw.img 也会清掉，需重建 4G 稀疏盘 + QEMU 内 `format`（**format 需要二次确认 y**）。
2. **inject 8.3 名格式**：内核 FAT 用标准 8.3（名 8 字符+扩展 3 字符，**无点**，如 `TEST_AB CE `），带点名（`TEST_AB.CE `）内核 fs_resolve_file 找不到（err -2）。inject_any.py 已修。
3. **inject 顺序坑**：删除旧目录项（0xE5）后若先注入再恢复 `.`/`..`，新文件会写到 `.`/`..` 槽被覆盖。先恢复目录项再注入。
4. **pkill -f 匹配 bash 自身**（heredoc 命令行含 qemu 字符串会自杀）；用 `pkill -x qemu-system-i386`。
5. **Linux GNU 构建链**：CFLAGS 加 `-fleading-underscore`（cpu.s/boot.s 用 `_` 前缀符号）、boot.s `call _kernel_main`、build_ce.sh `cd "$CEBASE"` + nm 探测 entry 符号 + python 算 16 进制、task.c 无 libc（memset 手写循环、前向声明）。

### 3.1 🔴 高风险技术债

#### TD-01: 缺页处理中跳过 task_cleanup

**位置**: `src/vma.c:task_page_fault()`

**风险**:

```c
// 方案 A: 将 task_cleanup 移到 intr.c (推荐)

// 方案 C: P1 重构时引入轻量级 cleanup 钩子
```

**影响范围**: 所有触发缺页的程序  
**修复优先级**: P1 第一项  
**预计工时**: 4h

## 四、经验教训总结

### 4.1 架构设计经验

#### ✅ 做得好的

1. **VMA 优先于硬编码**
   - 虽然 CE 兼容要求保留固定偏移，但 VMA 框架为未来 ELF/PIE 铺平道路
   - 双轨制（CE legacy + ELF modern）是合理的过渡策略

2. **Append-only ABI**
   - `catos_api_t` 末尾追加 `brk()` 字段
   - 旧二进制看到 NULL，安全 noop
   - **关键原则**：新 syscall 必须追加到末尾，绝不重新编号

3. **防御性校验**
   - 所有用户指针经过 `validate_uaddr()` 后才使用
   - 不再信任传入地址，消除 UAF/越界风险

#### ❌ 需要改进的

1. **环形依赖未提前规划**
   - vma.c 需要调用 task_cleanup()，但 task.c 不能 include vma.c
   - **教训**：内核模块划分时应提前设计依赖方向（leaf → root）

2. **工具链环境问题**
   - MinGW gcc.exe 是 WOW64 进程，DLL 依赖链断裂
   - **教训**：文档化构建环境要求，提供 Docker/VM 镜像

3. **测试覆盖不足**
   - P0 完成后缺少自动化回归测试
   - **教训**：每个 P 阶段应包含 CE 测试套件验证

### 4.1 架构设计经验

#### ✅ 做得好的

# CatOS P0 Spawn 执行权限检查（2026-11-11）

> 对应 ROADMAP P1 / 问题清单 #96：`task_spawn_ce` 补上 `PERM_EXEC` 检查。

## 背景

ROADMAP P1 第一项待办：`spawn 执行权限检查`。v2.13 已引入多用户 + ACL，但 `task_spawn_ce()` 只校验路径存在与镜像大小，**从不查 `PERM_EXEC`**。这意味着 uid=100 可以 `run /root/malicious.ce`——写保护只防"改文件"而不防"跑文件"。

## 改动

### kernel_v25/src/task.c (`task_spawn_ce` 入口之后)

在 `fs_resolve_file` 成功、`size >= 4` 之后加入两段检查：

1. **快速拒绝无 x 的文件**：`acl_lookup(path, &fuid, &fgid, &fmode)` 找到 ACL 项且 mode 不含 `0o111` → 直接返 -2（不引入新错误码，保持错误语义一致）。
2. **按 owner/group/other 语义重验**：取调用者 uid 对应的 gid，调已有 `fs_perm_check(path, uid, gid, PERM_EXEC)`；root 直通，其他按 12 位 Unix 模式算。

```c
    /* v2.15: enforce PERM_EXEC on the path before loading. */
    {
        int fuid, fgid, fmode = 0;
        if (acl_lookup(path, &fuid, &fgid, &fmode) == 0 &&
            !(fmode & 0o111)) {
            return -2;   /* no execute bit at all */
        }
        user_rec_t *u = user_by_uid(uid);
        if (fs_perm_check(path, uid, u ? u->gid : 0, PERM_EXEC) != 0)
            return -13;  /* EACCES */
    }
```

### 1.2 VMA 类型与布局

```c
typedef struct vma {
    uint32_t  start;      /* 起始地址（包含）*/
    uint32_t  end;        /* 结束地址（不包含）*/
    uint8_t   kind;       /* VMA_IMAGE / VMA_VSYSCALL / VMA_ANON / VMA_MMAP */
    uint8_t   writable;   /* 0=read-only, 1=read-write */
    uint8_t   reserved;
    uint8_t   ref_count;  /* 供未来 COW 使用 */
    vma_t    *next;       /* 按地址升序排列的链表 */
} vma_t;
```

**CE 任务 VMA 布局**（兼容 legacy 固定偏移）：
```
0x02000000 ── VMA_IMAGE (可读，含代码 + 数据)
0x02080000 ── VMA_VSYSCALL (只读，syscall thunks)
0x02100000 ── VMA_ANON (可写，堆，懒初始化)
0x021F0000 ── VMA_ANON (可写，栈，spawn 时全映射)
```

### 1.3 新增系统调用

| 系统调用 | 编号 | 功能 |
|---|---|---|
| `SYS_BRK` | 48 | `brk(0)` 查询当前 heap break；`brk(addr)` 动态扩展堆 |
| `SYS_PAGE_FAULT` | (INT 0x0E) | 缺页中断，支持懒映射 + guard page |

### 1.4 用户指针校验框架

```c
int validate_uaddr(task_t *t, uint32_t addr, uint32_t len);
int copy_to_user(task_t *t, void *dst, const void *src, uint32_t len);
int copy_from_user(task_t *t, void *dst, const void *src, uint32_t len);
int uaddr_in_vma(task_t *t, uint32_t addr);
```

**工作原理**：
1. 检查指针落在任务的 VMA 列表中
2. 逐页遍历，对未映射页面触发懒分配（仅可写 VMA）
3. 遇到 guard page 或未映射区域 → 返回 EFAULT (-14)

### 1.2 VMA 类型与布局

```c
typedef struct vma {
    uint32_t  start;      /* 起始地址（包含）*/
    uint32_t  end;        /* 结束地址（不包含）*/
    uint8_t   kind;       /* VMA_IMAGE / VMA_VSYSCALL / VMA_ANON / VMA_MMAP */
    uint8_t   writable;   /* 0=read-only, 1=read-write */
    uint8_t   reserved;
    uint8_t   ref_count;  /* 供未来 COW 使用 */
    vma_t    *next;       /* 按地址升序排列的链表 */
} vma_t;
```

**CE 任务 VMA 布局**（兼容 legacy 固定偏移）：
```
0x02000000 ── VMA_IMAGE (可读，含代码 + 数据)
0x02080000 ── VMA_VSYSCALL (只读，syscall thunks)
0x02100000 ── VMA_ANON (可写，堆，懒初始化)
0x021F0000 ── VMA_ANON (可写，栈，spawn 时全映射)
```

### 1.3 新增系统调用

| 系统调用 | 编号 | 功能 |
|---|---|---|
| `SYS_BRK` | 48 | `brk(0)` 查询当前 heap break；`brk(addr)` 动态扩展堆 |
| `SYS_PAGE_FAULT` | (INT 0x0E) | 缺页中断，支持懒映射 + guard page |

### 1.4 用户指针校验框架

```c
int validate_uaddr(task_t *t, uint32_t addr, uint32_t len);
int copy_to_user(task_t *t, void *dst, const void *src, uint32_t len);
int copy_from_user(task_t *t, void *dst, const void *src, uint32_t len);
int uaddr_in_vma(task_t *t, uint32_t addr);
```

**工作原理**：
1. 检查指针落在任务的 VMA 列表中
2. 逐页遍历，对未映射页面触发懒分配（仅可写 VMA）
3. 遇到 guard page 或未映射区域 → 返回 EFAULT (-14)
