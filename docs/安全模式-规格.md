# SAK 安全模式规格（Secure Attention Key）

> 对应主线 `feat/gui-blocks`；实现见 `kernel_v25/src/gui/sak.c`、`src/keyboard.c`、
> `src/shell.c`、`src/task.c`、`src/gui/input.c`、`src/gui/chrome.c`。
> 自检子命令：`gui sak`（探针 `tests/gui_probe.py sak`）。

## 1. 触发条件与键位表

| 键位 | 扫描码 | 说明 |
|---|---|---|
| 左 Ctrl | `0x1D` make / `0x9D` break | 键盘最底层维护 `ctrl` 状态 |
| 右 Ctrl | `E0 1D` / `E0 9D` | 同上 |
| 左 Alt | `0x38` make / `0xB8` break | 维护 `alt` 状态 |
| 右 Alt | `E0 38` / `E0 B8` | 同上 |
| Del | `0x53` | 与 Ctrl、Alt 同时按下 → 置 `sak_request` |

- 组合键在键盘解码最底层（`src/keyboard.c`）识别：`sc == 0x53 && ctrl && alt`
  时置 `sak_flag` 并 `continue`；Ctrl、Alt、Del 三键**全部吞掉，不下发**。
  任何应用、组件、输入框、CE 进程都拿不到这三键的事件。
- `sak_requested()` 消费并清除标志；`sak_request_clear()` 仅清标志。

## 2. 抢占时延

- 置位后**下一帧**进入安全模式。协作式调度下，GUI 空闲节拍
  （`gui_idle_step()` 首行 `gui_sak_poll()`）与 shell 主循环都在 yield 点轮询
  `sak_requested()`；`net_poll` 等让出点同样可被响应。
- 时延口径：**≤ 2 帧**（置位帧 → 下一空闲节拍进入）。

## 3. 面板块树（pid=0 系统覆盖层）

安全模式是系统侧块树，挂载在 `LAYER_OVERLAY`（层号 4000），归属 pid=0：

1. **全屏纯色遮罩**：`BLK_RECT`，全出血压暗；不引入 alpha / 半透明通道。
2. **中央面板**：`BLK_COLUMN`，内含
   - 标题：`安全模式`；
   - 四条动作行（`z` 编号即动作号）：
     | z | 动作 | 行为 |
     |---|---|---|
     | 1 | 返回桌面 | 关闭 SAK 覆盖层，回到原桌面（不退出 GUI） |
     | 2 | 块列表 | 打点 `GUI:sak blocks=<n>`，面板保持打开 |
     | 3 | 锁定 | 进入 `SAK_LOCKED` 态，打点 `GUI:sak lock` |
     | 4 | 重新启动 | warm reboot（`outb(0x64, 0xFE)` → `hlt`），打点 `GUI:sak reboot` |

### 3.1 输入独占与 inert

- 面板出现后调用 `gui_modal_inert(sak_panel)`：所有层号低于 `LAYER_OVERLAY`
  的既有应用块标记 `inert`，命中测试跳过；鼠标 / 键盘事件只由系统面板消费。
- `gui_sak_active()` 在面板 / 锁定态均返回 1；CE 事件轮询双保险过滤（见 §7）。

### 3.2 退出

- 按 `Esc` 或点「返回桌面」关闭覆盖层；`gui_sak_esc()` 先于菜单 / 退出 GUI
  路径消费 Esc。
- 关闭走两阶段销毁：`b_remove` 摘树标 leaving，两轮 `gui_presence_sweep()`
  归还句柄，退出后 `leaked=0`。

## 4. 锁定语义

- 锁定态（`SAK_LOCKED`）下再次按 SAK，弹出口令校验（`kb_readline_masked`
  掩码输入）；复用现有 `/etc/passwd` 口令体系：`user_by_name("root")` +
  `user_check_pw()`。
- 校验通过：打点 `GUI:sak unlock`，回到面板态；失败：打点
  `GUI:sak deny_app pid=<tid>`，保持锁定。
- 锁定期间下层应用仍全部 inert，事件继续被 SAK 过滤。

## 5. TEXT 模式覆盖

文本控制台同样响应 SAK（不画 GUI）：

- shell 主循环每轮先查 `sak_requested()`；命中则打印安全提示，给出两动作：
  - `l` 锁定：进入阻塞锁定，等待第二次 SAK 后走 root 口令校验；
  - `r` 重新启动：warm reboot。
- 打点与 GUI 侧同口径：`GUI:sak enter/lock/unlock/deny_app`。

## 6. 串口打点与自检

### 6.1 运行期打点

| 打点 | 含义 |
|---|---|
| `GUI:sak enter pid=<tid>` | 进入安全模式，记录当前任务 tid |
| `GUI:sak deny_app pid=<tid>` | 安全模式期间有应用试图取事件（双保险过滤） |
| `GUI:sak lock` | 进入锁定态 |
| `GUI:sak unlock` | 口令校验通过，解除锁定 |
| `GUI:sak blocks=<n>` | 块列表动作：当前块表存活数 |
| `GUI:sak exit leaked=<n>` | 退出覆盖层，块泄漏计数（必须为 0） |

### 6.2 自检子命令 `gui sak`

探针流程：建桌面 → 直入 SAK → 校验浮层在位 / 应用 inert / 命中系统面板 →
退出后 `leaked=0`。串口输出：

```
GUI:sak panel=<0|1> events_blocked=<0|1> hit_panel=<0|1> leaked=<n> text_hook=<0|1> result=<0|1>
```

判据：`panel=1`、`events_blocked=1`、`hit_panel=1`、`leaked=0`、
`text_hook=1`、`result=1`。

## 7. 不可劫持证据链

1. **键盘层先于一切输入栈**：组合键在 scancode 解码最底层吞掉，不进入
   `kb_peek` / `kb_getkey` / `kb_readline` 队列；应用读不到三键。
2. **系统层最高优先级**：SAK 面板挂 `LAYER_OVERLAY`（4000），命中顺序层号
   降序，面板优先于所有 WORK / CONTENT / CHROME 块。
3. **CE 侧无热键注册槽**：声明式 ABI 不开放任何热键 / 快捷键回调注册；
   `blk_event_poll` 路径（`SYS_POLLKEY`，`src/task.c`）在 `gui_sak_active()`
   为真时返回 `-1` 并打 `deny_app`，是第二道保险。
4. **应用集合 inert**：面板出现后下层块全部 `inert`，即便事件到达也不参与
   命中与拖拽。
5. **Esc 归属 SAK 优先**：`input.c` 的 Esc 分支先交 `gui_sak_esc()` 消费，
   面板不开时才走菜单 / 退出 GUI，应用无法拦截 SAK 退出路径。
6. **回收可验证**：退出后 `stat_blocks_leaked()==0`，探针 `leaked=0` 断言
   覆盖；无句柄 / 块树残留可供后续会话挂载。

## 8. 边界与不做项

- 本段不引入 alpha 遮罩、圆角、阴影；面板为纯色矩形 + 令牌角色色。
- SAK 不提供应用级「紧急退出」或命令注入通道；重启走与 `reboot` 命令同一
  warm reboot 口径。
- 密码体系复用 root 校验；不新建 SAK 专用口令库。
- CE 侧热键槽位未规划；后续若加全局快捷键，须先过声明式 ABI 评审，不得
  绕过本规格的 §7 证据链。
