# CatOS 块化 GUI 进阶路线图 v1

> 目的：cap2（26 属性 + BLK_POPOVER/BLK_ICON + CE rec2 通道）与 cap3（ARC/SQ5/SQ45 三套 24×24 面积采样表）已经把"声明式块树 + 可核对像素证据"这条地基铺完。本文回答的是下一个问题：**从"能画对"到"像个现代 GUI"，要补哪几层、按什么顺序补、每层拿什么证明它成了。**
>
> 编制时间：夜间窗口（cap2 交付收口期）。基线：`feat/blk-cap2 @079e699`，ISO 12,167,168 B，`_bss_end=0x02122f94`，`full_avg=1976us / idle_avg≈13–21us`，final2 12 项门禁全绿（cap2 通过）。

---

## 0. 先说清楚"更先进"指什么

四条主轴，缺一条都会在真实原型里露馅：

| 主轴 | 现状 | 差距性质 |
|---|---|---|
| **A. 视觉质量** | 16 档 ordered 抖动 alpha、6 档 9-slice 阴影、8×8 位图字 + 伪粗、16×16 单色图标、24×24 圆角覆盖率表 | 无抗锯齿、无灰度字形（中文靠 2×2 降采样）、无渐变、无图像缩放、阴影档位粗 |
| **B. 布局与容器** | 绝对坐标 + 单层自然高聚合 + wrap≤6 + popover 内部滚动 | 无 flex/grid、无嵌套滚动容器、无虚拟列表（长列表会爆块表） |
| **C. 交互完整度** | 点击/输入/滚轮/键盘/浮层关闭、7 缓动×6 掩码动画、thumb 拖动 | 命中仍是**矩形**、无焦点链与键盘导航、无文本选择/编辑、无拖拽、无 hover 稳态、无 tooltip/对话框 |
| **D. 系统与性能** | 整屏重合成（1976us）、layer 常量、无 DPI、无 a11y、无 IME | 无 damage 区域传播、无 z-order 栈、无多窗口、无缩放档、无 IME 候选窗 |

**排序原则**：先用"能看见的错"换用户信任（视觉+命中），再做"让原型跑得起来"的骨架（flex/滚动/虚拟列表），最后做"像桌面"的系统层（焦点/多窗口/DPI/IME）。性能和证据链贯穿每一阶段，不放到最后补。

## 1. 现有能力盘点（能撑到什么程度）

**已经能拿得出手的**
- 声明式块树 + append-only 契约（旧 rec1 40B / 旧 24B 事件队列全程兼容）
- 子树 alpha 乘法 + 4×4 Bayer16 抖动（alpha maxerr ≤2/255）
- 逐角 / pill / auto 同心圆角，cap3 面积采样（n=2 与解析圆弧逐字节 diff=0）
- 阴影 6 档 9-slice（损伤外扩 10/10/16/16、seam_bad=0）、HC 换 1px 边框
- 文本：wrap 1..6/auto、char/word 省略、4 档字号、伪粗、等宽数字、UTF-8 宽字符、禁则、度量缓存
- 浮层：两趟 measure→place、8px 安全边距、四向翻转、超 max_h 内部滚动、点外/ESC、400ms 桥
- 动画：7 曲线 × 6 属性掩码、16 槽、可中断接管、reduced motion
- CE ring3 通道：槽 77/78/79，`caps=0x1ff`，rec2 76B，事件 ev2（click/focus/blur/input/wheel/key/dismiss）
- **桌面事件闭环已打通**（`tree_reset_keep_ce`，真实点击/输入回传实测 PASS）

**硬缺口（按痛感排序）**
1. 命中是矩形 → 圆角块四角、浮层下穿透、pill 按钮外沿都会误命中
2. 中文只有 8px 2×2 降采样 / 16px 1-bit → 正文级中文不可读，直接卡住"原型能不能给人看"
3. 整屏重合成 1976us → 一屏多个动画块就掉帧，且无法做局部重绘
4. 无 flex/grid、无嵌套滚动、块表固定容量 → 真实列表（>200 块）建不出来
5. 无焦点链 → 键盘用户只能点鼠标，Tab/方向键无意义
6. 无文本编辑（光标/选择/剪贴板）→ 输入框只能"打字符串再回车"

## 2. 阶段路线图

每个阶段 = 1 个"包" = 独立 worktree + 独立探针族 + 独立门禁 + 合并后补跑全量。字段一律 append-only，旧记录语义不动。

### P0 · 收口与止血（1 波，约 4–6h）

> **前置：独立审计（`docs/blk-cap2-审计-独立.md`，40 项：通过 17 / 可疑 6 / 问题 17）给出的 2 个阻塞项必须在 P0 内清掉，否则 cap2 不能对外说"能力可用"。**

| 项 | 内容 | 验收 |
|---|---|---|
| P0-0a | **`elevation` 越界钳制**：`validate2` 查 `elevation ≤ 5`，`sh_paint` 入口再钳一次（`shadows.c` 的 `shadow[6]/SH_PAD[6]` 数组越界读，轻则错误阴影、重则页错误） | 负例探针 `elevation=6/255` 不越界、渲染回退 flat |
| P0-0b | **事件队列溢出显式化**：`enqueue2` 满队当前静默 `return`（`decl.c:690`），改为"丢最旧 + `dropped++` + 串口打点"，`decl_stats` 可读 | 深 8 队列灌 12 条：收到 8 条、`dropped=4`、无静默 |
| P0-0c | **`anim_kick` 接生产路径**：现在只有探针在建档，真实声明块动画永不启动。改为 `decl_apply2`/属性变更处按 `anim_ms>0` 建档 | CE 提交一个带 `anim_ms=192` 的块，桌面帧循环里真的动起来（事件/像素双证） |
| P0-0d | **滚轮链路接线**：`mouse.c` 已解析 `dz` 但 `input.c` 从不读；`sb_wheel`/`decl_post_wheel` 全树无生产调用 → CE 收不到 `ev_kind=4`。补 `gui_pump_input` 读 `dz` → `sb_wheel` + `decl_post_wheel` | 滚轮探针：thumb 位移 3 行、CE 收到 `ev_kind=4 dx/dy` |
| P0-1 | `079e699` 上补跑完整门禁（final3 全套 13 项，含 `cap2_deskev` 6/6） | 全绿 + `gate-*-final3.log` |
| P0-2 | 独立审计三类问题清零（阻塞项必修，可疑项定级处理） | 审计表 0 阻塞 |
| P0-3 | **命中改圆角精确**：`hit_test` 用 `corner_mask` 覆盖率做圆角外剔除（>50% 才命中） | 探针：四角内外各 8 点，误命中 0 |
| P0-4 | **damage 矩形并集**：动画/滚动/输入光标只重合成脏矩形，不再整屏 | 单块动画 full_us 1976→≤600us |

> 说明：P0-3 是把 cap3 的表从"只影响像素"升级到"也影响交互"，性价比最高；P0-4 是所有后续视觉特性（AA、渐变、多窗口）的成本前提。

### P1 · 视觉质量（2–3 波）
1. **灰度字形**：字模从 1bpp 升 4bpp 灰度（8/16/24px 三档内置），中文 16px 单独一套（4bpp 16×16 = 128B/字，按 300 常用字预算 ≈ 37.5KiB，走**帧池/按需上盘**，不进静态 `.bss`）；渲染走 subpixel 定位 + 灰度混合 → 抗锯齿中文。
2. **渐变填充**：线性/径向两端色，4 档抖动量化（复用 Bayer16），块级 `grad_dir/grad_c0/grad_c1` 三字段。
3. **阴影升级**：6 档 → 10 档，9-slice 边距按档自适应；加"接触阴影"细分（1px 硬边 + 8px 软晕）。
4. **图像**：块级 `img_scale`（1/2、原尺寸、整数倍），最近邻 + 面积平均两档；先不做双线性。
5. **图标**：16×16 单色 → 16×16 双色 + 24×24 一套（矢量描述过重，先用位图，`icons_gen.py` 生成）。

验收：灰度中文 16px 目视 + 逐字像素断言（笔画覆盖率 ≥ 阈值）；渐变 4 档量化 error ≤2/255；`full_us` 不因 AA 上升超过 15%。

### P2 · 布局与容器（2–3 波）
1. **一维 flex**：`dir(row|column) / grow / shrink / basis / gap / align(start|center|end|stretch) / justify`，主轴按 basis+grow 分配余量，交叉轴按 align。
2. **简化 grid**：固定列宽数组 + `span`，行高自然。
3. **滚动容器**：`scroll_h/scroll_w` + `clip_children`，thumb 与内容高联动（复用既有 sb 代码，扩到任意容器）；惯性滚动（速度衰减，可关）。
4. **虚拟列表**：容器按"可见窗口 ± 1 屏"只建块，滚动时回收池复用（块表固定容量下这是唯一活路）。
5. **sticky header**：滚动容器的第一个子块可 `sticky`。

验收：flex 三档余量分配表格化断言；滚动容器 300 子块只建 ~30；虚拟列表滚动 20 帧块表不增长。

### P3 · 交互完整度（2–3 波）
1. **焦点链**：`tab_index` + 环形 Tab/Shift-Tab，方向键在 flex 容器内空间导航，焦点环绘制（elevation 自动 +1 已有）。
2. **文本编辑**：光标、选区、Backspace/Delete、Home/End、Ctrl+A/C/V（剪贴板走内核单槽）、多行换行与垂直滚动联动。
3. **拖拽**：8px 阈值、幽灵块（半透明副本）、drop 目标高亮、`drag_start/drag_move/drop` 三事件（ev2 扩 kind 7/8/9）。
4. **hover 稳态**：指针停留 400ms 触发 `hover` 状态（elevation/阴影变化），离开复位；与 400ms 桥共用计时器。
5. **tooltip / dialog**：tooltip 复用 popover（无关闭、随指针）；dialog 复用 popover + 模态遮罩（吞掉下层命中）。

验收：Tab 顺序 12 块环形；选区像素高亮；拖拽三事件字段；模态遮罩下穿透命中 0。

### P4 · 系统层（2–3 波）
1. **z-order 栈**：块树外再挂"层序表"（每层有序 pid 列表），浮层/菜单/dialog/toast 五层固定；damage 传播按层裁剪。
2. **多窗口**：可拖拽标题栏、最小尺寸、层序提升、窗口级 clip。
3. **DPI**：1x/1.5x/2x 三档，字模与掩码按期选择（2x 用 48×48 表或运行时上采样）；坐标统一逻辑像素，光栅化时乘缩放。
4. **鼠标指针**：软件光标（16×16 双色 + 热点），隐藏硬件光标。
5. **a11y 树导出**：`role/name/state/value` 四字段，CE 可读（槽 80 `a11y_get`）；先供测试用，不做屏读。

验收：窗口拖拽 20 帧无撕裂；2x 下像素断言全过；a11y 树 20 块字段正确。

### P5 · 性能与可测（贯穿）
- 每阶段固定四个数：`full_us`、`idle_us`、`damage_ratio`（脏面积/整屏）、`_bss_end`。
- 缓存分层：字形 LRU（度量已缓存，位图未缓存）→ 掩码按 (radius, shape) 索引 → 阴影图集。
- 块表分级：静态块池 + 可回收池；>80% 占用时打 `WARN_BLK_POOL`。

## 3. ABI 与契约策略

- **继续 append-only**：`blk_spec` 追加字段（P1 的 `grad_*`、P2 的 `flex_*`、P3 的 `tab_index`）；`ce_blk_rec2_t` 不动，新增 `ce_blk_rec3_t`（128B，前 76B 与 rec2 逐字节一致），`rec_size==128` 才走新路径。
- **CE 槽位**：80 `a11y_get`、81 `drag_begin`（可选）。槽号不复用、不重排。
- **版本串**：cap 位 `DECL_CAP_*` 逐阶段加 bit，`decl_caps()` 返回值即能力清单；CE 侧按位降级。
- **不承诺清单**（本轮明确不做的）：真矢量字体光栅化（TTF 解析）、双线性/三线性图像缩放、GPU 加速、桌面合成器级模糊/毛玻璃。

## 7. 与 cap2 交付的关系（审计后修正）

- 门禁（final2 12 项 + deskev 6/6）证明的是**被探针覆盖的路径正确**，不证明**生产路径全部接线**。独立审计指出 17 项问题，其中 4 项属"实现了但无生产消费点"：
  - `anim_kick` 仅探针调用 → 声明式动画在真实路径**不启动**；
  - `dz` 已解析但 GUI 分发不读 → **滚轮对 CE 与 scrollbar 都没通**；
  - `border_sides` 无绘制消费点 → 单边描边**不生效**；
  - `sb_mouse` 拖 thumb 未接线；`hc_force` 不下传子树。
- 因此 cap2 的准确交付口径应写成：**"26 个属性里 24 条有像素/行为证据，6 条判据偏弱，5 条生产路径待接线；2 个阻塞项（`elevation` 越界、事件队列静默丢）必须在 v2.81 前修掉。"**
- 未跑 final3 时，交付文档须注明"最后完整门禁为 `49334c3` 的 final2，`079e699` 只有 deskev + 回归子集"。
- P0-0 与 P0-1 必须排在任何新特性之前——否则后续每波都在一个"探针绿、生产路径有洞"的树上叠加，越往后越难定位。
