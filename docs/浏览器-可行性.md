# 浏览器 v0 —— 可行性与零件选型

> 分支 `feat/gui-blocks`。本文合并两份 spike 材料：
> - 网络运行时实测：`/home/user/work/browser-spike/runtime/NET-RUNTIME.md`（客人机上机证据）；
> - 零件体积/堆/许可证实测：`/home/user/work/browser-spike/SPIKE-MEASURE.md`、
>   `可行性-草案.md`、机读 `measure.json`。
>
> 门槛（零件选型口径）：i386 32 位、`-Os`、freestanding；`.text ≤ 120 KiB`，
> 峰值堆 ≤ 512 KiB（固定池 bump allocator，带 reset）；关键静态表必须留在
> `0x02000000` 用户镜像窗口之下，引入前过 `kernel_v25/tools/check_link_layout.py --strict`（退出 0）。

## 1. 结论（v0 选型）

| 环节 | 选型 | 判定 |
|---|---|---|
| HTML 解析 | **自写瘦流式 tokenizer（不建树）**，工作集 < 16 KiB 量级 | 采用 |
| 图像解码 | **stb_image.h**，仅 PNG/JPEG 档，`.text` 24.53 KiB（PD/MIT 双许可） | 采用 |
| myhtml | LGPL-2.1-or-later copyleft，不在许可证允许集；**不能挑文件 vendoring** | **否决（许可证）** |
| lexbor | Apache-2.0 许可证合格，但 `.text`/静态表/堆均不达标 | **否决（预算）**，二期参考备选 |

v0 形态：块式浏览器，复用现有块化 GUI（COLUMN/ROW/STACK、`BLK_TEXT`、`BLK_CANVAS`、
令牌主题、脏位提交）；无进程、无 IPC、无窗口系统概念；回调只打脏位，33 fps 节拍不变。

## 2. 网络运行时实测（上机）

环境：QEMU slirp user-net，e1000，`-m 256`；客人机 `netcfg dhcp` 租到
`10.0.2.15` / gw `10.0.2.2` / dns `10.0.2.3`。证据屏证与 `results.json` 在
`browser-spike/runtime/`。

| URL | 方案 | 状态码 | 收到字节 | 判定 |
|---|---|---:|---:|---|
| `http://example.com/` | HTTP/1.0 | 200 | 577 B | ✅ 完整取回 |
| `https://example.com/` | TLS 1.2 | — | — | ❌ `error -6` 握手失败 |
| `http://www.baidu.com/` | HTTP/1.0 | 状态行出屏不可见 | 8191 B（命中 shell 8 KiB 缓冲上限） | ⚠️ 有响应体，被截断 |
| `https://www.baidu.com/` | TLS 1.2 | — | — | ❌ `error -6` 握手失败 |

宿主同出口 HTTP/HTTPS 均 200，排除网络不通；本地 OpenSSL 自签 + 0xC027 TLS1.2
回路此前 D2 验收通过。**真站点 HTTPS 阻塞的根因定性见 §6（取证进行中）。**

### 2.1 内核网络约束（源码核实）

- **缓冲上限**
  - `net_http_get(url, out, max)`：复制 `max-1` 字节，尾部补 NUL，文本口径；
  - shell `curl` 静态 buf `[8192]` —— **浏览器缓冲不能复用它**，须用池/arena 内存；
  - 明文 TCP `rcv_buf[65536]`（64 KiB），非流式 GET 整包落在其中，超出丢弃；
  - TLS 解密收集 `resp[20480]`（20 KiB），TLS 路径不解析 chunked；
  - 大包可走 `net_http_download_stream(...)` 流式 sink（明文路径有增量 dechunk）。
- **阻塞/超时**：单条阻塞连接，忙轮询 `net_poll()` + `task_maybe_yield()`（协作式让出，
  非抢占异步）；SYN 300 万次迭代、明文接收 1500 万次、TLS recv 50000 ticks/段；
  无连接池、无 keep-alive、无并发下载。**导航中只允许一个请求在飞。**
- **HTTPS 现状**：无证书链/主机名/SKE 签名校验（仅加密，可 MITM）；TLS 1.2，
  Offer `0xC02F`(GCM) 回落 `0xC027`(CBC)，secp256r1，已带 SNI；无会话恢复、无 1.3；
  https 下载非流式。重定向最多 4 跳，跨方案跳 https 返回 `-7`。

## 4. 体积与堆实测

### 4.1 体积（`.text` / 静态表；门槛 `.text ≤ 120 KiB`）

| 档位 | `.text` | `.rodata` | `.data` | `.bss` | 判定 |
|---|---:|---:|---:|---:|:--:|
| myhtml-core（tokenizer+parser，不含 DOM） | 52.39 KiB | 859.68 KiB | 0 | 0 | 体积过，许可证否决 |
| myhtml-dom（核心 + DOM 层） | 77.49 KiB | 860.91 KiB | 0 | 0 | 体积过，许可证否决 |
| lexbor-all（全模块） | 266.46 KiB | 1258.06 KiB | 762.82 KiB | 0.09 KiB | 不过 |
| lexbor-html（仅 HTML 解析链路） | 161.68 KiB | 1210.20 KiB | 760.20 KiB | 0.09 KiB | 不过 |
| stb-all（全图像格式） | 40.19 KiB | 3.11 KiB | 0.02 KiB | 0.02 KiB | 过 |
| **stb-png-jpg（推荐档）** | **24.53 KiB** | **2.36 KiB** | **0.01 KiB** | **0.02 KiB** | **过** |

lexbor-html 静态表合计约 1.94 MiB（unicode 数据库 752 KiB rodata、编码资源 768 KiB data、
tokenizer 状态表 242 KiB 等），对 `0x02000000` 用户镜像窗口与链接护栏是高风险。

### 4.2 堆（门槛峰值 ≤ 512 KiB，bump 池带 reset）

32 位结构体实测：lexbor element 92 B / node 48 B / attr 72 B；myhtml node 44 B / token 52 B / attr 68 B。

| 用法 | 100 KB 文档 | 密集元素压力剖面 | 判定 |
|---|---:|---:|:--:|
| lexbor 含 DOM | 460.5 KiB（对齐 480.0 KiB，紧平衡） | 1622.2 KiB（对齐 1632.0 KiB） | 压力不过 |
| myhtml 含 DOM | 510.1 KiB（对齐 512.0 KiB，贴顶） | 1953.3 KiB（对齐 1984.0 KiB） | 不过；许可证否决 |
| **自写瘦 tokenizer（流式，不建树）** | **工作集 < 16 KiB 量级** | 同量级，随当前 token 复用 | **过** |

未计入：原始 HTML 源缓冲（走 mmap arena，不进 bump 池）；解码位图帧缓冲（见 §4.3）。

### 4.3 位图内存（硬约束）

| 分辨率 | RGB | RGBA |
|---|---:|---:|
| 800×600 | 1.37 MiB | 1.83 MiB |
| 1920×1080 | 5.93 MiB | 7.91 MiB |

帧缓冲**必须走 mmap arena / 页分配器**，不进 bump 池、不进 `.bss`；v0 限制图片分辨率或先降采样。

## 5. v0 范围与砍项

### 5.1 v0 做

- 地址栏块；前进 / 后退 / 刷新 / 停止；状态行（URL / 状态码 / 字节数 / 耗时）。
- 取 HTML：`net_http_get` 或 `net_http_download_stream`；浏览器自有池/arena 缓冲，
  不复用 shell curl 的 8 KiB 静态 buf；单条阻塞连接，导航中只允许一个请求在飞。
- tokenizer → 极简样式（标题/段落/列表/粗体/链接/居中/基本颜色；只认少数属性与内联
  `style`，无选择器引擎）→ 块描述树 → `gui_commit_desc`。
- 映射：block 级 → COLUMN/ROW；文本 → `BLK_TEXT`（折行在浏览器层自己切，不改全局
  文本块口径）；`<img>` → `BLK_CANVAS`（stb_image 解码 24bpp 不透明 1:1）；
  `<a>` → 命中跳转；表格 v0 只逐行 ROW 摊平。
- 滚动：视口块平移 + 裁剪，不整页重建；hover 只换令牌色。
- 串口 `GUI:` 打点：fetch 字节数 / 解析节点数 / 块数 / 帧耗时；像素断言 browser 组。

### 5.2 砍项（v1 不做）

- **HTML**：CSS 解析/选择器/层叠；完整 Unicode 数据库/BIDI/大小写映射；多字节编码
  （仅 UTF-8，Latin-1 回退）；全量实体表（保留常用约 200 个）；命名空间、mutation 事件、
  节点克隆、DOM 序列化；表格/表单 quirks 规则；数字格式化解析。
- **图像**：BMP/GIF/TGA/PSD/HDR/PNM 不解码；不支持 GIF 动画；不做缩放、色彩管理、
  EXIF 方向修正。

## 6. HTTPS 阻塞（根因归网络线，非 GUI 线）

现象：`https://example.com/`、`https://www.baidu.com/` 均 `error -6`；宿主同出口 200；
本地自签 0xC027 回路通过。`-6` 在 TLS 路径覆盖 ClientHello/记录发送、握手记录接收失败、
uECC 密钥生成失败三种来源，当前未细分。

**口径裁定（2026-11-24）**：真站点 `-6` 定性为**网络线**问题（TLS1.2 无 CA 存储 /
SNI 落地 / 密码套件路径），不是块化桌面 GUI 线的缺陷。B1 验收**不以 HTTPS 野站为阻塞项**：
HTTP 站点 ≥3 个渲染成功即可；HTTPS 打通单独立项「网络线：TLS 真站点握手」，排在浏览器
v0 之后。`src/tls.c` / `src/tls_aes.c` 仍属禁改文件，根因若落在其中须上交证据与最小改动
方案，不擅自改。

取证方向（不改 `src/tls.c` / `src/tls_aes.c` 语义前提下）：
1. ClientHello 发出后是否等到 ServerHello（卡在等待 / 被关闭 / 收到 alert）；
2. 证书消息大小 / 分片是否超 20 KiB 收集缓冲；
3. SNI 是否被对端接受；
4. 是否 TLS1.3-only 站点拒绝 1.2 ClientHello；
5. 调用侧接收缓冲 / TLS 收集 20 KiB 上限 / chunked / 超时是否为可修根因。

边界：若根因落在禁改的 `tls.c` / `tls_aes.c` 内，**停止改代码**，把证据与最小改动
方案上交，由主代理请示用户；若根因在调用侧（netstack.c 缓冲/收集上限/超时），可直接修。

## 7. 风险与回退

| 风险 | 缓解 / 回退 |
|---|---|
| 堆不足：DOM 紧平衡、帧缓冲 MiB 级 | 树节点/帧缓冲走 mmap arena；bump 池只放瞬时 token；必要时池扩到 2 MiB 复测 |
| 畸形 HTML 崩溃/爆栈 | 长度与深度硬上限；迭代状态机；脏页面 fuzz；token 边界检查 |
| 深递归 | v1 不建树规避；二期引入 DOM 前先测最大嵌套深度并改迭代 |
| 字符集 | 仅 UTF-8；非 UTF-8 页面降级提示，不做全编码解码 |
| 静态表超镜像窗口 | 引入前过 `--strict`；大表先压缩/外置/评审 |
| 自写 tokenizer 规范覆盖不全 | 以 lexbor 为对照做黄金样例比对；未覆盖场景降级为纯文本展示 |
| HTTPS 真站点不可用 | v0 先以 HTTP 本地/明文页交付；HTTPS 打通前如实记为阻塞项，不假装可用 |
