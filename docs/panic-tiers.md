# CatOS 异常 / 崩溃分级表（panic tiers）

> 版本：v2.59-crashscreen 增量（基于合流主仓 cbf77c3）
> 口径：可靠性优先。本表核对的是**当前代码实际分级**，与 `intr.c` 异常分发、
> `diag.c` 的 `panic()`、`bsod.c` 崩溃屏一一对应；若后续改动分级，必须同步本表。

## 1. 分发入口

异常统一进入 `isr_exception(int_frame_t *f)`（`kernel_v25/src/intr.c`）。
分发依据两个事实：**故障发生的特权级**（`f->cs & 3`）与**异常向量**（`f->intno`）。

- 入口先写 COM1 串口 breadcrumb（`serial_log.c`，轮询 LSR.THRE，超时丢弃不阻塞）。
- P0-2 护栏：若 `g_in_panic != 0`（已在崩溃屏），直接 `cli; hlt` 死循环，**不再递归进蓝屏**。

## 2. 三级分级（现行实现）

| 级别 | 触发条件（向量 / 特权级） | 现行行为 | 代码位置 | 是否冻结整机 |
|---|---|---|---|---|
| **L0 用户态异常（隔离级）** | ring3（`f->cs & 3 == 3`）的任何致命异常：`#PF(14)` / `#GP(13)` / `#UD(6)` / `#DE(0)` / `#DF(8)` 等 | ① `#PF` 先交 `task_page_fault()` 惰性映射；可恢复则重试指令，**不杀任务**；② 不可恢复则 `fault_record()` 记录最后一次故障，`task_die_fault()` 打印一行简短错误（任务名 / tid / 故障类型 / EIP / CR2），置僵尸、退出码 `-1`、重调度。**不进全屏蓝屏**，shell 与其他任务继续运行。 | `intr.c` `isr_exception()` ring3 分支；`task.c` `task_die_fault()`；`vma.c` `task_page_fault()` | 否，只杀出错任务 |
| **L1 可恢复内核错误（任务级降级）** | ring0 内核路径中**可定位到单个任务**的错误（如用户指针校验失败、VMA 映射失败等受控返回路径） | 打印简短错误行，终止相关任务（僵尸 + 回收 + 唤醒等待方），不冻结整机；内核其余部分继续调度。 | `vma.c` `validate_uaddr()` / `task_page_fault()` 返回 `-14`；`task.c` 退出/回收管线 | 否，终止相关任务 |
| **L2 致命内核错误（全屏蓝屏）** | ring0（`f->cs & 3 == 0`）的致命异常：`#DE(0)`、`#UD(6)`、`#DF(8)`、`#GP(13)`、`#PF(14)`、`#NM(7)`、`#SS(12)`、`#TS(10)`、`#NP(11)`，以及机器检查类（18/19）；另有手动 `panic(msg)` 与 shell `bsod` 命令 | `fault_record()` 记录 → COM1 breadcrumb → `bsod_enter()` 全屏崩溃屏（摘要字段 + 单键诊断页），按缓存的 `/etc/panicmode` 执行 reboot / halt / wait。 | `intr.c` `isr_exception()` ring0 分支；`diag.c` `panic()`；`bsod.c` `bsod_enter()` | 是，整机停机/重启 |

### 2.1 向量到全屏的归属核对（任务书口径对照）

| 任务书点名的全屏向量 | 编号 | 现行是否进全屏（ring0） | 备注 |
|---|---|---|---|
| `#PF` 页错误 | 14 | 是 | ring3 先惰性映射，不可恢复才杀任务；ring0 直接 L2 |
| `#GP` 一般保护 | 13 | 是 | ring3 杀任务；ring0 直接 L2 |
| `#UD` 非法指令 | 6 | 是 | ring3 杀任务；ring0 直接 L2 |
| 双重故障 `#DF` | 8 | 是 | ring0 进入；ring3 双重故障本身极少，走 L0 杀任务分支 |
| 看门狗（watchdog） | — | **deferred** | 当前内核未实现硬件/软件看门狗（`grep watchdog` 无命中）；接口预留：看门狗超时未来应直接走 L2 全屏路径，与 ring0 异常同一入口。 |

其余向量（`#DE 0`、`#BP 3`、`#OF 4`、`#BR 5`、`#NM 7`、`#TS 10`、`#NP 11`、`#SS 12`、`#MF 16`、`#AC 17`、`#MC 18`、`#XM 19`）：
ring3 一律 L0 杀任务；ring0 一律 L2 全屏。

## 3. 与任务书分级口径的差异 / 待办

1. **「可恢复内核错误打印简短错误并终止相关任务」**：现行内核没有独立的「可恢复 ring0 错误」类别——ring0 一旦取到致命异常即 L2 全屏。L1 级目前由**受控返回码**（非异常）承载：用户态指针/VMA 校验失败在 ring0 syscall 内返回负错误，相关 ring3 任务由退出管线终止，不触发异常分发。这与任务书「可恢复内核错误终止相关任务不冻结整机」的**效果一致**，触发方式是返回码而非异常。
2. **看门狗**：未实现，登记 deferred（见问题清单续号条目）。
3. **退出码**：ring3 被杀任务的 `exit_code = -1`（`task_die_fault`），简短消息走控制台一行；退出码细化（按向量区分）留后续。

## 4. 崩溃屏（L2）输出契约

- **双输出**：关键信息先写 COM1（0x3F8，轮询 `LSR.THRE`，守卫超时丢弃字节不阻塞），再写 VGA 文本缓冲；任一路失败不影响另一路。
- **自包含**：蓝屏路径不调用 `kmalloc`、不持阻塞锁、不 `sleep`、不开 FS、不进 IME、不做 UTF-8 框线绘制。
- **护栏**：`g_in_panic` 置位后，任何再次进入的致命异常 / triple fault 直接 `cli; hlt`；panic 深度计数上限 `BSOD_PANIC_DEPTH_MAX = 2`，超限 halt。
- **默认摘要页**：异常类型 + 十六进制向量、CPU 号、FATAL、RECOVER、简短原因、ERR、EIP、CR2（仅页错误）、RSP、EFLAGS、栈顶 3~5 帧、操作提示行、自动重启倒计时；默认**不显示**全量寄存器 / 日志 / 用户输入 / 剪贴板。
