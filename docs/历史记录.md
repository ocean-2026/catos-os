# CatOS v2.67 变更说明（二进制注册表 / 命令契约 / 安全基线 / TUI / 渲染）

## 1. 二进制树状注册表（`hive.c` + `hive.h`）

替换 v2.62 的 `/etc/reg` 文本 INI。镜像 `/etc/hive`，格式 CHV1：

```
off 0   8   magic "CHV1\r\n\x1a"
off 8   4   version = 1
off 12  4   generation（每次成功 save +1）
off 16  4   node count
off 20  4   payload bytes = count * 122
off 24  4   payload CRC32
off 28  4   header CRC32（前 28 字节）
off 32  ..  节点区：每节点 122 字节
```

节点：`parent/child/sib` 各 int16、`kind`（0 free / 1 key / 2 sz / 3 dw / 4 bin）、
`namelen`、`datalen`、`name[32]`、`data[80]`。根：`HKLM`、`HKU`、`HKSEC`；
`HKCU\...` 在解析阶段改写为 `HKU\<uid>\...`。路径大小写不敏感，分隔符 `\` 或 `/` 均可。

保存是"写入 → 回读 → 逐字节比对 CRC/长度"的事务：失败从 `/etc/hive.bak` 回滚；
损坏镜像隔离成 `/etc/hive.bad` 供 `hive chk` 查看。

常用命令：

```
hive                     摘要
hive ls [-R] [PATH]      列出子键/值
hive get PATH            取值
hive set PATH VALUE      写字符串
hive setdw PATH N        写 DWORD（十进制 / 0x / 负数）
hive mkkey / del / delkey
hive export / dump       文本导出
hive import FILE         文本导入
hive chk                 非破坏性校验（不在运行中的树上做 load）
hive save / commit / flush
```

### 本轮修掉的三个真实缺陷

1. `path_split()` 复用 `cur[]` 时未置 NUL，第二个组件起会带上一个组件的尾巴，
   种出 `HKLM<garbage>` 这类伪根 → 树自毁、`hive_verify()` 必败。
2. `resolve()` 在"中间段是值"时把错误码 `-7` 当节点索引返回，导致 `g_nodes[-7]`
   越界写 → 静默踩坏节点表。改为一律返回 `NODE_NONE`，原因存 `g_resolve_err`，
   各 setter 原样返回（保住 `ENOTDIR` 语义）。
3. `hive chk` 曾调用 `hive_load()` 做"复读"：它先清空 `g_nodes`，失败时会让**运行中的
   注册表**变空，后续 `hive get/ls` 全部报"没有这个键"。改为 `hive_check_image()`：
   只校验镜像头部/CRC，并把 payload 与当前树的序列化逐字节比对，绝不触碰活树。

QEMU 实测（带 FAT32 磁盘）：`hive save` → 重启 → `on-disk state: loaded and CRC-verified
at boot`、`dirty 0`、`generation` 递增、`hive ls HKLM` 正常列出三个子键。

### 设置整合

`HKLM\Software\CatOS\Terminal\{Theme,FontSize,Cursor\*,ScrollbackRows,Pager\*,
Colors\<16 角色>}`、`HKLM\System\{Language,VideoMode,Crash\Mode,Crash\Colors\<5 角色>}`、
`HKLM\Environment\{PATH,PS1,HistoryMax}`、`HKSEC\Policy\*`。
`/etc/reg`、`/etc/lang`、`/etc/videomode`、`/etc/panicmode`、`/etc/size`、`/etc/env`
在首次启动时被迁移进 hive（`hive_init` 的 `migrate_legacy_files`）。

## 2. 渲染不再整屏闪

- `redraw_all()` 的 `be->clear()` 只保留给模式切换/初始化；
- 滚动时后端不能平移（VBE 环绕、模式不支持）的路径改为 `repaint_all()`：逐格覆盖，
  不再先擦黑整屏；
- 文本模式宽字符（CJK / 制表符）刷新 `render_flush()` 改为 `repaint_wide_only()`：
  只重绘宽字符格，而不是每打一个汉字全屏重画。

## 3. 命令契约（`posix.c`）

一张 `SPECS[]` 表描述每个内建的 synopsis、允许的短/长选项、操作数上下限、路径存在性检查。
分发前统一校验，输出 POSIX 风格报错与退出码（2 语法 / 1 运行失败 / 13 权限），
`--help` 自动可用。详见 `docs/SECURITY-v2.67.md` §7。

## 4. 权限与安全（`sec.c`）

集中式 `sec_allow()` + 每命令可覆盖的 `HKSEC\Policy\Cmd\<cmd>\Caps` + 可执行文件策略
`HKSEC\Policy\Exec\Strict` + 48 条环形审计。详见 `docs/SECURITY-v2.67.md`。

## 5. TUI（`tui.c` 重写 + `dash.c`）

旧 `tui.c` 在 VBE24 下直接写像素，绕过脏格追踪（幽灵残影），且没有任何调用者。
新版规则：**只写单元格**（`con_set_style_rgb` + `con_write_at`）、只用单宽 ASCII 字形、
颜色全部取自注册表调色板。组件：`tui_box/panel/fill/gauge/kv/tabs/section/hintbar/row/spark`。
`dash`（别名 `sysmon`）用它们画出四页面板：System / Storage / Network / Security，
`q` 退出、`tab` 切换、`1-4` 直选、`r` 刷新。

## 6. 配色注册表化

`palette.c` 把 21 个语义角色（BG/FG/PROMPT_*/COMMAND/ARGUMENT/ERROR/WARNING/SUCCESS/
INFO/DIM/ACCENT/SELECTION/STATUS_*/BSOD_*）映射到 CLUT 槽 32..52 与
`HKLM\...\Colors\*`。`shell.c`、`fs.c`（ls 着色）、`bsod.c`、`tui.c` 已无硬编码 VGA 颜色；
`theme dark|light|solarized|mono [--crash]` 立即生效并**写盘持久化**。

## 7. 关机（`power.c`）

删除保护模式 `INT 15h`（APM）路径——它走内核异常门 → panic → 蓝屏，这就是
"shutdown 必蓝屏"的根因。改为 ACPI：RSDP(EBDA + 0xE0000..0xFFFFF) → RSDT/XSDT → FADT
的 PM1a/PM1b_CNT_BLK + DSDT `_S5_` 的 SLP_TYPa，写 `(t<<10)|SLP_EN`，t 从固件值 0..7 扫描；
所有 ACPI 物理指针先经 `paging_phys_top()` 边界校验。兜底：0x604/0xB004/0x4004 固定端口、
8042 `0xFE` 复位。

QEMU 实测：`shutdown` 后进程退出（`guest alive: False`），无蓝屏。

## 8. 已知未完成

- VMware ES1371 发声：现状把 ES1371 当 ES1370 编程，AK4531 codec 未解静音。
  QEMU 只有 ES1370 模型（`-device es1370`），**无法复现** VMware 的 ES1371 行为。
- `pkg` 包签名、`UnknownBinary` 校验器、每任务 CPU 配额。

# CatOS v2.67.1 补充：前台看门狗 / 可写目录拒绝 / dash 分页

本轮把 v2.67 里"只有默认值、没人执行"的两个策略键真正接进了控制路径，
并修掉两个测试/路径上的小坑。全部在 QEMU 6.2 上实测。

## 1. 前台看门狗（HKSEC\Policy\Foreground\*）

问题：v2.67 的 `audit` 只能如实写出"前台 ring0 命令可以长期占住控制台"，
`hang` 一按就 cli/hlt，机器再也不回来。这既是可用性坑，也是安全面（任何人
一次按键即可让系统失去响应）。

实现（`src/sec.c` + `src/shell.c`）：

- `sec_fg_arm(cmd)` 在 `shell_run()` 每次真正调用 `shell_exec` 之前记录起始
  `timer_ticks` 并读取预算；`sec_fg_disarm()` 在其后清除。
- 预算来自 `HKSEC\Policy\Foreground\TimeoutSec`（默认 **60** 秒）；
  `HKSEC\Policy\Foreground\AllowUnbounded=1` 可整条关掉（回到旧的致命行为）。
- `sec_fg_expired()` / `sec_fg_used()` / `sec_fg_should_abort()` 供命令自身轮询。
  **它是协作式看门狗，不是抢占式调度**：从定时器中断里 longjmp 出正在执行的
  函数会把内核状态踩坏，这里明确不做，也不假装做了。
- `cmd_hang` 改为"在预算内把 CPU 挂住，预算用尽则恢复中断、打印并把控制台
  还给 shell"，同时写一条 `fg-timeout` 审计（rc=124，对齐 coreutils 的超时码）。

实测（TimeoutSec=5）：

```
root@catos:/# hive setdw HKSEC\Policy\Foreground\TimeoutSec 5
hive: HKSEC\Policy\Foreground\TimeoutSec = 5 (dw)
root@catos:/# hang
Halting until the foreground budget expires...
hang: budget spent, interrupts re-enabled -- console returned
root@catos:/# echo still-alive
still-alive
```

## 2. UnknownBinary\AllowFromWritableDir 真正生效

原来只有默认值 0，没有任何代码读它。`sec_exec_check()` 现在除了检查 **文件**
本身的 world/group 可写位，还会取父目录的 ACL：

- 目录 world-writable → `binary sits in a world-writable directory`
- 目录 group-writable → `binary sits in a group-writable directory`
- 设 `AllowFromWritableDir=1` 才放行（显式降级，审计留痕）

理由：`0755` 的可执行文件放在 `0777` 的目录里，依然是谁都能替换，只看文件
模式等于没看。

实测：

```
root@catos:/# chmod 777 /ww
mode updated
root@catos:/# /ww/hello.ce
exec: refused '/ww/hello.ce': binary sits in a world-writable directory
catos: unknown command: /ww/hello.ce
root@catos:/# hive setdw HKSEC\Policy\UnknownBinary\AllowFromWritableDir 1
root@catos:/# /ww/hello.ce
Hello from CE!
```

`AllowUnsigned` 仍然是"没有校验器"的诚实状态：CE01 头没有签名字段，加一个
谁都能追加的魔数当"签名"是假安全。要么加真密钥（HMAC over image + 密钥存
hive），要么不做——本轮选择不做，并在 SECURITY 文档里保持列为缺口。

## 3. dash 分页参数

`dash [system|storage|network|security|1-4]` 直接从指定页打开。原因很实际：
交互式界面永远不回到提示符，截图脚本无法用按键切页；给个参数就能一次
boot 拍一页。未知页名 → 报错 + `$?`=2。

## 4. 两个路径/测试坑

- `run_from_path()` 在 cwd 为 `/` 时拼出 `//ww/hello.ce`，诊断和审计里那个双
  斜杠很难看，已改为单斜杠。
- `tests/shoot_dash.py` 之前"22 秒后屏幕全空、no prompt"的根因找到了：不传
  磁盘时客机没有 FAT32 卷、也就没有 `/bin`，走的是"无文件系统"分支而不是
  shell。现在默认取 ISO 同目录的 `catos_disk.img`。

## 仍未做（不掩饰）

- `pkg install` 无签名校验；`AllowUnsigned` 无校验器（见上）。
- 无每任务 CPU 配额；看门狗是协作式的，纯 `while(1)` 不轮询的自定义 `.ce`
  仍能把机器占住——只有 ring3 任务被调度器轮转时才不受影响。
- VMware ES1371 无声：QEMU 只有 ES1370 模型，无法复现，未盲写 codec 序列。

# CatOS v2.68 / v2.68.3 变更说明（中文输出 / 命令合并 / sudo / 输入法 / 包签名 / gfx 查询）

本轮把中文覆盖到几乎所有系统命令，收敛重复命令，修掉 sudo / 裸名 PATH /
输入法选词 / 包签名等一系列真实缺陷。v2.68.1/.2/.3 是同轮热修复：修正 RSA
验签大整数实现、sudo 参数透传、`ls --color-scale=VALUE` 的 POSIX 规格、
`strncmp_()` 精确前缀比较导致 `ls -l` 丢列，以及 `--blocks=COLS` 表头缺列。

---

## 1. 中文输出全覆盖

语言设为 `zh` 时（`/etc/hive` 的 `HKLM\System\Language`，或 `lang zh`），
以下命令输出中文：

| 命令 | 覆盖内容 |
|---|---|
| `about` | ASCII 大标严格按指定字样，正文全中文 |
| `keys` / `shortcuts` | 快捷键说明 |
| `uname` / `date` | 系统标识 / 当前 RTC（v2.68.1 补齐） |
| `mem` / `uptime` | 内存与运行时长 |
| `color` / `style` / `theme` | 配色提示 |
| `autostart` | `/etc/autostart` 脚本列出提示（仍不自动执行） |
| `caps` / `audit` | 能力位图例与审计日志 |
| `hwinfo` | 硬件属性标签 |
| 通用报错 | `permission denied` / `no such file` / `unrecognized option` 等经 `trs()` |

实现：`lang.c` 扩充 `es/en→zh` 词条，`shell.c` 约 242 处 `trs()` 调用点，
`about` 大标的中英文分支使用完全相同的 ASCII 字符（不受语言影响）。

> 注意：VGA text 后端用 128 个动态字体槽（0x80+2×slot）渲染汉字，
> QEMU 探针的 `read_screen()` 只保留 ASCII 32..126，因此**探针无法读取
> 中文文本**。中文正确性须在真机/VMware 屏幕或 gfx screendump 上目视核对，
> 不要因探针里中文断言 FAIL 就判定代码有问题。

## 2. 命令合并（收敛重复）

| 旧命令 | 新入口 | 说明 |
|---|---|---|
| `cat` | `edit -c FILE` | 打印整个文件 |
| `head` | `edit -c N FILE` | 前 N 行 |
| `tail` | `edit -c -N FILE` | 后 N 行 |
| `touch` | `edit FILE`（不存在则创建） | — |
| `rmdir` | `rm -d DIR` | — |

`cat`/`head`/`tail`/`touch`/`rmdir` 作为**退役别名**保留，执行时输出
`catos: 我们不支持此命令了，请使用: <新命令>`，不再有实际功能。
`edit` 内部仍调用 `cmd_cat/cmd_head/cmd_tail`（纯函数保留），POSIX 规格
允许 `edit -5 FILE` 这类负数位置参数。

`dir` 现在是 `ls` 的别名（同一 `cmd_ls`），两者都支持 6 种模式：
默认 / `-l` / `-t`(树) / `-lt` / `--color-scale` / `--blocks=perm,size,name`。

## 3. sudo 与裸名 PATH

- `sudo CMD [ARGS...]` 是内建命令，重入 `shell_exec()` 并把 `g_uid/g_gid`
  临时切到 `UID_ROOT`；要求 CAP_USERADM。v2.68.1 修 `sudo ls -l`：
  POSIX 校验器现在把 `sudo`/`run`/`echo` 等透传命令的第一个操作数之后
  的所有 token 当子命令参数，不再误判 `-l` 为 sudo 自己的选项。
- `PATH` 作为命令直接打印当前环境变量（`/bin` 等）。

## 4. 输入法（Shift 拼音）

- 唤出方式改为**单次孤立 Shift tap**（按下-抬起期间无其他按键），
  不再要求双击；组合键中的 Shift 不触发。
- 候选选择：`1-9` 选第 N 个、`0` 选第 10 个、`↑/↓` 循环、空格提交当前选中。
- ASCII 标点在中文模式下映射为 GB2312 全角标点（`ime_punct()`）。
- 修复中文状态下退格无效的问题。

## 5. 包签名（CPKG02 + RSA-512）

- 打包器 `tools/mkpkg.py` 升级到 `CPKG02`：204 字节头（含 64 字节签名），
  私钥 `tools/pkg_devkey.txt` 仅在宿主，内核只嵌公钥模数 `PKG_PUB_N`。
- 摘要是 header(140) + payload 的 FNV-1a64，编码为 `0x01<<56 | digest`，
  签名 `pow(m, d, n)`，验签 `pow(s, 65537, n)`。
- **v2.68.1 关键修复**：初版内核 bigint 有四重错误——`uint16_t` 累
  加溢出（64×255×255≈4.1M > 65535）、密钥大端与运算小端混用、
  模幂平方的是 base 而非 result、以及最隐蔽的：double-and-add 里
  `r<<1 | bbit` 后又 `t += a`，导致每个置位多算 +1（`1×sig` 竟等于
  `2×sig`）——任何包都验签失败、无法安装。
  重写为一致的 17×uint32_t 小端 512 位 bignum（正确的 double-and-add
  模乘：只 `t=r*2`，置位时才 `t+=a`；加正确的 square-and-multiply），
  `pkg install bc` 恢复正常。
  验证遵循"先出原型"规则：在宿主用 MinGW 编译等价 C bigint 原型，
  `1*sig==sig`、`pow(sig,65537,n)==m`（cmp=0）确认后才移植回内核。
- 文档 `docs/pkg-repo-design.md` / `SECURITY-v2.67.md` 中"CPKG01"和
  "无签名校验"的表述已过期，以 `mkpkg.py` 与 `shell.c` 为准。

## 6. gfx 模式查询与滚动

- `gfx mode`（别名 `gfx --query`）打印当前图形模式与行列数，例如
  `gfx mode: text cols=80 rows=25`。
- 命令行软换行、PgDn 逐行回滚、鼠标 sprite 压字修复继承自 v2.66。

## 7. 硬件核查结论（本轮确认）

- SATA/AHCI：未实现，当前为 IDE/ATAPI 路径。
- SMP/多核：未实现（`hwinfo cores 1`）。
- 硬盘多分区：未见完整支持，主要是 FAT32 单卷。
- 声卡：SB16 / ES1371 / ES1370，PCM 播放；`sndinfo` 的 period/avail/
  underrun、AC97 混音读取在无对应驱动时显示 `n/a`。

## 8. v2.68.1 / v2.68.2 / v2.68.3 热修复清单

1. `shell.c` bigint 重写（见 §5）——pkg 安装恢复。
2. `posix.c`：`sudo` 等透传命令的参数不再被误判为选项。
3. `posix.c`：`ls` 长选项规格补 `--color-scale=` / `--color-size=`，
   `ls -l --color-scale=size` 不再报 unrecognized option。
4. `shell.c`：`uname` / `date` 补中文 `trs()` 分支。
5. **v2.68.2：`shell.c:strncmp_()` 修复**——旧实现在 n 个字节全部相等后
   仍比较第 n+1 个字节，`strncmp_("perm,size,name","perm",4)` 返回
   `','-'\0'=44` 而非 0。这让 `ls` 的 `perm_first` 永远为假，`ls -l`
   只显示文件名、丢掉权限列和 size 列；同类精确前缀分派（`--blocks=`、

6. **v2.68.3：`shell.c:cmd_ls()` 的 `--blocks=` 表头缺列**——解析
   `--blocks=size,name` 时把逗号一并过滤掉，`blocks` 变成 `sizename`。

# CatOS v2.70 变更说明（pkg 远程仓库拉包）

v2.70 把包管理从"只能读磁盘本地仓库"扩展到"可以从 HTTP 远程仓库拉签名包"，

> SSH-2 服务端：本轮完成宿主可行性原型（`deliverables/ssh-prototype/`，

## 1. 新增命令

```
pkg repo [http://IP[:port]/dir]   # 无参查看；有参设置远程仓库 base URL（存 hive，重启保留）
pkg update                        # GET <repo>/PKGS.TXT 覆盖本地 /pkg/PKGS.TXT
pkg fetch NAME                    # 查索引文件名 -> GET <repo>/<file> -> 验签 -> 装 /bin/<cmd>.ce
pkg fetch http://IP[:port]/x.catpkg  # 显式 URL 直拉（不受索引限制）
```

`pkg list/info/install/remove` 语义不变；`help` 增加四行说明。

## 2. 网络层：二进制安全下载

- `netstack.c`：把 `net_http_get()` 的请求/收包/响应解析核心抽成
  `static int http_fetch(url, uint8_t* out, max)`，返回精确字节数、不追加 NUL。
  - `net_http_get()` 保留文本语义（`curl` 用）：`max-1` 截断 + NUL 结尾。
  - **新增 `net_http_download()`**：原样拷贝 body、零字节保留，供 `.catpkg` 使用。
- `tcp.rcv_buf` 从 4096 扩到 20480：整包（4–16 KiB payload + HTTP 头）可一次性接收，
  不再因缓冲满提前截断。
- `net.h` 增加 `net_http_download()` 声明与错误码说明。

为什么不能直接用 `net_http_get()`：它是 `char* out` + NUL 结尾，且按 Content-Length
截断到 `max-1`；`.catpkg` 头部/签名/payload 含大量 0 字节，会被当成字符串截断。

## 3. 验签零分叉

`shell.c` 把原来 `cmd_pkg_install()` 里的 magic/length 校验、`pkg_verify()`、写盘
抽成 `static void pkg_install_payload(int rd)`：
- 本地 `pkg install NAME`：从 `/pkg/<file>` 读到 `pkg_payload` → 调该函数。
- 远程 `pkg fetch ...`：`net_http_download()` 读到 `pkg_payload` → 调同一函数。

因此远程包**不可能绕过验签**：篡改 payload 任一字节，FNV-1a64 摘要改变，
RSA-512 `pow(sig,65537,n)` 与编码摘要不等 → "SIGNATURE VERIFICATION FAILED - install refused"。

# v2.71 变更说明 —— 内核 SSH-2 服务端

**主题**：CatOS 内核原生 SSH-2 服务端（`sshd` 命令）。宿主 OpenSSH / paramiko
可通过 QEMU slirp 端口转发（`hostfwd=tcp::2222-:22`）或 VMware NAT 直接连入，
拿到 CatOS shell（exec 单命令 + 交互式 shell 通道）。

## 新增

### 1. 密码学原语（`crypto.c` / `crypto.h`，~950 行）

全部 C 实现，无外部依赖；宿主自测（`-DCRYPTO_SELFTEST`，mingw32 i386 与内核
同 32 位同源码）12 项全 PASS，Ed25519/X25519 经 libcrypto（`cryptography`）
逐字节交叉验证：

| 原语 | 说明 |
|---|---|
| SHA-256 | 空串 / `abc` / 63B / 119B 边界回归全过 |
| HMAC-SHA256 | RFC 4231 用例验证；支持两段拼接消息（MAC 用） |
| AES-128-CTR | S-box 运行时生成（GF(2^8) 逆 + 仿射）；**128 位大端计数器跨包连续 keystream**（RFC 4344 SDCTR，OpenSSH 兼容）；FIPS C.1 逐轮对照 |
| SHA-512 / X25519 / Ed25519 | TweetNaCl（公有领域）逐字移植（gf[16] 字段运算、ge_add、modL 等）；X25519 agreement 与 libcrypto 一致 |
| `crypto_random` | rdtsc 混合 xorshift64*（演示级熵，v2.71 可接受） |

### 2. TCP 服务端（`netstack.c` / `net.h`）

独立 `tcps` 上下文，与既有 TCP 客户端共存：
`net_tcp_listen(port)` / `net_tcp_saccept()` / `net_tcp_ssend()` /
`net_tcp_srecv()` / `net_tcp_srecv_all()` / `net_tcp_sclose()`。

- SYN→SYN+ACK→ESTABLISHED 三段握手；**握手 ACK 可能捎带首个数据段
  （客户端 banner），必须 fall-through 处理**（否则双方互等死锁）。
- 接收缓冲 16KB，带去前缀压实；`srecv_all` 精确 n 字节阻塞读（~30s 空闲超时）。

### 3. SSH-2 协议栈（`ssh.c` / `ssh.h`，~780 行）

忠实移植宿主原型 `deliverables/ssh-prototype/sshd_min.py`（v2.70 已验证）。
曲线 `curve25519-sha256`，主机密钥 `ssh-ed25519`，加密 `aes128-ctr`，
MAC `hmac-sha2-256`（非 EtM）。要点（header 注释 8 条铁律）：

1. 交换哈希 H = SHA256(s(V_C)‖s(V_S)‖s(I_C)‖s(I_S)‖s(K_S)‖s(q_c)‖s(q_s)‖mpint(K))，
   全部字段带 4 字节长度前缀；**I_C/I_S 含 msg 字节 20**。
2. Ed25519 直接签 H；sigblob = s("ssh-ed25519")‖s(sig64)。
3. 密钥派生 `SHA256(mpint(K)‖H‖letter‖H‖prev)` 链式；收向 A/C/E，发向 B/D/F。
4. aes128-ctr 加密**整包（含 4 字节长度字段）**，CTR keystream 跨包连续。
5. MAC = HMAC(mac_key, seq‖明文包)。
6. **padding 按 16 对齐**（RFC 4253 §6：整包必须是 cipher block size 或 8
   的较大者 = 16）。⚠️ 8 对齐会被 OpenSSH（`padding error: ... mod N`）与
   paramiko（`Invalid packet blocking`）同时拒绝——原型侥幸全落在 16 上。
7. SERVICE_REQUEST/ACCEPT 在 NEWKEYS 与 USERAUTH 之间完成。
8. channel request 体：recipient(4) 再 string type。

**一条连接多通道**：paramiko 在同一 TCP 连接上复用通道（exec 之后开 shell），
serve 循环按通道服务直到 DISCONNECT/断连；`pty-req`/`window-change`/`env`
回 SUCCESS（paramiko `_request_failed` 会直接关通道，不能回 FAILURE）。

### 4. shell 集成（`shell.c`）

- `sshd` 命令：net_up → DHCP → listen(22) → accept 循环；ESC 退出
  （必须用 `kb_getkey_timed(2)`，`kb_getkey` 遇修饰键永久阻塞）。
- `shell_ssh_exec_line()`：tee 捕获控制台输出（`\n`→`\r\n`）、
  `g_script_mode=1` 防分页阻塞、`g_last_rc` 回传退出码。
- 未知命令补 `g_last_rc = 127`（POSIX 惯例，SSH exit-status 需要）。

# v2.72 补充说明（VMware 反馈轮）

本轮针对 VMware 上反馈的三条渲染现象 + 一条声卡现象做处理，并把 v2.72 里

## 1. 字体底色 ≠ 背景色（渲染 #4）

`boot_apply_videomode()` → `pal_apply_scheme()`。前者切到 vbe24 时用当时的
背景色（默认 `#0C0C0C`）清了一整帧；后者随后把 `PAL_BG` 换成注册表里的主题色
（例如 `#0A0E14`）。**之后只有被"写"过的单元格用新底色，没人重画的地方还是旧底色**，
于是字块和背景出现色差，且留下一个矩形边界。

修法两条：
1. 启动顺序改为 **主题先应用，再切显示模式**；
2. `pal_apply_scheme()` 结尾调用新增的 `con_repaint_frame()`：
   `be->clear(s_bg_rgb)` + 全格重绘，文字不丢，整帧同色。

`con_clear()` 不能用——它会把文字一起清掉。

## 2. 开机几秒的频闪（渲染 #2）

同一条链路上还有两次多余的全屏清屏：

| 位置 | 原来 |
|---|---|
| `v24_enter_svga()` / `v24_enter_bochs()` | 切模式后再 `gfx24_clear()` 一次 |
| `v24_set_scale()` | 又被 `size_restore()` 调起，再清一次 |
| `switch_backend()` → `redraw_all()` | 又 `be->clear()` 一次 |

在 VMware SVGA 上每一帧都会被宿主以 25 Hz 重贴（`svga_tick()` → `svga_flush()`
发 `SVGA_CMD_UPDATE` 全屏矩形），所以**连续三次全屏清空=肉眼可见的闪三下**。
现在只保留 `redraw_all()` 那一次，`enter()` 与 `set_scale()` 都不再清屏。

## 3. 分辨率"不严丝合缝"（渲染 #3）

先把事实钉住：`svga_mode_set()` 本来就会回读 `SVGA_REG_WIDTH/HEIGHT` 并在
不一致时 `goto fail`，所以**"要 800x600 却真给了别的尺寸"这条路不存在**。
截图里那块颜色不同、边界正好 640x400 的矩形，是上面第 1 条留下的旧底色
（640x400 = 80×25 文本模式的像素范围，正好是切换前那一帧的大小），不是
"VMware 给的屏幕比要的小"。

因此这一条的修法就是第 1 条：整帧统一重绘，边界自然消失。另外为了以后能从
日志而不是截图定位，启动时多打一行真实几何：

```
[display] boot mode: vbe24 (800x600, 100x37 cells @8x16)
```

`vdiag` 里仍然有 pitch/stride/lfb/bar 的原始值。

## 4. 声卡（VMware ES1371 无声）

**没有盲改。** 现状是拿 ES1370 的寄存器布局去编程 ES1371：DAC1 走
MEMPAGE=0xc 窗口的 `0xc30/0xc34`、采样率走 `CTRL` 的 `WTSRSEL` 两位。
ES1371 的 AK4531 codec 是**只写**接口，读不回来；没有实机读数就写序列，
等于把"没声音"换成"可能是另一组寄存器写坏了"，而且无法验证。

本轮加的是取证工具：`sndregs` 直接打印原始寄存器。

```
snd: ensoniq id=1274 dev=5000 io=0xc000 irq=11 ready=1
  CONTROL=0x100  STATUS=0x60  SERIAL=0x83
  SCOUNT=0x0  FRAMECNT=0x0  PORT20=0xd3
  rate=5512 bufsz=65536
```

判读方法（也已写在命令输出里）：

- 播放时 **FRAMECNT 不动** → DMA 根本没被 arm（寄存器布局/采样率编程错）；
- 播放时 **FRAMECNT 在动但没声** → AK4531 仍处于静音，需要 codec 初始化。

`dev=1371` 时命令返回 `$?=3`（"设备认出来了，通路未验证"），不会假装成功。

## 5. 删除 sshd 开机自启动

`sshd` / `sshd -d` 手动启动仍然可用。理由：一个开机就监听的 :22，加上尚未
做签名校验的 `pkg` 通路，是负债不是特性。

## 第二轮（VMware 实机回读后的追加修复）

实机两张截图说明第一轮「整帧重绘」**没有解决**底色不一致，只是换了个样子：
截图 801×599 里，x 0..640 / y 0..400 是 `#0A0E14`（单元格底色），其余仍是
`#0C0C0C`（旧的清屏色）。边界 640×400 正好是 80×25 × 8×16 —— 也就是
**切模式那一刻的旧网格**。

结论：模式切换过程中的某一次 `clear + redraw` 用的是切换前的网格几何
（80×25），于是整帧只有 640×400 被刷成主题底色；之后 `size_restore()`
把网格改成 100×37，但没有任何一次「以最终几何整帧重刷」，剩下的一圈
永远是旧底色。同理，`vdiag` 报告 `pitch=0xC80`(3200)、`800x600`，
说明模式协商本来就是对的 —— 看到的「不严丝合缝」是这块残留，不是分辨率错。

修法：`boot_apply_videomode()` 在 `size_restore()` **之后**、
打印 boot 几何行之前，补一次 `con_repaint_frame()`（整帧 `be->clear(主题底色)`
+ 全格重绘）。这是最后一句话的时机，之后的输入不会再改变底色。

另加 `fprobe`：整帧填黑 + 四角四色块 + 四边框。VMware 上跑它即可判定
「宿主显示面是否真等于我们编程的模式」：角块被切掉 = 宿主面更小（问题在
SVGA 模式设置）；四个角都在 = 面正确，问题只在控制台绘制路径。

## 第三轮（定时任务复查时追加）

- `sndmap`：**只读** dump 整个 `0x00..0x3C` 寄存器窗口（每次 4 字节）。
  读操作不改变器件状态，所以在 VMware 的 ES1371 上也是安全的。用途：
  确认哪些偏移是真正可回读的 RW 寄存器。实机 `sndregs` 已给出
  `PORT20=0x83`（我们写的是 `0x0c`），说明 ES1370 那套偏移映射在这颗

## 第四轮：静态分析定位到根因（两套背景色）

用户反馈澄清了关键事实：**文字是按屏幕宽度排的（网格 100×37 正确），只有背景色
没铺满屏**。因此不是分辨率协商问题，也不是"字体底色"问题，而是**画布底色有两套，
互相不一致**。

证据链：
- `render.c` 的内建主题 `g_dark_tokens[0]`（canvas）= `#0A0E14`；
  它在 `con_init()` 末尾 `con_apply_theme(1)` 里生效，并把
  `s_bg_rgb` 设为 `#0A0E14`；
- `palette.c` 的 `k_defaults[PAL_BG]` 与 hive 种子
  `HKLM\Software\CatOS\Terminal\Colors\Background` = `#0C0C0C`；
  v2.67 起开机走 `pal_apply_scheme()` + `con_set_style_rgb(pal_rgb(PAL_BG))`，
  于是 `s_bg_rgb` 又变成 `#0C0C0C`；
- 单元格在写入时**快照**当时的 `s_bg_rgb`（`cell_blank`/`cell_set` 复制到
  `c->bg`），所以先落的格子带 `#0A0E14`、后落的带 `#0C0C0C`；
  `redraw_all()` 还会跳过 `cp==0 && bg==clear_bg` 的空格——被跳过的地方就永远
  留着另一套颜色。屏幕上表现为"文字区域是深蓝黑、其余是灰黑"的补丁状边界。

版本对照：v2.66 只有 `con_apply_theme()` 一个来源（单套颜色），从不出问题；
v2.67 引入 hive 颜色角色作为第二来源 → 问题开始；v2.68.1 之后一直继承。

修法（三处，同一件事：只留一个"背景"定义）：
1. `palette.c`：`k_defaults[PAL_BG]` 与静态初值改为 `0x0A0E14`，与内建主题对齐。
2. `hive.c`：种子 `Colors\Background` 改为 `#0A0E14`。
3. `render.c::con_set_style_rgb()`：背景色变化时，把**所有** `bg == 旧默认色`
   的格子重新盖成新色（显式设置过背景的面板/反显不受影响）；
   `theme` 命令与开机流程随后各补一次 `con_repaint_frame()`。

验证（QEMU `-vga std`，整帧 4 像素步进统计）：修前存在 `#0C0C0C` 与 `#0A0E14`
两种底色；修后整帧只剩 `(10,14,20)` 一种底色（另加文字色），`uniq=4`。

## 第五轮：补上"颜色可运行时修改"这条链

原先的设计缺口（用户实测发现 `reg set` 改底色"没反应"）：
1. `pal_reload()` 写了却没有任何调用点 → 颜色只在开机 `pal_init()` 读一次，
   改完必须重启；
2. 开机还会 `pal_apply_scheme(Theme)` 把整张角色表按内置方案重写，
   **用户刚用 `reg set` 写进 `Colors\Background` 的值会被无声覆盖** ——
   看上去就是"注册表改了没用"。

改法：
- 开机不再重放 scheme：hive 是唯一事实源，`Theme` 仅作标签；
  `theme <name>` 仍是"整表重写"的显式入口。
- 新增 `colors` 命令（补齐运行时的另一半）：
  - `colors` 从 hive 重读全部角色 → `con_set_style_rgb` → `con_repaint_frame()`，立即生效；
  - `colors save` 持久化；
  - `colors reset` 恢复内置默认并应用（新增 `pal_reset()`）；
  - `colors set <role> <#RRGGBB>` 写单个角色并立即重绘。
- 命令表 / TAB 补全 / help 均已登记。

验证（QEMU `-vga std`，整帧 4 px 步进统计）：
- 开机画布 (10,14,20) = `#0A0E14`，`uniq=4`；
- `colors set background #101418` 后整帧变 (16,20,24)，`uniq=5`（只有画布那一色变了）；
- `colors reset` 后回到 (10,14,20)。

### 2. 鼠标滚轮滚动时指针瞬移到左下角（根因已定位，非猜测）

`mouse_init()` 里 IntelliMouse 协商写的是：

```
aux_write(0xF2);                  /* identify */
wait_out_full();
uint8_t id = inb(PS2_DATA);       /* ← 读到的是 0xFA(ACK)，不是设备 ID */
if (id == 3) { wheel_mode = 1; pkt_size = 4; }
```

设备对 `0xF2` 先回 ACK(0xFA)，再回 ID(0x03/0x04)。旧代码只读一个字节，于是 `id` 恒为 `0xFA`，
`wheel_mode` 恒为 0、`pkt_size` 恒为 3；而 200/100/80 已经让设备切到 **4 字节滚轮包**。
结果每第 4 个字节（滚轮半字节）被当成下一个包的标志位，后续字节被当成 dx/dy —— 一次
200+ 像素的假位移，再被 `MOUSE_MAX` 夹紧，指针就"瞬移"到左下角；乱序字节还会让
sprite 的存档/恢复错位，把行首字符擦掉（用户 `ping` 第三行 `eply` 丢 `r` 极可能同源）。

修复：
- 新增 `init_inbox` + `init_mode`：协商期间 IRQ12 顶半把 aux 字节存进 inbox，初始化代码
  从 inbox 取，杜绝"ISR 抢字节"造成 ACK/ID 丢失。
- `aux_read_ack()` 校验 0xFA（不再盲读），`aux_read_byte()` 遇到键盘字节转交 kbd。
- `0xF2` 之后 **先读 ACK 再读 ID**，最多两次协商；ID=3 或 4 才 `wheel_mode=1, pkt_size=4`。
- `mouse_feed()` 的字节 0 校验从 `bit3` 收紧为 `(b & 0xC8) == 0x08`，错帧不再起包。
- `mouse` 命令新增 `id= / wheel= / pkt=` 三项，可直接核对协商结果。

QEMU 实测：`mouse: ... id=3 wheel=1 pkt=4`，6 次 `mouse_move 30 -30` 后 `x=580 y=120`（精确 +180/-180），无瞬移。

### 3. 彻底修复 `curl` 不可用

v2.70 客户端的三个硬伤：

| 现象 | 原因 | 修复 |
|---|---|---|
| `curl baidu.com` 直接失败 | `http_parse_url()` 强制要求 `http://` 前缀 | 协议头可省略，缺省 http |
| `curl http://baidu.com/` 只有 57 字节"空页" | `3xx` 当错误码 -4 返回，不跟跳转 | 最多跟随 4 跳；相对/绝对/`//` 形式 Location 都支持 |
| 部分站点响应被截断 | `Transfer-Encoding: chunked` 被原样拷贝 | 新增 `http_dechunk()` 解码 |
| https 站点报"连不上"，误导 | https 被当成坏 URL | 明确返回 -7 + 打印 Location，提示"未实现 TLS" |

另外：`Host` 头改用解析出的 host（不再假设 `url+7`）、新增 `Accept: */*` 与
`Accept-Encoding: identity`、`curl` 输出头改为 `--- URL (HTTP nnn) ---`，
失败时打印真实状态码与 Location。

QEMU 实测（`-netdev user -device e1000`）：

```
curl example.com/                 → HTTP 200, 977 bytes
curl 10.0.2.2:8099/redir          → 302 跟随 → HTTP 200, local-server-ok
curl 10.0.2.2:8099/chunk          → chunked 解码 → chunked-body-ok, 16 bytes
curl 10.0.2.2:8099/404            → error -4 + "server answered HTTP 404"
curl http://baidu.com/            → error -7 + Location: https://www.baidu.com/
```

# CatOS v2.76 变更说明（2026-11-22）

## 1. 终端交互三项

### 1.1 输出滚动时按任意键跳过（A5.1）

以前 `help` / `tree` / `cat` 这类长输出只能等它自己刷完，期间按的键都排在扫描码队列里，
刷完才回到输入行。现在 `pager_line()` 在"已经打满一屏"之后检查一次是否有真实按键
（`kb_key_pending()`，只看按下码，忽略松开码和 0xE0/0xE1 前缀，避免被启动命令的那下回车误触），
命中就标记 aborted 并停止本条命令的剩余输出，其余调用方早已 `pager_quit()` 检查，自然中断。
被按下的那个键不消耗，原样交给行编辑器；`shell_exec` 打印一行提示后回提示符。

- 重定向输出（`help > f`）时**禁用**跳过：否则文件会被截成半截。
- 探针验证：`help` + typeahead `x` → 输出停在当屏，提示"（输出已跳过：剩余内容未显示，键入的按键已保留）"，提示符上出现 `x`。

### 1.2 滚动历史 96 → 10000 行（A5.2）

`CON_SB_ROWS` 从 96 提到 10000。原结构 `con_cell_t` 每格 20 字节，100 列 × 1 万行 ≈ 20 MiB，
而 BSS 会被零填充进 flat 内核镜像，等于每次开机多背 20 MiB。所以历史格改为 8 字节紧凑格
（`cp` + `fg_idx` + `bg_idx` + `attrs` + `flags`），回显时用 `render_clut()` 还原 RGB。

- 代价（如实说明）：用 `con_set_style_rgb()` 设的自定义颜色，在**历史行**里显示为调色板中
  最接近的颜色；当前画面不受影响。UI 配色本身走调色板角色，无感。

### 1.3 滚轮 / PgUp 卡顿（A5.3）

根因不是鼠标驱动，是 `con_scrollback()` 的实现：它按行步进，每一步都把整个 cell 网格移位、
把所有行的脏标记清掉、再整屏重绘。一个滚轮档口是 24 行（`w > 8` 时按 24），PgUp 一页是
`rows-1 ≈ 35` 行 → 单次按键触发 24~35 次全屏重绘。

改法：直接算目标 `sb_view`，一次把所有网格行从归档/活动快照重建，然后只重绘一遍。
开销从 O(位移 × rows × cols) 降到 O(rows × cols)/事件；回到底部时仍是逐字节还原的活动网格
（探针：3 次 `help` 后连按 8 次 PgUp 仍能看到最早输出，回滚 9 次 PgDn 后画面与滚动前一致）。

# CatOS v2.77 变更说明（2026-11-22）

本轮做完 5 条待办（E11 / E1 / F6 + 两条现场反馈），D2、D10 明确未完成。

## 1. E11 — `rm -r` 嵌套递归（#155）

旧实现直接在 `fs_foreach` 的回调里递归删除，等于"边遍历自己边拆自己"：FAT 目录项槽位一旦释放就会被下一次分配复用，父层迭代器可能拿到被复用的槽位，结果是要么漏删、要么同一名字删两次。

新实现分两阶段：先用 `fs_enum_entries()` 把该层名字拍成快照（按深度分桶，`FSREC_DEPTH_MAX+1` 层、每批 32 个），再对快照逐个删/递归；一批做完重扫一层，删除期间不持有目录流。

验收：`mkdir -p /u/a/b/c` + 3 个文件 → `rm -r /u` → `fsck` 输出 `FAT mirror OK` / `directory tree OK`。

## 2. E1 — 包签名强校验 + UnknownBinary 拦截

- 摘要：`FNV-1a64`（非密码学哈希，64 位碰撞即可伪造）→ `SHA-256(header||payload)` 截 56 位（RSA-512 的模数下只能放这么多）。内核新增 `sha256_2()` 增量实现，`tools/mkpkg.py` 同步改为同一算法，两边必须一致否则安装全失败。
- 安装前三道闸：命令名只允许 `[A-Za-z0-9_-]`（旧代码把它直接拼进 `/bin/<cmd>.ce`，`../` 可穿越）；载荷必须是 `CE01` 头；`image_size == payload_len - 20` 且 `entry < image_size`。
- 验收：重建磁盘镜像后 `pkg install bc` / `pkg install rps` 均 `installed … -> /bin/xx.ce`；用旧摘要签名（v2.76 及以前的镜像）安装被 `SIGNATURE VERIFICATION FAILED - install refused` 拒绝——顺带证明强校验生效。

## 3. A5.4 — IME 候选框不再跟着滚动

候选框画在 `rows-2` / `rows-1` 两行里（原内容暂存后由 `con_status_bar_off()` 还原）。任何网格移动都会把那两行一起卷走，所以"滚动时候选框跟着跑"。现在：

- `scroll_one()`（输出换行）与 `con_scrollback()`（滚轮 / PgUp）先摘框、移动、再 `con_status_bar_reapply()` 钉回新底部；
- `bar_active` 语义改为"有文字可重画"，`con_status_bar_off()` 不清文字；IME 关闭走 `con_status_bar_forget()`，否则滚一次旧候选框就会复活。

验收：`help` 输出后 F2 + 输入 `ni` → 候选框在底部；连按 PgUp 两页，候选框依旧钉在底部，视口内容正常滚动。

## 4. B12 — 中文标点两个问号

IME 标点表原本直接吐 GB2312 双字节（`。` = `0xA1 0xA3`）。控制台按 UTF-8 取码点，两个字节都 >0x7E 且无字形，于是各画一个 `?`——一个中文句号占两格、显示两个问号。标点表已改成 UTF-8 码点（`。` → U+3002，`,` → U+FF0C…），字库子集本来就有这些字形。

验收：F2 开启后依次敲 `. , ? !`，得到 `。 ， ？ ！` 各占两格，不再有 `??`。

## 5. D11 — `shutdown` 之后自动重启

`cmd_shutdown()` 的兜底就是 `outb(0x64,0xFE)` 冷重启，所以"自动重启"= ACPI 关机没生效。两个根因都修了：

1. ACPI 2.0 固件在 legacy 模式（`PM1_CNT.SCI_EN=0`）会忽略 PM1_CNT 写入，必须先写 FADT 的 `SMI_CMD` + `ACPI_ENABLE` 再等 SCI_EN；QEMU 出厂已是 ACPI 模式，VMware 不是。
2. 旧代码把 `SLP_TYP 0..7` 全带 `SLP_EN` 写一遍，错误类型在部分芯片组会被解码成平台复位——这本身就会重启。

现在只写固件 `\_S5` 的 SLP_TYP，不生效再退 5、7 各一次。**关机/重启类操作在云端执行环境被禁止，无法实测，需 VMware 真机复核。**

## 6. 未完成（如实记录）

- **D10 包体大小**：上限不在 `fs_write_raw_mode`，而在下载链路——`pkg_payload[16 KiB]`、`tcp.rcv_buf` 一次收完整个响应、`http_fetch()` 整块拷贝。真解要 TCP 边收边排空 + HTTP 增量解析 + 边下边落盘，本轮未做。
- **D2 HTTPS/TLS**：基元齐（SHA-256/HMAC/X25519/AES-128-CTR/RSA），缺记录层、CBC 套件、X.509 解析与验签。验收标准定为 `openssl s_server` 端到端跑通，不能用"能连某网站"糊过去；本轮未做。

## 1. D2 — HTTPS / TLS 1.2 客户端

### 实现

- **新模块** `kernel_v25/src/tls.c` + `include/tls.h`：TLS 1.2 客户端，只实现验收所需的
  `TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA256`（0xC027）。
  - 记录层：16 KiB 明文分片、CBC 记录 MAC-then-encrypt，MAC 输入
    `seq(8)||type(1)||version(2)||length(2)||plaintext`，解密后常数时间比较；
    seq 双向独立递增。
  - 握手：ClientHello（`supported_groups: secp256r1` + `signature_algorithms`）、
    ServerHello、Certificate（跳过内容）、ServerKeyExchange（取 curve=23 与 65 字节
    `0x04||X||Y` 公钥）、ServerHelloDone、ClientKeyExchange、CCS、Finished；
    **服务器 Finished 的 transcript 哈希包含客户端 Finished**，逐字节校验。
  - 密钥派生：ECDH 共享 x 坐标 → `master_secret` → `key_block`，PRF 为 P_SHA256，
    其中 `A(0)=label||seed`（本轮修掉的根因之一）。
- **vendor 依赖**（`src/third_party/`）：
  - `uecc/` — micro-ecc（secp256r1 ECDHE，固定 4 字节 limb，其余曲线关闭）；
  - `tiny-aes/` — tiny-AES-c（AES-128-CBC 加解密）。
  二者均在主机侧与 Python `cryptography` / NIST SP800-38A 向量交叉验证后才进内核。
- **接入** `src/netstack.c`：`http_parse_url()` 识别 `https://`（默认端口 443）并通过出参
  回传；`http_fetch_once()` 在 https 时直接调 `tls_https_get()`，明文 HTTP 路径不变。
- `curl` 用法/提示同步更新（不再声称"仅支持明文 http"）。

### 验收（端到端）

```
openssl s_server -accept 8443 -cert <self-signed> -key <key> \
                 -tls1_2 -cipher ECDHE-RSA-AES128-SHA256
# QEMU: -netdev user,id=n0 -device pcnet,netdev=n0
root@catos:/# netcfg 10.0.2.15 10.0.2.2 10.0.2.3
root@catos:/# curl https://10.0.2.2:8443/
--- https://10.0.2.2:8443/ --- CATOS_TLS_OK_278 --- 16 bytes ---
```

截图证据：`artifacts/d2-tls/tls_probe.png`；脚本 `tests/tls_probe.py`（自带 s_server + QEMU + 判定）。

### 已知限制（重要）

- **仅加密、未验签**：不解析证书链、不做主机名校验、不校验 ServerKeyExchange 的 RSA
  签名，无信任锚。**可被中间人冒充**；X.509 DER 解析 + RSASSA-PKCS1-v1_5(RSA-2048)
  验签列为下一阶段（仓库现有包签名 bignum 仅 512 位，需另写 2048 位实现）。
- 仅 TLS 1.2 / 套件 0xC027 / 曲线 secp256r1；不支持 TLS 1.3、会话恢复、SNI、

- 单连接、阻塞式、静态缓冲（无 malloc）；响应体一次性读入调用方缓冲（不流式）。
- `https://` 的**重定向目标**仍返回 `-7`（不支持跨协议跳转）；流式下载入口

### 附带修复：用户虚存区物理切片被帧分配器复用（内核级）

大镜像验收时出现"任务 `exit(0)` 但零输出"，根因不在下载链路：

- 内核对象帧（VMA 节点、页目录/页表）按物理地址 first-fit 分配后被**当作恒等映射指针**
  解引用；而 ring3 任务 CR3 下 `0x2000000..0x2800000`（PDE 8/9）走任务私有页表，
- 大镜像把内核对象帧推到该物理切片内，指针被别名到任务镜像页，`validate_uaddr()`
  读到的是 blob 字节，首个 syscall 即崩溃。
- 修复：`src/paging.c::paging_init()` 把该物理切片标记保留、不交给帧分配器；
  任务帧仍经页表项映射（不要求 phys==virt）。小镜像下这一别名窗口同样存在，属潜在
  长期 bug，本轮一并堵上。

## 二十五、v2.38 P0 4GB 内存支持（跨夜分片）

- **设计权衡（务实落地，未做内存动态化重构）**：沿用既有“内核虚拟地址
  = 物理地址”恒等映射假设，把 PSE 恒等映射范围从固定低 64MiB 扩展到
  multiboot mem_upper 实际报告的 RAM 上界，封顶 4GiB；帧分配器位图按
  4GiB 上限静态预留（32768 字 / 128KiB BSS），只管理 frames_base..mem_top。
  不引入每帧内核窗口、不取消恒等映射（ROADMAP 诚实清单 #1/#3 的重构项
  仍 deferred）。
- **32 位边界处理**：KB→字节用 uint64 中间量换算，避免 mem_upper<<10
  在近 4GiB 回绕；4GiB 本身不可表示，上界封顶 0xFFFFF000。
- **探测链路排查**：截断点共两处——hw.c HW_MEM_TOTAL_KB 钳到 63MiB、
  paging.c top 钳到 64MiB；均已去除。shell `mem` 命令直读 mbi 本来就如实，
  仅补打 PMM used/free 帧。
- **已知限制（遗留）**：① multiboot mem_upper 只统计 1MiB 以上的连续低
  内存，PCI hole 之上的第二段 RAM（mmap 表区域）本内核未解析，大内存
  客户机显示总量仍小于 `-m` 标称值，属如实反映；② 真 4GiB 客户机可能把
  PCI BAR 放进最后 4GiB 块，当前恒等映射未避让 MMIO，需后续内核窗口方案；
  ③ 本机 cgroup 内存上限 4GiB，无法实跑 `-m 4096`，最大验证档 3840MiB

- **遗留项 #122/#123**：#123 ata_read_sectors DRQ 失败改为返回 -1（与写

- **内建符号表（#204）**：`tools/gen_symtab.py` 构建期从 `nm` 读 T/t 符号、去前导下划线、按地址排序，生成 `src/symtab.inc`（`.rodata`，约 785 符号）；`bsod_sym_fmt()` 二分查最近符号+偏移，蓝屏与 `crashlog` 摘要共用；build.sh 编译前先临时链接 PE 取符号（干净树首构兜底）。
- **单键交互（P1-6）**：8042 扫描码直解（只认 ASCII，忽略 break code）：R 触发崩溃动作、D 完整寄存器、S 栈回溯全文、M 内存映射/CR3 摘要、P 排队转储（仅显示 `dump queued`）、A 全核状态（SMP deferred 占位）、C 继续（RECOVER: NO 时拒绝并提示不可继续）；F1 保留 faultinfo 页。输入法强制关、无句子级命令、无子提示符；页面切换整屏重绘，不做增量滚动。
- **转储与事后诊断（P1-7 / #205）**：panic 路径不写 FS；预留 bss 固定区 `panic_record_t`（magic `CPN1`：tick/向量/EIP/CR2/ERR/EFLAGS/ESP/栈顶 5 帧/版本/原因）。下次正常启动内建 `crashlog` 读取并符号化显示摘要；`crashlog --full` 才出原始片段并附敏感数据策略提示；无记录提示 `no crash record`。固定扇区转储 deferred。

### P2 增强（尽力项）
- 标题反显（`!!! PANIC !!!` 白/蓝反显行），无颜色也可读；配色仅增强；蓝屏路径禁光标闪烁/进度条/动画；IME 候选区不进入。
- 窄屏（<60 列）/串口只显示核心摘要（向量/EIP/原因/提示），不做双列布局与栈转储。
- SMP 接口占位（#207）：per-CPU 快照槽位、NMI/IPI 停核标记数组、`[CPU n]` 串口前缀；UP 构建只采样 CPU 0，cpus 页标注 deferred。
- `/etc/panicmode` 扩展支持 `reboot|halt|wait` 与 `reboot:<Ns>` 倒计时秒数形式；启动期缓存，崩溃路径不开文件；开发版默认 `wait`。
