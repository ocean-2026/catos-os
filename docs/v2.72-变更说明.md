# v2.72 变更说明 —— sshd 开机自启动 + host key 持久化

**主题**：v2.71 的 SSH 服务端升级为"开箱即连"：开机自动启动 sshd 守护进程，
宿主机第一次连接后 host key 持久保存，known_hosts 校验跨会话稳定。

## 新增

### 1. ring0 内核线程生成 API（`task.c` / `task.h`）

`int task_spawn_r0(void (*entry)(void), const char *name, int daemon)`：

- 与 idle 伪任务同款的协作式切换帧（pop edi/esi/ebx/ebp + ret → entry），
  ring0、root 全能力位、无独立地址空间
- entry **永不返回**（帧内无退出跳板）；线程必须在阻塞点调用
  `task_maybe_yield()` / `task_block()`（内核 ring0 非抢占）
- daemon=1 时在 `jobs` 中以 `D` 标记显示，输出进 per-task log ring

### 2. sshd 守护进程模式（`ssh.c` / `shell.c`）

- `sshd_daemon_main()`：等网卡就绪 → DHCP → 监听 22 → 永久 serve，永不返回
- `sshd -d`：前台命令同样能拉起守护进程（`[daemon tid N] sshd`）
- 不带参数的 `sshd` 仍是前台模式（ESC 停止，v2.71 行为不变）

### 3. 开机自启动（`boot_autostart`）

- `/etc/autoexec` 的 `@` 前缀守护行此前只能启动磁盘上的 `.ce` 程序；
  v2.72 增加**内置命令守护分支**：`@sshd` 直接 `task_spawn_r0`
- 新卷自动播种 `/etc/autoexec/sshd.sh`（内容一行 `@sshd`；
  `fs_write_raw` 对已存在文件跳过，老卷行为不变）
- 注意：自启动需要盘上有 FAT32 卷（无卷时 `boot_autostart` 直接返回）——
  **空盘时第一次开机要 `format` 后重启一次**，之后每次开机自动 sshd

### 4. host key 持久化（`ssh.c`）

- `/etc/ssh_host.key` 保存 64 字节 Ed25519 私钥（sk[0..31] 种子 +
  sk[32..63] 公钥）；首次使用时生成并写盘，之后每次会话加载
- 客户端 known_hosts 条目跨会话有效，不再需要 `StrictHostKeyChecking=no`
- 无盘（fs 未就绪）时优雅降级为每会话临时密钥

## 验证

`tests/ssh_v272_probe.py`（带 FAT32 磁盘：format → guest `reboot` → 全自动）**5/5**：

1. autostart：`jobs` 里有 `D sshd`，全程未敲过 sshd 命令
2. exec：宿主 ssh 直连开机守护进程，echo marker 返回
3. host key：首次连接 `accept-new` 存 key，第二次 `StrictHostKeyChecking=yes`
   强校验重连成功（key 未变）
4. `/etc/ssh_host.key` 存在
5. 守护进程跨会话持续服务

回归：`tests/ssh_v271_probe.py` 6/6（前台 sshd 路径不变）。

## 已知限制

- 一个守护进程实例同一时刻只服务一个会话（tcps 单上下文）；并发第二连接
  需等第一会话结束
- `reboot` 后 VMX 指向的 ISO 决定内核版本；空盘开机需 format+重启一次
  才有自启动
- VMware NAT 端口转发（vmnetnat.conf `[incomingtcp]`）仍需管理员手动配置

## 部署

`catos-v2.72.iso` + `kernel-v2.72.bin`，VMX `ide1:0.fileName` 已指向 v2.72。
