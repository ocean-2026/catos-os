# CatOS v2.77 变更说明（2026-11-22）

本轮做完 5 条待办（E11 / E1 / F6 + 两条现场反馈），D2、D10 明确未完成。

## 1. E11 — `rm -r` 嵌套递归（#155）

旧实现直接在 `fs_foreach` 的回调里递归删除，等于"边遍历自己边拆自己"：FAT 目录项槽位一旦释放就会被下一次分配复用，父层迭代器可能拿到被复用的槽位，结果是要么漏删、要么同一名字删两次。

新实现分两阶段：先用 `fs_enum_entries()` 把该层名字拍成快照（按深度分桶，`FSREC_DEPTH_MAX+1` 层、每批 32 个），再对快照逐个删/递归；一批做完重扫一层，删除期间不持有目录流。

验收：`mkdir -p /u/a/b/c` + 3 个文件 → `rm -r /u` → `fsck` 输出 `FAT mirror OK` / `directory tree OK`。

## 2. E1 — 包签名强校验 + UnknownBinary 拦截

- 摘要：`FNV-1a64`（非密码学哈希，64 位碰撞即可伪造）→ `SHA-256(header||payload)` 截 56 位（RSA-512 的模数下只能放这么多）。内核新增 `sha256_2()` 增量实现，`tools/mkpkg.py` 同步改为同一算法，两边必须一致否则安装全失败。
- 安装前三道闸：命令名只允许 `[A-Za-z0-9_-]`（旧代码把它直接拼进 `/bin/<cmd>.ce`，`../` 可穿越）；载荷必须是 `CE01` 头；`image_size == payload_len - 20` 且 `entry < image_size`。
- 验收：重建磁盘镜像后 `pkg install bc` / `pkg install rps` 均 `installed … -> /bin/xx.ce`；用旧摘要签名（v2.76 及以前的镜像）安装被 `SIGNATURE VERIFICATION FAILED - install refused` 拒绝——顺带证明强校验生效。

## 3. A5.4 — IME 候选框不再跟着滚动

候选框画在 `rows-2` / `rows-1` 两行里（原内容暂存后由 `con_status_bar_off()` 还原）。任何网格移动都会把那两行一起卷走，所以"滚动时候选框跟着跑"。现在：

- `scroll_one()`（输出换行）与 `con_scrollback()`（滚轮 / PgUp）先摘框、移动、再 `con_status_bar_reapply()` 钉回新底部；
- `bar_active` 语义改为"有文字可重画"，`con_status_bar_off()` 不清文字；IME 关闭走 `con_status_bar_forget()`，否则滚一次旧候选框就会复活。

验收：`help` 输出后 F2 + 输入 `ni` → 候选框在底部；连按 PgUp 两页，候选框依旧钉在底部，视口内容正常滚动。

## 4. B12 — 中文标点两个问号

IME 标点表原本直接吐 GB2312 双字节（`。` = `0xA1 0xA3`）。控制台按 UTF-8 取码点，两个字节都 >0x7E 且无字形，于是各画一个 `?`——一个中文句号占两格、显示两个问号。标点表已改成 UTF-8 码点（`。` → U+3002，`,` → U+FF0C…），字库子集本来就有这些字形。

验收：F2 开启后依次敲 `. , ? !`，得到 `。 ， ？ ！` 各占两格，不再有 `??`。

## 5. D11 — `shutdown` 之后自动重启

`cmd_shutdown()` 的兜底就是 `outb(0x64,0xFE)` 冷重启，所以"自动重启"= ACPI 关机没生效。两个根因都修了：

1. ACPI 2.0 固件在 legacy 模式（`PM1_CNT.SCI_EN=0`）会忽略 PM1_CNT 写入，必须先写 FADT 的 `SMI_CMD` + `ACPI_ENABLE` 再等 SCI_EN；QEMU 出厂已是 ACPI 模式，VMware 不是。
2. 旧代码把 `SLP_TYP 0..7` 全带 `SLP_EN` 写一遍，错误类型在部分芯片组会被解码成平台复位——这本身就会重启。

现在只写固件 `\_S5` 的 SLP_TYP，不生效再退 5、7 各一次。**关机/重启类操作在云端执行环境被禁止，无法实测，需 VMware 真机复核。**

## 6. 未完成（如实记录）

- **D10 包体大小**：上限不在 `fs_write_raw_mode`，而在下载链路——`pkg_payload[16 KiB]`、`tcp.rcv_buf` 一次收完整个响应、`http_fetch()` 整块拷贝。真解要 TCP 边收边排空 + HTTP 增量解析 + 边下边落盘，本轮未做。
- **D2 HTTPS/TLS**：基元齐（SHA-256/HMAC/X25519/AES-128-CTR/RSA），缺记录层、CBC 套件、X.509 解析与验签。验收标准定为 `openssl s_server` 端到端跑通，不能用"能连某网站"糊过去；本轮未做。
