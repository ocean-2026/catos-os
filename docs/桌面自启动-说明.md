# 桌面自启动说明（`GUI_AUTOSTART` 与 `/etc/autostart`）

## 1. 优先级（开机时 `boot_autostart()` 判定顺序）

1. **盘内 `/etc/autostart` 存在且非空** → 按文件内容逐行执行（每行一条
   shell 命令，`#` 注释、空行跳过）。这是用户显式选择，最高优先。
2. **盘内文件缺失或为空** → 看编译开关 `GUI_AUTOSTART`：
   - `=1`：内置默认动作，直接进入块桌面；串口打点 `BOOT:autostart gui`；
   - `=0`（默认）：不做任何自动动作，停在 shell prompt。
3. 两者都未命中 → 停 shell，等待交互输入。

> 既有 `/etc/autoexec/*.sh` 启动横幅脚本不受影响，仍在自启动判定之前执行。

## 2. 编译开关

`build.sh` 读取环境变量 `GUI_AUTOSTART`：

- `GUI_AUTOSTART=0`（缺省）：生产 / 门禁 / 探针镜像保持旧行为，开机停在
  prompt；
- `GUI_AUTOSTART=1`：盘内无 `/etc/autostart` 时开机进块桌面。

```sh
sh build.sh kernel                       # 默认 AUTOSTART=0
GUI_AUTOSTART=1 sh build.sh iso          # 编译进默认进桌面口径
```

## 3. 运行期安装命令

```sh
autostart --install gui
```

把选择写入盘内 `/etc/autostart`（内容 `gui`），下次开机按第 1 条优先执行。
无参 `autostart` 重跑启动脚本（不写文件）。

## 4. 为什么默认关闭（For what default off）

门禁与探针镜像**必须停在 shell prompt**：

- 门禁驱动（vprobe / E3 / F11）与 `gui_probe.py` 都在 prompt 上等待串口
  锚点、再逐条输入命令；若开机自动进桌面，控制台被 GUI 占用，探针自己的
  串口打点与命令输入会被冻掉（与控制台闸门 hotfix 同类问题）；
- 自动进桌面改变了开机路径，会让回归基线混入不可控的首屏状态；
- 交付产品镜像才需要 `GUI_AUTOSTART=1` 或盘内 `/etc/autostart=gui`，
  门禁镜像始终走默认关闭口径。

## 5. 边界

- `/etc/autostart` 是单行命令清单，不支持后台守护 `@` 前缀（那是
  `/etc/autoexec` 脚本的口径）。
- 编译开关只兜底盘内无文件的情况；盘内文件永远优先，安装后改开关不再
  影响开机动作，须删盘内文件才回落。
- 本段不做双 ISO 产出与版本号归档（见排队项 #37 / #39，等 v2 线并入后收口）。
