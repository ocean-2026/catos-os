# 一、CDE 模块化设计：可拆卸、可安装的图形桌面扩展

# CatOS CDE 模块化设计：可拆卸、可安装的图形桌面扩展

> 目标：把"图形桌面环境"从内核拆出来，做成一个像 Linux 桌面那样
> **可 pkg 安装 / 可卸载**的扩展。内核只提供通用图形原语，桌面语义
> （窗口、控件、任务栏、开始菜单、事件队列）全部随 `desk.ce` 一起装卸。
>
> 参考：另一位开发者的 CatOS CDE（`/d/xwechat_files/.../2026-11/isofiles.zip`），
> 已归档在 `deliverables/cde-ref/` 与 `github.com/ocean-2026/catos-cde`。
> 本设计**学其设计理念，不照抄其内核耦合架构**。

---

## 1. 为什么不能照抄参考实现

参考实现的 CDE 是**内核全功能 + 用户态外壳**的紧耦合架构：

- `src/cde.c`（2486 行 / 89 KB）把窗口管理、控件、事件泵、任务栏、
  开始菜单、壁纸、焦点路由全编译进内核；
- `catos_api_t` 里约 60 个槽是 GUI/CDE 语义（`cde_win_*`、`cde_poll_event`、
  18 种 `CDE_EVT_*` 等）；
- `desktop.ce`（1942 行）只是"声明 UI + 收事件"的薄外壳。

问题：桌面语义焊死在内核里，既不能装卸，也让 ABI  forever 膨胀。
这与 CatOS 的战略（图形模式 = shell 的图形后端，不是独立 GUI 体系）
和 CE ABI 的 append-only 冻结约束都冲突。

## 2. 我们的架构：内核只留通用原语，桌面整体上移

```
┌──────────────────────────────────────────────┐
│  可安装扩展包 desk.catpkg (CPKG02 签名)        │
│   └─ payload = desk.ce                        │
│       ├─ 窗口管理 / 控件 (retained 自绘)        │
│       ├─ 事件循环 (pollkey + mouse ABI)        │
│       ├─ 任务栏 / 开始菜单 / 桌面图标           │
│       └─ .cdeconf 配置持久化                   │
├──────────────────────────────────────────────┤
│  内核 CE ABI (append-only, 只加通用原语)        │
│   已有: gfx_rect/gfx_blit/gfx_info (61-63)     │
│   已有: pollkey(64) + mouse_* 全族 + mmap       │
│   新增: video_* / buf_* / key_peek 等 (§3)     │
├──────────────────────────────────────────────┤
│  渲染后端: be_text / be_gfx / be_vbe24         │
└──────────────────────────────────────────────┘
```

**内核退化成"帧缓冲 + 输入 + 计时"提供者**，和 X11 server 的角色类似；
桌面环境是一个普通 CE 程序，走 `pkg install` 装卸，与内核版本解耦。

## 3. 需要新增的 ABI 槽（append-only，追加到 65 号之后）

现状 66 槽（0..65，末槽 `gotoxy`）。参考调研结论：要让纯用户态 CE
完整实现桌面，最小新增 12 个通用原语槽。**注意先修复已有漂移**
（`ce.h` 内核镜像缺 65 号 `gotoxy`，`task.c:nargs[]` 也漏了槽 65）。

| 新槽 | 签名 | 用途 |
|---|---|---|
| 66 | `int key_peek(void)` | 窥视下一个 scancode 不消费（事件泵需要） |
| 67 | `int key_mods(void)` | Alt/Ctrl/Shift 修饰键位掩码 |
| 68 | `int video_info(int *w,int *h,int *pitch,int *bpp)` | 查询帧缓冲几何 |
| 69 | `int video_mode_set(int mode)` | 进入图形模式（幂等） |
| 70 | `int video_mode_text(void)` | 恢复文本模式 + 字库快照 |
| 71 | `int buf_create(int w,int h)` | 离屏缓冲（窗口客户区/双缓冲） |
| 72 | `int buf_destroy(int id)` | 释放离屏缓冲 |
| 73 | `int buf_blit(int id,int x,int y)` | 合成到屏幕（裁剪） |
| 74 | `int buf_rect(int id,...)` / `buf_text(...)` | 在离屏缓冲绘制（可选，也可复用 gfx + blit） |
| 75 | `int gfx_dirty(int x,int y,int w,int h)` | 显式脏矩形（配合 vbe24 脏检查） |
| 76 | `const char *clock_text(void)` | 内核时钟字符串（可选，也可用 `time_str`） |

> 落地时按"最小可用"分期：P1 只需要 `key_peek/video_info/buf_create/
> buf_destroy/buf_blit`（5 个）就能跑通一个窗口 + 事件泵；其余按需追加。
> 每加一批都要三处同序同步（见 §5）。

## 4. 可安装性设计

### 4.1 扩展包格式

复用 CPKG02（v2.68 已实现 RSA-512 签名），payload 是 `desk.ce`：

```
/pkg/desktop.catpkg  → pkg install desktop → /bin/desktop.ce
```

`build/pkg.list` 增加一行：`desktop|1.0|detachable desktop environment|desktop.catpkg|desktop`。
扩展本身**不进 `build/apps.list`**（不随内核内置），只有 `pkg install` 后才出现在 `/bin`。

### 4.2 命令与启动

- `pkg install desktop`：安装桌面扩展（验签 → 写 `/bin/desktop.ce`）；
- `desktop` 命令：shell 分发到 `ce_run("/bin/desktop.ce")`，进入图形桌面；
- 桌面内 `Start > Shut Down` 或 Esc → `cde_exit` → 回文本 shell；
- `pkg remove desktop`：删除 `/bin/desktop.ce`，系统回到纯命令行，**内核不变**。

### 4.3 生命周期状态

安装状态靠 `/bin/desktop.ce` 是否存在判定（与现有 `pkg_installed()` 一致），
无需新增注册表项。偏好配置 `.cdeconf` 由 `desk.ce` 自己读写（复用 `save/cat` ABI）。

## 5. ABI 追加的三处同步（血的教训）

参考 `CDE_NOTES.md` 记录过"三处顺序不一致导致所有后续函数指针错位"。
CatOS 同理，追加每个槽必须同时改：

1. `include/ce_abi.h` — 用户侧 `catos_api_t` 结构末尾追加；
2. `include/ce.h` — 内核侧镜像结构末尾追加（当前缺 65 号，先补齐）；
3. `src/task.c` — `enum SYS_*`、`nargs[]`、`isr_syscall` 的 `case`、
   `build_vsyscall_page` 的 thunk 数（2 KiB 区上限约 85 槽）；
4. extapp 侧 `ce_app.h`/`ce_app.c` 自动跟随，无需改；宿主桩 `host_stub_go.c`
   若做完整结构初始化需补成员。

## 6. 从参考实现吸收的关键经验（不踩重复的坑）

| 坑 | 我们的规避 |
|---|---|
| `cde_poll_event` 每轮整屏重绘 → 撕裂 | 桌面用脏矩形 + 只在事件变化时合成 |
| 字体用 Consolas 8x8 阈值化糊成乱码 | 复用 CatOS 自带真 IBM VGA 8x16 ROM（`font_ascii.inc`） |
| 编辑器打字整屏闪 | 影子缓冲 + 屏幕差分，只写变化的 cell |
| 后台窗口输入框抢按键 | 焦点窗口归属检查（`cde_focused_win` → 我们的焦点状态） |
| `^A/^U/↑/↓` 被输入框吞 | 这些键不消费，推给应用做行编辑 |
| 函数参数 >6 个变栈垃圾 | 新 ABI 参数控制在 6 个以内（已有 `gfx_blit` 用结构体指针） |
| 编译列表两处漏加 `.o` | 我们的 `build.sh` 三处硬编码列表要同步（若加内核侧文件） |

## 7. 分期路线（每期都过 QEMU 实机回归）

- **P1 原语补齐**：修 ABI 漂移（65 号）+ 追加 5 个最小 GUI 原语槽；
  写一个 `win_demo.ce` 验证开窗/绘制/事件（先在宿主原型）。
- **P2 桌面外壳**：移植参考 `desktop.c` 的事件循环与窗口模型到纯 CE
  （retained 控件自绘），做 `desk.ce`；`pkg install` 装卸验证。
- **P3 完整外壳**：任务栏/开始菜单/桌面图标/文件管理器/终端/编辑器，

- **P4 可拆卸性回归**：装 → 用 → 卸 → 系统回到纯 shell，内核二进制

### P1 实际实现（与 §3 原计划的差异）

经盘点，参考实现桌面依赖的核心底层能力是**鼠标状态 + 文本绘制 +
键盘事件**。现有 CE ABI 已有 gfx_rect/gfx_blit/gotoxy/pollkey，唯一
完全缺失的是鼠标。因此 P1 按"最小可用"收窄为：

1. **修 ABI 漂移**：`include/ce.h` 内核镜像补槽 65 `gotoxy`；
   `task.c:nargs[]` 补槽 65 的 `nargs=2`（此前隐式 0 → thunk 不转发
   ebx/ecx，`gotoxy(x,y)` 拿到陈旧参数）。实机 `tests/gotoxy_v269_probe.py`
   验证标记精确落在 (10,3)，2/2 PASS。
2. **追加 3 个通用鼠标原语槽**（append-only，66/67/68）：
   `mouse_x()/mouse_y()/mouse_buttons()`，均薄包装内核 `mouse_get_state()`。
   三处同序同步：`include/ce_abi.h`、`include/ce.h`、`task.c` 的 enum/
   nargs/isr case。`tests/mouse_abi_v269_probe.py` 验证 CE 读数与内核
   `mouse` 命令状态完全一致，4/4 PASS（本 QEMU 无 PS/2 鼠标，事件注入
   检查按环境跳过）。
3. **`desk.ce`（源 `extapp/desktop.c`）**：纯用户态桌面，全部窗口语义
   （焦点/命中测试/任务栏/事件循环）在 CE 侧，内核只提供原语。当前用
   text 后端 ASCII 窗口（`gotoxy`+`write`），可在 QEMU/VMware 目视与
   text buffer 探针验证。
4. **可安装扩展包**：`build/pkg.list` 增加 `desktop|1.0|...|desktop.catpkg|
   desktop`，复用 CPKG02 + RSA-512 签名；`pkg install desktop` 验签后写
   `/bin/desktop.ce`，裸名 `desktop`（PATH=/bin）直接运行，无需改 shell。
   `tests/desktop_pkg_v269_probe.py` 完整生命周期 **10/10 PASS**：
   list→install→运行桌面→q 退出→remove→命令消失，内核二进制不变。

## 9. v2.73 地基修复：ring0 sshd 阻塞 CE 键盘事件（2026-11-22）

### 9.1 症状与定位

v2.72 上 `pkg install desktop` → `desktop` 能装能渲染，但 `q`/`Esc`/`Ctrl+C`
全部无效，**进桌面后只能重启**。v2.69 探针声称的 "10/10 PASS" 是**假阳性**：
它用 `"root@catos" in screen_text()` 判断"已退出"，而桌面用 `gotoxy` 画在
text buffer 上，旧提示符残留直接命中断言。

定位手段（可复用）：写最小 CE 探针 `extapp/keyprobe.c`（阻塞 `getch()` +
非阻塞 `pollkey()` 打印返回值），用 `inject_any.py` 注入测试盘，跨版本二分。
结论：**v2.68.3 及以前正常，v2.72 收不到任何键**——是内核回归，不是
desktop.c 应用 bug，也不是 QEMU 环境。

> 二分过程踩坑：批量连跑多个 QEMU 实例时残留进程导致端口/焦点干扰，
> 出现"v2.69/v2.71 也坏"的假象。每次测试前必须 `taskkill qemu-system-i386`
> 并用独立 monitor 端口，否则结论不可信。

### 9.2 根因

v2.72 新增 `/etc/autoexec/sshd.sh` 自启动 ring0 daemon（`task_spawn_r0`）。
该 daemon 常态停在 `!net_up()` 分支，用 `task_maybe_yield()`（cooperative
busy-yield）让出 CPU。当 ring3 CE 任务阻塞在 `SYS_GETCH` 内时，`g_in_syscall`
全局计数器停在 1，令 `task_maybe_yield()` 直接 return——sshd 于是不再让出，
独占 CPU，键盘 IRQ 唤醒的等待任务永远得不到调度，CE 的 `pollkey`/`getch`
收不到键。ring0 shell 走 timer 睡眠路径不受影响，所以命令仍能输入。

### 9.3 修复

`kernel_v25/src/ssh.c` 的 `sshd_daemon_main()`：无网卡等待分支改用
`task_sleep_ticks(1)`（进 `T_SLEEPING`，由 timer IRQ 唤醒 + idle park 路径），
不再依赖 cooperative yield。改动一行，保留 sshd 自启动功能。

> 尝试过但**无效**的方案：改 `task_maybe_yield()` 让 ring0 忽略
> `g_in_syscall`——单独改这处键盘仍不通，因为 cooperative 切换本身
> 无法恢复等待任务。已回退，不要重试。

### 9.4 验证

- `keyprobe.c`：`getch=979`('a')、`pollkey=111311`('q')、正常 `exit(0)`。
- CDE 桌面：`desktop` → `q` 退出回 shell → `pkg remove` → 命令消失，全通过。
- `ssh_v272_probe.py`：4/5 PASS；唯一 FAIL（host key 重连严格检查）在原版
  v2.72 ISO 上同样 FAIL，属宿主 ssh 客户端环境问题，与修复无关。

### 9.5 遗留隐患（本次未改）

`net_tcp_saccept()`（netstack.c）内有 3000000 次 `task_maybe_yield()` 忙循环，
有网卡时 daemon 会走这里，理论上有同类键盘饥饿风险。该方法被前台交互
`sshd` 共用，直接改会破坏其 ESC/超时语义，故本次不动。带网卡的 VMware
上若复现"进桌面后键盘失灵"，优先查此处。

## 10. v2.73 gfx24 真图形后端调查（进行中）

### 10.1 目标与现状

P1b 目标：把 CDE 从 text 后端 ASCII 窗口升级为 gfx24 真彩图形桌面。
现有 `desktop.c` 仍是 text 后端（`gotoxy`+`write`），P1b 的 `gfx_text`/
`buf_*` ABI 槽未追加。**更正上轮结论**：远端那批 v2.72 提交里的
"canvas colour"只是主题配色单一数据源（`colors` 命令 + hive），
与"画布应用"无关，P1b 并未被别人完成。

### 10.2 关键发现：CE 侧渲染完全可行（零 ABI 改动）

内核 gfx24 后端已有 `render_font_glyph` 字体渲染循环，只是没暴露给 CE。
验证了一条**零内核改动**的路子：CE 把真 IBM VGA 8x16 字体
（`font_ascii.inc`）编进镜像，在离屏 RGB24 buffer 上逐像素画字，
用**现有** `gfx_blit`（槽 63）一次投屏。

- 原型：`kernel_v25/extapp/gfxtext.c` + `tests/gfxtext_probe.py`。
- 结果：`gfxtext.ce` 实机画出 5 行彩色文字，字形锐利清晰、无残缺错位
  （`tests/dumps/gfxtext_zoom.png` 目视确认）。**证明 P1b 渲染不需要新 ABI**。
- 完整桌面原型：`kernel_v25/extapp/gfxdesk.c` + `tests/gfxdesk_probe.py`，
  画 800x600 背景、任务栏、三个窗口、图标，`gfxdesk_probe.py` 像素断言 4/4 PASS。

**两个构建坑（务必记住）**：
1. CE 的 bss 上限 256 KiB（`ce.h:CE_MAX_BSS`）。离屏 buffer 必须 ≤ 216 KiB；
   384x192x3=216 KiB 可用，448x224x3=301 KiB 会被 mkce.py 拒绝。
2. **CE 源文件里绝不能重定义 `__ce_api`**。`ce_app.c` 已提供 weak 定义；
   再加一个强定义会让 `build_ce.sh` 的 nm 正则选中错的 `.ce_api` 单元格，
   内核写入另一个槽 → 程序读到 NULL → `pollkey` 处 page fault
   （`cr2=0xf4` = API 槽 61×4）。`gfx24.c` 是老代码仍带强定义，别照抄。

### 10.3 曾经的"阻塞 bug"：gfx 模式下 ring3 的 task_sleep_ticks() 不返回
（**已证伪，见 §10.5；本节保留调查过程存档**）

排除了原型逻辑问题后，做了一个干净对照：把已证明 text 模式下键盘
3/3 PASS 的 `keyprobe.c` 改成先 `display_mode(3)` 切 gfx24——同样的代码
立刻 0/3（getch/pollkey 全收不到键）。**这是内核级 bug，不是桌面应用问题。**

二分定位链路：
- 切 gfx 后 CE 能画画面（gfx_rect/blit 成功）→ 切换本身和 API 表正常。
- 但 `q` 之后 CE 无任何响应；把循环心跳绑到任务栏颜色后确认：
  任务栏停在初始 compose 的蓝色，第一次循环迭代的 `api->delay(30)`
  之后的绿色重绘**从不执行**。
- `api->delay` → `task_sleep_ticks()` → `task_block(T_SLEEPING)`，靠
  IRQ0 的 `sched_timer_tick()` → `task_tick_wake()` 唤醒。
- 定位到 `kernel_v25/src/task.c:sched_timer_tick()` 的 ring3 抢占分支：
  中断 ring3 任务时走主动 `pick` 切换；空闲时（`c->ring0`）只置
  `need_resched`。怀疑 idle park 路径在 gfx 模式下没把唤醒的 sleeper 切回 CPU。

> 尝试过但**无效**：忙轮询版（去掉 delay）反而画不出画面，怀疑高频
> syscall 触发了另一处问题。不要在这条路上继续。

> **结论已推翻（v2.74）**：上面的怀疑是错的。串口实证表明 sleep/wake、
> idle 调度、pollkey 和按键全部正常；"卡死"其实是探针在 gfx 模式读 TEXT
> buffer 的观察误判。忙轮询版画不出是另一回事（高频 syscall 的时序问题），
> 与 scheduler 无关。详见 §10.5。

### 10.4 交付状态

- 已交付：`gfxtext.c`/`gfxdesk.c` 原型 + 两个正式探针；渲染能力已证实。

### 10.5 v2.74 结案：§10.3 的"内核 bug"是误判（阻塞项已解除）

用 COM1 串口 breadcrumb（`tests/gfxsleep_diag.py`，内核诊断已回退）对 gfx
模式下 ring3 CE 的调度/输入链路做了实证，**推翻 §10.3 的结论**：

- **sleep/wake 完全正常**：日志中 `[sleep]`/`[woke]`/`[idle->]` 循环 200+
  次，每次 `task_sleep_ticks()` 都在 2 tick 后被 IRQ0 的 `task_tick_wake()`
  置 READY，idle 的 `pick_ready()` 立即把任务切回 CPU。`task.c` 的调度器
  无任何问题。
- **键盘完全正常**：CE 每帧照常调用 mouse_x/y(66/67)、mouse_buttons(68)、
  pollkey(64)、delay(17)（nr 0x42/43/44/40/11）；按下 `q` 时日志记录
  `[key tid=1 k=0x71]`，`pollkey()` 正确收到键值。
- **退出完全正常**：CE 收到 q 后调 `display_mode()`(49) 并 `sys_exit`(13)，
  shell(tid=0) 随即恢复。全程无 fault/panic。

**误判根因**：旧 `gfxdesk.c` 退出时调 `display_mode(2)`（切到 VBE，非 TEXT——
切 TEXT 需用户按 Y 同意），于是 "exited to text shell" 这行写进了 VBE 后端；
`gfxdesk_probe.py` 用 `screen_text()` 读 TEXT buffer 自然读不到，被标成
XFAIL。当年 keyprobe "加 display_mode(3) 就 0/3" 同理——切 gfx 后 TEXT
探针读不到输出，并非真收不到键。

**修复（v2.74，纯原型/探针层，内核零改动）**：

1. `gfxdesk.c` 退出改 `display_mode(0)`（请求 TEXT），内核弹出 consent
   提示后按 Y，退出标记落入 TEXT buffer；顶部错误注释已更正。
2. `gfxdesk_probe.py` 改为 `q` 后补发 `y`（同意切 TEXT），用真实标记断言
   退出。结果 **5/5 PASS**（含此前 XFAIL 的 `q exits to text shell`）。

**回归全绿**：gfxdesk 5/5、keyprobe 3/3、desktop CDE 10/10、gfxtext PPM
生成成功。浏览器/多媒体查看器等 gfx 交互应用的**前提已具备**，无内核阻塞。

**遗留注意**：
- 离屏 buffer 仍受 CE bss 256 KiB 限制（≤216 KiB 可用），见 §10.2。
- CE 不能静默切回 TEXT（consent 是强制的），退出类交互需按用户确认流程设计。
- QEMU 实机务必用独立端口 + 跑前清理残留进程，否则会误判。

## 一、结论先行

1. 渲染从其它层里彻底剥出来了：一个与模式无关的前端 + 两个可插拔后端。
   除 `src/render*.c` / `src/be_*.c`，全内核再无任何地方写 `0xB8000`、
   `0xA0000` 或 VGA 端口。
2. 图形模式（当前实现是 VGA Mode 13h，用户称之为 VBE 模式）**只做文本绘画**：
   40x25 字符格、256 色、8 种样式。所有帧缓冲图元都是 `static`，链接产物里
   不存在 `gfx_putpixel` / `gfx_fillrect` / `gfx_rect` 之类的符号。
3. 用户态**没有任何绘制 API**：没有绘图 syscall、没有 CE API 槽位、
   帧缓冲也没有映射进 ring3 页表（`task_space_create()` 里 PDE 0 是
   supervisor-only）。用户态能拿到的只有 `write/putc/cls/set_style/display_*`。
4. 用户态程序可以主动 文本→图形；图形→文本 **强制**经过一个物理 `Y` 按键确认，
   程序无法伪造（没有参数、没有 token、没有可跳过该路径的 syscall）。

## 四、模式策略（第 2 条需求）

`con_request_mode(mode, origin)` 是**唯一**切换入口。

| 方向 | 谁可以 | 行为 |
|---|---|---|
| 文本 → 图形 | 内核 / shell / 任何 ring3 程序 | 直接切换，无需同意 |
| 图形 → 文本 | 任何人 | `con_ask_consent()` 打印提示并**阻塞读一个物理键盘按键**，只有 `Y`/`y` 放行，其它键拒绝并返回 `-13 (EACCES)` |
| 图形 → 文本（紧急） | 仅内核 `con_force_text()` | 跳过同意；panic/致命异常路径专用，无 syscall 可达 |

同意不可伪造的三点保证：
- syscall 只有 `int display_mode(int)`，参数只有目标模式，没有 consent 位；
- 同意来自 `kb_getkey()` 读 PS/2 扫描码队列，没有任何 syscall 能往队列写；
- origin 参数被故意忽略 —— 连 shell 的 `text` 命令也要按 `Y`，策略统一。

`display_mode(0)` 从 ring3 调用时会阻塞在 syscall 内（`task_block(T_WAIT_KB)`，
与现有 `SYS_GETCH` 同一条已验证路径），程序暂停，用户按键后继续。

## 九、v2.8 增量：中文显示 + 真彩文字 + 自定义调色板 + VBE 后端

用户给了两条路：① 中文支持；② "255×255×255 色或其它多色"。结论是
**① 是真需求，② 的前提是错的**，但按"全做"的要求，② 被拆成两个
可交付物一并实现。

### 9.1 为什么 "255×255×255 色" 在 Mode 13h 上不成立

- VGA Mode 13h 是 **8bpp 索引色**：帧缓冲每像素 1 字节，同屏最多
  **256 色**。这是硬件上限，不是软件偷懒。
- VGA DAC 每通道 **6 bit（0..63）**。v2.7 的 `be_gfx.c` 往 `0x3C9`
  写 0..255 会被硬件截断成 0..63 —— 连"255 级/通道"都不存在。
  v2.8 已改成显式 `rgb >> 2`。
- 真正的 1677 万色必须换 **24/32bpp 线性帧缓冲**，那是一次底层重写。
- 更根本的：图形模式被定位成"颜色和样式更多的文本模式"，一次只用
  前景+背景两色，256 种可选色已经过剩。1600 万色对纯文本收益接近零。

因此 ② 落成两件事：
1. **务实版**：用户态可自定义 256 项 CLUT（Mode 13h 同步写 6-bit DAC）；
2. **真彩版**：新增 VBE 32bpp 后端，每个字符用字面 RGB 绘制。

### 9.2 中文显示

| 项 | 实现 |
|---|---|
| 字库 | GB2312 全 **6763 字**（U+4E00..U+9FA0），16×16 1bpp，32 字节/字 |
| 生成 | `tools/gen_hz_font.py`，用本机 `simsun.ttc` 16px + Pillow 渲染；产物 `src/font_hz.inc`（750 KB 源码 / 216 KB 数据）**已提交**，构建不依赖 Pillow 或字体文件 |
| 查找 | 按 Unicode 码点排序 + 二分查找，`render_font_hz(cp)` |
| 编码 | `con_write()` 内置 UTF-8 解码状态机；每次 write 结束 `con_flush_utf8()` 把残字节降级为 `?`，杜绝多任务串扰 |
| 排版 | 汉字占 **2×2** 个 8×8 逻辑格；强制从偶数行起，滚动固定 2 行；`reflow()` 把 2×2 块当原子搬运，切模式不会把汉字切一半 |
| 覆盖 | 文本模式不支持（`cjk=0`，降级 `?`）；图形 / VBE 完整支持 |
| 输入 | **没有中文输入法**，键盘仍是 US QWERTY 扫描码。只能显示 |

字库由系统字体渲染生成，本地 / 私有使用没问题；**对外分发内核镜像前
需确认字体 EULA**。

### 9.3 颜色模型升级

前端 cell 从 `(ch, fg8, bg8, attrs)` 升级为：

```c
typedef struct {
    uint32_t cp;                  /* Unicode 码点，0 = 空 */
    uint32_t fg, bg;              /* 0x00RRGGBB */
    uint8_t  fg_idx, bg_idx;      /* 量化后的 CLUT 索引 */
    uint8_t  attrs, flags;        /* 样式 / 宽字符标记 */
} con_cell_t;                     /* 16 字节 */
```

- 前端持有 256 项 CLUT；`set_style(int,int,int)` / `set_fg(int)` 保持
  **索引语义**（旧二进制不变），新增 `set_style_rgb` 走字面 RGB。
- 三后端各自翻译：`be_text` → 最近 16 色；`be_gfx` → CLUT 索引；
  `be_vbe` → 直接写 32bpp RGB（真彩）。
- `set_palette(idx, rgb)` 改 CLUT 并同步 6-bit DAC，然后重画整屏。

### 9.4 第三个后端：VBE 800×600×32

`src/be_vbe.c`，100×75 逻辑格，`colors=16777216`，`bpp=32`。

- 模式设置走 **Bochs/QEMU VBE dispi 端口** `0x1CE/0x1CF`，不需要在
  保护模式里调 BIOS `int 0x10`。
- LFB 物理地址来自 VGA PCI BAR2（QEMU std VGA `1234:1111`、QXL、
  Virtio GPU），老 Bochs 回退 `0xE0000000`。
- 新增 `vbe_lfb_map()`（`paging.c`）：为高端 PDE 建 4 KiB 页表，
  **supervisor-only**，且拒绝触碰 PDEs 0..15。ring3 页目录只复制前
  16 个 PDE，所以真彩模式同样看不到帧缓冲 —— "不开放绘图 API"
  在 32bpp 下依然成立。
- 硬件探测失败时 `enter()` 返回负值，`con_request_mode(VBE)` 返回
  `-19 (ENODEV)` 且**不改变当前模式**。

### 9.5 模式策略更新

`con_request_mode()` 仍是唯一入口：

| 方向 | 规则 |
|---|---|
| → GFX / → VBE | 所有来源（含 ring3）直接放行 |
| 任何非 TEXT → TEXT | **一律**要物理 `Y` 确认，origin 参数被忽略；连 shell `text` 也要按 Y |
| `con_force_text()` | 内核紧急路径专用，无 syscall 可达 |

`switch_backend()` 顺序改为 **先 `old->leave()` 再 `new->enter()`**：
VBE 的 dispi 关闭必须先于 Mode 13h / 文本模式的寄存器序列，否则会
被后续 disable 重置。探测失败会调 `old->enter()` 恢复原模式。

#### 10.4.1 实现

1. **MTRR Write-Combining**（`be_vbe.c: mtrr_set_wc`）：按 SDM 完整序列
   （CD|NW → wbinvd → MTRRs off → 编程 → MTRRs on → wbinvd → 恢复 CR0/
   EFLAGS），为 LFB 找一个空闲变量 MTRR 标成 WC。护栏：只对
   `>= 0xC0000000` 的区域生效（绝不覆盖系统 RAM）；区域必须是 2 的幂且
   基址对齐，对不齐则向下对齐并扩区域（QEMU 下无害，真机上可能覆盖其它
   BAR——已知瑕疵，真机线下再修）；CPUID 检查 MTRR 支持；失败一律静默
   退回 UC。
2. **硬件平移滚动**：按 BAR 实际大小申请虚拟高度（上限 4096px = 256 行），
   滚动 = 先把新露出的一行擦成背景色（12.8KB 纯写）再写 DISPI_Y_OFFSET，
   **零像素搬运、零 VRAM 读**。视口到底时回卷到 0 并让前端整屏重渲染
   （约每 219 次滚动一次 1.9MB 纯写突发）。
3. **明确不做像素双缓冲**：前端的单元格网格就是权威屏幕副本，所有像素
   都由它派生，1.9MB RAM 镜像买不到任何东西。退化路径 = 前端从网格整屏
   重渲染（纯写），替代旧版的"显存 memmove"（UC/WC 下读显存都是毒药）。
4. 退化可观测：`vdiag` 与 `display` 都输出 `MTRR-WC/UC` 与

### 11.1 TD-01：page fault 致命路径（真 bug，比待办描述的更糟）

### 11.2 mmap / munmap（CE ABI v2.10，槽位 55/56）

**地址空间扩容**（前提）：原内核用户空间只有一张用户页表（PDE 8，
32-36 MiB），CE 全家桶占了大半。新增第二个用户 PDE（9 号，36-40 MiB）：
- `task_space_t` 增加 `pt2`；`task_space_create` 挂两张用户页表，
  失败路径不再泄漏帧（原代码部分失败会漏）。
- `task_map_page / task_virt_to_phys / 新增 task_unmap_page` 按 PDE
  分派；`task_space_destroy` 释放两张页表的全部帧。

**语义**：
- `mmap(addr, len, prot, flags)`：addr 必须 0；匿名映射，first-fit
  分配在扩展区；每映射前面带 8 KiB guard 页（返回地址在 guard 之后，
  越界下写直接 page fault 杀任务而不是踩邻居）；页面 lazy 映射
  （复用 page fault 路径）；返回用户地址或 -22/-12。
- `munmap(addr, len)`：解除映射、释放帧、归还空洞；部分解除缩小 VMA，
  全解除删除 VMA。只接受本任务 mmap 出来的区间（-22 拒绝其它）。

### 11.3 ELF32 加载器（PIE + ASLR，双轨制第三轨）

`task_spawn_ce` 现按 magic 分派：`CE01` 走旧路径（PDE 8 固定偏移），
`\x7fELF` 走 ELF 路径（PDE 9 扩展区）。

- 校验 ELF32 / LE / i386 / ET_DYN / PT_LOAD 数 ≤16 / 文件 ≤2 MiB。
- **ASLR**：PIE 基址 = USER_EXT_BASE + (tick 哈希 mod 16) 页，每次
  spawn 滑动 0-64 KiB。
- 段加载：PT_LOAD 页区间排序合并（经典 RO 尾页 / RW 首页共享页），
  逐合并区间 kzalloc + map + 建 VMA；再按段从 FAT 直接读文件字节进
  用户页（`fat_pread` 支持任意文件偏移跨簇读）；bss 由零页天然覆盖。
- 入口 = base + e_entry，校验落在已映射区间。
- **syscall 约定**：ELF 没有 __ce_api 槽，直接调固定 vsyscall 表
  `CATOS_VS_TABLE`（0x2080800，ce_abi.h 新宏）：
  `call dword [CATOS_VS_TABLE + 4*slot]`。
- ET_EXEC 也按 PIE 处理（文档明说：仅支持位置无关代码）。

**工具链现实**：本机 MinGW 无 elf_i386 输出能力（连 MSYS2 usr/bin 的
ld 都只支持 pe）。`tools/mkelf.py` 手工构造最小但真实的 ELF32

`extapp/bin/hello.elf` 已编入内核内置表，QEMU 里 `hello.elf` 即可
验证 ELF 路径。**没有真实 C→ELF 编译链**——这是后续待办（binutils
elf 目标或 lld）。

1. ELF 仅支持位置无关代码；没有动态链接、没有 symbol relocation。
2. munmap 空洞归还后，mmap first-fit 会复用地址（测试利用了这点）；
   无 ASLR 重随机。
3. 扩展区共 4 MiB（单页表上限）；ELF 与 mmap 共享，ELF 最多 2 MiB。
4. `fat_pread` 与 spawn 共用 static 簇缓冲（ring0 非重入，安全）。
5. cc.ce 尚无 `void*` 指针运算的全部语义，mmaptest 只能用 gcc 构建。

### 11.7 QEMU 实机测试结果（2026-11-07，QEMU 11.1.0 @ C:/qemu-portable）

QEMU 经由官方安装器 7z 解包为便携版安装成功。`tests/qemu_regress.py`
端到端跑通：**12 步 12 PASS**（boot/format/help/display/gfx/同意门
N+Y/ls/mmaptest/hello.elf/vdiag/final-frame），截图在
`tests/qemu_shots/`。实机验证确认并修复了 **5 个只有真机才暴露的 bug**：

1. **字形重载写错了地方（v2.9 的原始 bug）**：`fontwin` 停在 0xB8000
   且从不切窗 —— GC 0x06=0x0E 时 0xA0000/B8000 都别名到文本缓冲，
   "字形装载"实际是把 8KB 字形喷进文本缓冲，字形 RAM 从未被装载。
   修正为标准序列（Seq 04=06 sequential + GC 06=00 A0000 窗 + 写后恢复）。
2. **CRTC 写保护吞掉恢复写**：gfx_enter 写 `CRTC11=0x8E`（bit7=保护）
   后，text_enter 对 0x00-0x07 的恢复写**全部被硬件静默丢弃**，
   gfx 的垃圾垂直时序（06=0x0B：垂直总数 11 行！）残留 → 往返后花屏。
   text_enter 现在先 `0x11=0x0E` 解锁再恢复。
3. **gfx_enter 的 Mode 13h 垂直时序表本身是错的**（BIOS 标准表
   04=55 05=81 06=BF 07=1F 09=41），已改为标准值 —— 修复后 gfx 模式
   在 QEMU 里完整渲染：**中文 + 8 种样式全部正确显示**。
4. **vdiag 一跑屏幕永久黑**：text_diag 读 Attribute Controller 时
   索引写不带 0x20（Video Enable）位 —— VGA 协议里这会关掉视频输出
   且不恢复。已修（所有 AC 索引写 OR 0x20，收尾 0x20 恢复）。
5. **mkelf.py 的 e_entry 用了文件偏移**（0x1000，而段 vaddr=0），
   加载器入口校验拒绝 → -5。改为 0，并在自检里加了入口范围断言；
   随后发现手编机器码把 msg 指针编成绝对地址，PIE 滑动后指向页 0
   被 validate_uaddr 拒绝（exit 走得通、write 静默失败）—— 改为
   EIP 相对取址（call $+5 / pop）。最终 QEMU 实机输出：
   `hello from ELF` + `[task 1 'hello' exit(0)]` —— **ELF32 PIE+ASLR
   加载链路真机全通**。mmaptest 同样真机全绿（mmap/懒映射/munmap/
   空洞复用/非法拒绝，`MMAPTEST PASS`）。

配套修复：shell `run_from_path` 对带扩展名的命令不再强拼 `.ce`
（`hello.elf` 之前被拼成 `hello.elf.ce`）；format 确认是整行读取
（回归脚本补回车）；回归脚本 PNG 解析支持 32bpp screendump。

**已知遗留（纯外观）**：gfx→text 往返后文本屏有对角 RGB 细条纹。
排查结论：CRTC/Seq/GC/AC/DAC 寄存器经物理内存 dump 证明与干净 boot
逐字节一致、内容无关（clear 后仍在）、-vga cirrus 与 std 输出相同、
Seq 复位脉冲/AC 开关/平面清零均无效 —— 判定为 QEMU std-VGA 内部
surface 状态问题，真机硬件无 surface 缓存，预期不复现；后续可从
QEMU vga.c 源码级追查。诊断基建保留：`vga_reg_dump[]` 全局数组 +
monitor `xp` 直读物理内存，可随时对比任意两个时刻的完整 VGA 寄存器组。

摘标结论：v2.9.1 的 `[MTRR/pan UNTESTED]` 中，VBE 模式进入/退出、
text 同意门、闪烁光标、mmap、ELF 均已实机验证；MTRR WC 与
HW-pan 滚动本身仍需在 `vbe` 模式下跑 `vdiag` 确认（本轮未跑 VBE 路径）。

## 十二、v2.12 增量：24bpp 真彩后端 + 用户绘图 API（2026-11-10）

**本节推翻第一节点 3 与第五节的「用户态没有任何绘制 API」结论**；第一至十一节的其余
结论（前后端分离、单元格网格、同意门、append-only 等）继续有效。以本节为准。

### 12.1 变更

| 项 | v2.7~v2.11 | v2.12 |
|---|---|---|
| 后端 | 3 个：text / gfx(8bpp) / vbe(32bpp) | 新增第 4 个 `be_vbe24.c`：800x600x24，3 字节 BGR，pitch 2400，1,440,000 B |

| CE ABI | 61 槽，无绘图槽 | 64 槽：61 `gfx_info`、62 `gfx_rect`、63 `gfx_blit` |
| `display` 输出 | `user drawing API : NONE` | vbe24 下报告 `GFX24 (gfx_info/gfx_rect/gfx_blit, kernel-side writes)` |

### 12.2 安全模型没有放松

帧缓冲**仍然是 supervisor-only**。变化在于：ring3 目录现在会镜像 LFB 所在的高 PDE，
但所有 PTE 都是 `0x003`（P|RW，**无 US 位**），用户代码读写 VRAM 依旧触发 #PF。
镜像的目的只是让「内核在调用者 CR3 上代写」不缺页（见问题清单 #84）。用户程序拿到的
从来不是帧缓冲地址，而是：

```
gfx_rect_t { x,y,w,h,rgb }            -> SYS_GFX_RECT  -> copy_from_user -> gfx24_rect
gfx_blit_t { src,w,h,x,y }            -> SYS_GFX_BLIT  -> 逐行 copy_from_user -> gfx24_blit
```

描述符而非 5 个标量参数，是因为 `generic_thunk()` 只转发 ebx/ecx/edx/esi 四个参数
（**不转发 edi**）。扩展手写 thunk 字节风险更高，故把多字段压成一个指针，顺带让
用户指针校验点集中。所有用户范围校验沿用 #78 的 `copy_from_user()` 模型。

### 12.3 同意门不变

`->gfx / ->vbe / ->vbe24` 自由；`->text` 仍强制物理 `Y`。`con_request_mode()` 的
白名单加入 3，其余分支未改。CE 应用 `gfx24.ce` 在 inactive 时会自行调用
`display_mode(3)`，这是允许的方向。

### 12.4 取舍

`be_vbe24.c` 不用硬件 pan（`VIRT_HEIGHT=600`，`scroll=NULL`，前端全量重绘）、
不启用 MTRR-WC。理由与验证数据见 `docs/CatOS-内核问题清单.md` 13.2 / 13.3。
像素级实机回归：`tests/gfx24_regress.py`（QEMU `-vga std`，解析 screendump PPM）。

## 2. 差距分析

> 每条按“HEAD 现状（代码证据）→ 差距 → 对使用的影响”陈述。标注“依赖外部子系统”的项，其前置状态见第 4 章。

### 2.1 多音节长串与最大匹配

- **现状**：音节串长度上限 6（`ime.c:148`），`py_find()` 只做整串精确二分（`ime.c:32-41`）；表内 400 条均为单音节（长度分布见 1.3）；无分隔符（如 `zh'ong`）解析，无分词，无前缀候选。

- **影响**：打词组必须逐字选；输入速度受限；与成熟拼音输入法的核心体验差距最大。

### 2.2 词组、词频排序与联想

- **现状**：表内只有单字；候选顺序是**构建期静态**的（jieba 可选 → 手工表 → GB2312 字级），运行期不记录用户选择频次；上屏后不产生后续候选联想。
- **差距**：无词组条目；无运行期词频学习；无“上一字 → 下一字/词”联想；无用户词典。
- **影响**：高频词组（如“我们”“操作系统”）需要逐字翻页选择；常用错字位置无法通过使用习惯前移。

### 2.3 标点与全角符号

- **现状**：IME 没有符号/标点模式，候选只来自 `py_tab`；字库已含 198 个标点/符号字形（`、。，！？：“”…·` 实测在册），但**框线制表符 U+2500..U+257F 在册 0 个**。
- **差距**：不能在 IME 内翻全角标点；横线分隔符没有现成字形；半角/全角切换缺失。
- **影响**：候选区横线只能靠 ASCII 字符或后端绘制（见 3.1）；中文行文的标点需另寻输入路径。

### 2.4 候选栏绘制质量与鼠标点选

- **现状**：候选条整行反白（`render.c:711` `s_attrs |= CON_ATTR_INVERSE`），首选候选无独立高亮（问题清单 #126：浮层未做首选高亮、编号徽章/间距未调）。HEAD 全仓 grep 无鼠标事件队列、无命中测试 API、无 HID 鼠标报告处理（`usb_uhci.c` 仅 HID 键盘引导协议）；`gfx24.h:52-57` 公开绘制面只有 `clear/pixel/rect/blit`，无文本测量 API。
- **差距**：候选不可点选；首选与普通候选视觉无差别；gfx24 下无法按像素做候选命中判定。
- **影响**：多候选场景只能靠键盘；并行的 v2.57 鼠标选择/剪贴板工作流落地后，候选区需能对接点选（见 3.3）。

### 2.5 光标跟随（行 / 列）

- **现状**：`anchor_row` 由调用方在进入 readline 时设置（`keyboard.c:398`），`ime_bar_row()` 把候选条放到输入行下一行，输入行在最后一行时回退上一行（`ime.c:58-64`）。**列不跟随**：候选条恒从第 0 列起绘制。编辑器循环内**不调用** `ime_set_anchor()`（全仓仅 `keyboard.c:398` 一处调用），编辑器内锚点停留在进入编辑器前的行号。
- **差距**：候选条不随输入光标列定位；编辑器多行编辑时锚点不随 `ed_cy` 移动。
- **影响**：长行/编辑器场景下候选条可能遮住新输出或落在错误行。

### 2.6 与选中 / 剪贴板集成

- **现状**：HEAD 无剪贴板、无文本选中子系统（grep `clipboard/paste/selection` 无功能命中；`shell.c` 的 `copy` 仅指文件 `cp`）；上屏路径只有 `rl_insert()` / `ed_insert_utf8()` 两条直插通道。
- **差距**：选中候选不会进入剪贴板；中键粘贴等路径与 IME 无对接。
- **影响**：依赖外部剪贴板子系统先落地（第 4 章依赖 D2）。

### 2.7 候选分页与总数显示

- **现状**：已显示“当前页/总页数”（`ime.c:92-94`）；窄列下放不下的候选被整项跳过（`ime.c:102-110`），但跳过项仍可翻页到达；未显示候选总条数（仅页数）。
- **差距**：无总字数直显；分页状态完全依赖键盘；无首尾页边界提示（越界页码在 `ime.c:87-88` 静默回第 1 页）。
- **影响**：低风险体验项，可在阶段三补全。

### 2.8 生僻字与 GB2312 外字符

- **现状**：拼音表 6,763 字全部可被 GB2312 编码（附录 A 实测）；字库为 GB2312 子集 + 198 个标点/符号；表外码点 `render_font_hz()` 返回 `0` → 画 `?`。text 模式 VGA 字库整段无中文字形（问题清单 #117，已知限制）。
- **差距**：GB2312 以外的罕用字、扩展区字符无法输入也无法显示；无 U+20000 以上扩展支持。
- **影响**：本期设计范围限定在 GB2312 常用集；扩字库属独立工具链任务。

### 2.9 繁简转换

- **现状**：字库与拼音表均为简体 GB2312 子集；无繁简映射表，无切换开关。
- **差距**：不能输出繁体；无简→繁映射数据。
- **影响**：列为远期项，不在本期三阶段内承诺。

### 2.10 其它已识别缺口

- 无模糊音（如 `z/zh`、`in/ing`）、无声调选择；
- 用户选词不持久化（无用户词典落盘）；
- 上屏通道 `out[5]` 只够 1 个三字节汉字，词组上屏需加宽；
- IME 全局单实例，readline / 编辑器 / 未来其它输入入口共享状态。

## 3. 三阶段可落地设计

### 通用约束（三阶段共同遵守）

1. **整数化**：内核 freestanding 构建为 `-m32 -O2 -std=c99 -mno-sse -mno-mmx -mno-3dnow -mno-80387`（`build.sh:26`），无 FPU/SSE 可用；**所有排序键、频次权重、页码宽度计算一律用 `int / uint16_t / uint32_t` 整数**，禁止 `float/double`、禁止浮点库调用。
2. **离线建表、提交源码**：沿用 `pinyin.inc` 模式，词表/权重由 `tools/gen_*.py` 在构建机离线生成、提交进源码树；内核运行期不依赖 Python、pypinyin、jieba 或任何字体文件。
3. **保守内存预算**：CatOS 项目内存上限 4 GiB，但内核静态表按“几十到几百 KiB”量级保守规划；新增只读表必须给出条目数 × 单条字节数的上限算式。
4. **不破坏现有三态接口语义**：`IME_PASS / IME_CONSUME / IME_COMMIT` 保持；缓冲区加宽以新增常量方式扩展，不改动返回值编码。
5. **回归不劣化**：现有手工链路（F2 → 音节 → 选字上屏 → `^S` 保存 → `cat` 回显，见 `docs/历史记录.md` 第二部分 v2.33 节）在每阶段后必须复跑通过。

### 阶段一：两行固定候选区 + 内联拼音串（UI 定案，已拍板）

#### 3.1.1 目标

把候选区从“输入行下一行的单条状态栏”改为**屏幕最底部两行**固定布局；拼音串回到输入位置（命令行/编辑器光标处）内联显示；候选条目格式固定为 `1.好 2.号 3.浩`；每页候选数按列宽自适应，**不少于现有 PER_PAGE=9**，列宽允许时可放更多；gfx24（vbe24）与 text 两种模式都正确绘制；状态栏保存/恢复语义覆盖两行（分隔行 + 候选行）。

#### 3.1.2 定案布局（实现口径，不得偏离）

- **倒数第二行**：整行横线分隔，铺满可视列。字形约束：U+2500 框线字符当前**无在册字形**（2.3），落地顺序为：
  - 方案 A（首选，不改动字体工具链）：后端用现有字符/单元格绘制——重复 ASCII `-`（`font8x8_basic` 在册）铺满，或由后端对整行做底色/反白填充形成横线；
  - 方案 B（可选跟进）：向 `tools/unifont-cjk-punct.hex` 补 U+2500 字形，经 `gen_hz_font.py` 离线重生成 `font_hz.inc`，再用框线字符绘制。
- **最后一行**：候选列表，格式 `编号.汉字`，候选之间空格分隔；编号从 1 开始；每行可放个数按 `con_cols()` 整数预算计算。
- **拼音串位置**：显示在输入处（readline 草稿行光标后 / 编辑器光标处），**不进候选区**；候选行只放分隔线与候选。
- **交互键位**：数字键选字；`Space` 选首选；`-`/`=` 或 `←`/`→` 翻页；`Esc` 取消；`F2` 开关；`Backspace` 编辑拼音串；其余键行为沿用现状。
- **双模式**：vbe24（gfx24）与 text 模式都要绘制正确；`be_gfx` / `be_vbe` 沿用同一前端单元格契约，顺带验证。

#### 3.1.3 数据结构

```c

#define IME_PER_PAGE_MIN  9      /* 现有 PER_PAGE，保底页数 */
#define IME_COMPOSE_MAX   16     /* 阶段一音节串上限，沿用 py[8] 可先扩到 16 */

typedef struct {
    int  index;        /* 候选在全量列表中的序号（0 起） */
    int  col_start;    /* 该候选在候选行的起始列（阶段三命中测试预留） */
    int  col_width;    /* 占宽：数字位数 + 1(点) + 2(汉字) + 间隔 */
```

渲染侧（`render.c` 现行为单行 `saved_row[] / saved_row_valid / saved_row_index`，`render.c:69-71`）扩展为两行保存态：

```c

```

#### 3.1.4 算法（全部整数运算）

1. **宽度预算**：设可视列 `cols = con_cols()`。单个候选占宽：
   - 编号位数 `d = 1 + (idx >= 9) + (idx >= 99)`（1/2/3 位，整数比较）；
   - 候选宽 `w = d + 1(点) + 2(汉字) + 1(候选间空格)`；两位数候选起 `w = d + 1 + 2`，尾部空格在列宽不足时最先省略。
2. **逐候选累加**：`used += w`，`used > cols` 即停止；保底目标 9 个；若 9 个仍放不下（40 列窄网格），先省略候选间空格（`w` 减 1）再评估，仍不足则按实际可放数渲染并在阶段三适配窄屏，不得截断半个汉字。
3. **页码/总数**：沿用现有 `total = strlen(hz)/3`、`page` 计算（`ime.c:86-94`）；横线行不参与候选计数。
4. **内联拼音串**：IME 对外暴露只读组合串访问器（拟 `const char *ime_composition(void)`）；readline / 编辑器在重绘草稿行时，于光标后追加绘制该串；提交或取消后清空。
5. **两行保存/恢复**：开条目前先备份倒数第二行、最后一行原始单元格；候选行切换、关闭、后端切换、清屏时两行一并还原；text 模式恢复后触发字槽重建（沿用 `con_status_bar_off()` 的 `redraw_all()` 路径，`render.c:725`）。

#### 3.1.5 内存预算（保守）

| 项 | 预算 | 算式 |
|---|---:|---|
| `slots[]` 表 | ≤ 17 × 12 B ≈ 204 B | `IME_PER_PAGE_MIN + 8` 条 × 3 个 int |
| 组合串缓冲 | 16 B | `IME_COMPOSE_MAX` |
| 渲染两行保存槽 | 2 × 100 × `con_cell_t` | 复用现有单元格结构；单格大小以 `render_be.h` 定义为准，不新增像素缓冲 |
| 候选行文本缓冲 | `BAR_MAX` 由 200 评估上调至 240 B | 两行分别建缓冲，栈上分配 |
| **阶段一新增静态/栈合计** | **< 1 KiB（不含既有字库/拼音表）** | — |

### 阶段二：多音节分词 + 词组候选 + 整数字频排序

#### 3.2.1 目标

支持连续拼音长串（可含可选分隔符 `'`）；做音节切分与最长匹配；候选池合并词组与单字；按离线词频 + 运行期学习加成的**整数权重**排序；词组可整词上屏。

#### 3.2.2 数据结构（拟）

```c
/* 离线只读词组表（tools/gen_phrase.py 生成并提交） */
typedef struct {
    uint16_t phrase_off;   /* 短语串在共享字符串池的偏移（UTF-8） */
    uint16_t py_seq_off;   /* 音节序列在拼音池的偏移 */
    uint8_t  hanzi_cnt;    /* 字数（2..6） */
    uint8_t  _pad;
    uint16_t base_rank;    /* 离线内置权重带 0..4095 */
} phrase_entry_t;

/* 拼音 trie 节点（静态数组，离线生成） */
typedef struct {
    int16_t  child[26];    /* 子节点下标，-1 表示无；按字母索引 */
    uint16_t phrase_idx;   /* 该节点结束的词组条目下标，0xFFFF 表示无 */
} trie_node_t;

/* 运行期学习计数（静态，上限饱和） */
typedef struct {
    uint16_t phrase_idx;
    uint16_t learn_cnt;    /* 0..4095 饱和 */
} learn_slot_t;
```

候选运行期结构：

```c
typedef struct {
    uint8_t  kind;         /* 0=单字 1=词组 */
    uint16_t ref;          /* 单字: py_tab 下标 + 字内偏移；词组: phrase_idx */
    uint8_t  hanzi_cnt;
    uint32_t sort_key;     /* 整数排序键，见 3.2.4 */
} ime_cand_t;
```

#### 3.2.3 算法

1. **音节切分**：输入字母流先按合法音节表（现有 400 条）做左贪心最长匹配；允许 `'` 作为显式分隔符；切不出来的尾段保留为“未完成串”，不报错清空。
2. **候选收集**：
   - 词组：trie 沿切分后的音节路径匹配，命中条目入候选池；
   - 单字：沿用现有 `py_tab` 精确/前缀查询，逐音节入池；
   - 同一字面去重，保留权重更高者。
3. **整数排序键**（无浮点）：
   - 离线 `base_rank ∈ [0, 4095]`（jieba 词频分带，构建期量化为整数带）；
   - 运行期 `learn_cnt ∈ [0, 4095]`，每次该词组被上屏 `learn_cnt = min(learn_cnt + 增量, 4095)`；
   - `sort_key = ((uint32_t)base_rank << 12) | (learn_cnt & 0xFFFu)`；单字条目 `learn_cnt` 取 0；
   - 按 `sort_key` 降序；键相同时按离线内置序号升序（稳定tie-break），不引入随机或浮点。
4. **上屏通道加宽**：`ime_feed` 输出缓冲由 `out[5]` 扩为 `IME_OUT_MAX`（拟 `3*8+1 = 25` B，最多 8 个汉字 + NUL）；调用方按串长插入。
5. **退格回退**：退格先回退词组分段，再删音节字母；Esc 清空整串。

#### 3.2.4 内存预算（保守上限）

| 资产 | 预算上限 | 算式 |
|---|---:|---|
| 词组表 `phrase_entry_t` | ≤ 4,000 条 × 8 B = 32,000 B | 5 字段 + 对齐填充 ≤ 8 B/条（32-bit） |
| 共享字符串池（短语 UTF-8） | ≤ 64 KiB | 4,000 条 × 平均 16 B 估算，封顶 64 KiB |
| trie 节点 | ≤ 8,000 节点 × 54 B（26×int16 子指针 + uint16 条目号）= 432,000 B ≈ 421.9 KiB → **超限需压缩**：改为稀疏子表或仅保留首/尾字母索引，目标 ≤ 128 KiB | 落地前按实际节点数复核 |
| 学习计数表 | ≤ 256 条 × 4 B = 1,024 B | 环形槽，LRU 式淘汰 |
| 候选运行期数组 | ≤ 32 条 × 12 B = 384 B | 栈/静态 |
| **阶段二新增合计** | **词组只读表 ≤ 256 KiB（题目口径）；含 trie 与学习表整体 ≤ 320 KiB** | trie 压缩不达标则先砍词组条目数 |

#### 3.2.5 接入点

- `ime.h`：`ime_feed` 输出缓冲常量 `IME_OUT_MAX`；新增词组查询/排序内部函数声明不外露。
- `tools/`：新增 `gen_phrase.py`（输入离线词频表，输出 `phrase.inc`）；`gen_pinyin.py` 保持单字表不动。
- `keyboard.c` / `shell.c`：上屏插入按 UTF-8 串长处理（`rl_insert` / `ed_insert_utf8` 现状已按长度插入，复核多字节边界）。
- 持久化（可选，阶段二尾段）：学习计数写 `/etc/ime.udict`，FS 不可用时静默退化为纯内存。

#### 3.2.6 回归与测试口径

## 附录 A：统计方法与口径

> 下列数字均在 HEAD `aae8640` 上实测；统计脚本为一次性 Python/grep 命令，未写入仓库。

1. **行数 / 字节数**：`wc -l`、`wc -c` 对 `src/ime.c`、`include/ime.h`、`src/pinyin.inc`、`src/font_hz.inc` 直接统计。
2. **拼音表解析**：正则 `\{"([^"]+)",\s*"([^"]*)"\},?\s*/\*\s*(\d+)\s*\*/` 逐行提取音节名、`\xXX` 转义串、注释计数；转义串按字节收集后按 UTF-8 解码；条目数 = 匹配行数；候选槽数 = 各条目解码后字数之和；去重字数 = 集合大小；最大候选 = 单条目字数最大值及对应音节；长度分布按音节字符数聚合；`>9 / >18` 与分桶按条目字数统计；GB2312 可编码性逐字尝试 `encode('gb2312')`；非三字节字符检查 `len(c.encode('utf-8')) != 3`。
3. **字形表解析**：正则提取 `{0xXXXX,` 码点；条目数 = 码点个数；汉字区计数为 U+4E00..U+9FFF，其余按 < U+4E00 与 > U+9FFF 两档统计；结构尺寸按 `uint16_t`(2 B) + `bits[32]`(32 B) = 34 B/条估算（32-bit ABI）。
4. **内存估算**：指针宽 4 B（`-m32`，`build.sh:26`）；`py_entry_t` = 8 B 数组 + 4 B 指针 = 12 B/条；UTF-8 候选池按 3 B/字；KiB 换算按 1024。
5. **后端网格**：取自 `be_text.c / be_gfx.c / be_vbe.c / be_vbe24.c` 后端描述符的 `cols/rows/pixel_w/pixel_h` 字段；vbe24 三档格子尺寸取自 `be_vbe24.c` 注释与 `v24_cw()/v24_ch()` 推导。
6. **缺失核查**：鼠标/剪贴板/分页器/`keys`/`clip`/`videomode` 等关键词在 `kernel_v25/src` 与 `include` 全量 grep，无功能命中即判定 HEAD 未落地；命中项逐一人工甄别（如 `be_vbe24.c` 的 `clip()` 为几何裁剪辅助函数，与剪贴板无关）。

# 五、v2.67 安全审计基线

# CatOS v2.67 安全审计：怀疑一切

> 本文对应 `kernel_v25/src/sec.c`、`posix.c`、`hive.c` 与 `shell.c` 分发器里的实际代码。
> 运行时同一份结论可以用 `audit` 命令打印（策略快照 + 决策日志）。

## 1. 威胁模型

CatOS 是单地址空间的内核：ring0 里跑 shell builtin，ring3 里跑 `.ce`。没有 MMU 隔离、
没有 NX、没有 ASLR、没有签名体系。因此**不能声称"防病毒"**，只能做到三件事：

1. 让"谁可以执行什么"成为**可配置、可审计**的显式策略，而不是散落在各命令里的一行 `if`；
2. 让所有拒绝都有**统一出口与日志**（`sec_audit`），不出现静默失败；
3. 让"可疑输入"默认失败（fail closed），而不是默认放行。

## 2. 能力模型

| 能力 | 位 | 保护对象 |
|---|---|---|
| `NET` | 0x0001 | curl / ping / dns / udp / netcfg / netdiag |
| `KILL` | 0x0002 | kill |
| `FSADMIN` | 0x0004 | format / fsck / mount / umount |
| `AUDIO` | 0x0008 | sndtest / sndinfo |
| `USERADM` | 0x0010 | useradd / userdel / passwd / chcaps / su / chown / hive 写 |
| `DEVICE` | 0x0020 | 原始设备访问 |
| `SYS` | 0x0040 | shutdown / reboot |
| `FORMAT` `FSCK` `RAWIO` `HWINFO` `REBOOT` `DIAG` | 0x0080..0x1000 | FSADMIN / DEVICE / SYS 的细分位 |
| `ALL` | 0xFFFFFFFF | root 等价 |

判定规则：`uid == 0` 直接放行；其他用户必须**持有全部所需位**（不是任意一位）。
`sec_allow()` 在 `shell_exec` 分发之前统一调用，命令体不再各自判断。

### 深度自定义（无需重新编译）

```
hive set HKSEC\Policy\Cmd\curl\Caps      "NET|KILL"   # 提高要求
hive set HKSEC\Policy\Cmd\format\Caps    "none"       # 显式降权（危险，需 root）
hive set HKSEC\Policy\Cmd\shutdown\Caps  "NET"        # 改需求
hive save
```

- 键不存在 → 使用内置表；
- 值为空 / `none` / `guest` → 无要求；
- 值存在但**解析失败**（拼错、未知名） → `SEC_HOSTILE`，命令一律按"权限不足(13)"拒绝。
  这样一份被写坏的 hive 永远不会"意外放开"权限。

## 3. 可执行文件策略

`run_from_path()`（cwd 优先，然后 `$PATH`）在 `spawn` 之前调用 `sec_exec_check()`：

- `HKSEC\Policy\Exec\Strict=1`（默认）时，拒绝**world-writable / group-writable** 的 `.ce`；
  这是"放个文件到共享目录就能以启动者身份执行"的经典提权路径。
- 每次外部执行都写 `exec-ce` 审计记录（含绝对路径）。
- 内置命令永远优先于同名文件，所以 `ls`、`cat` 这类核心命令无法被同名 `.ce` 劫持。

## 4. 前台任务独占（用户说的"强制不能操作"）

- 任何 builtin 在 ring0 同步执行，**不主动让出 CPU**；键盘 IRQ 仍在缓冲按键，但 shell
  要等命令返回才读取，因此一个死循环能长期占住控制台。`hang` 就是刻意演示这一点的命令。
- 只有自行轮询 `kb_getkey_timed()` 的命令才响应 Ctrl+C（`yes`、pager、`sleep`）。
- 目前**没有**看门狗、没有每任务 CPU 配额、没有"强制夺回控制台"的路径。
  缓解手段只有 Ctrl+Alt+Del 与物理复位。这是已知缺口，不是已修问题。

## 5. 已知攻击面（未修）

| 面 | 说明 | 现状 |
|---|---|---|
| `/etc/autoexec` | 开机以 root 执行脚本 = 持久化后门 | 目录应 root 0755；`ls -l` + `chmod` 自检 |
| `pkg install` | v2.68 起为 CPKG02 + RSA-512 验签（`pkg_verify`），签名不符拒绝安装；私钥不进内核 | 只从自己控制的目录安装 |
| 无隔离 | `.ce` 与内核同地址空间 | 架构性限制 |
| 无签名 | `UnknownBinary.AllowUnsigned=1` 默认允许 | 策略键存在，校验器尚未实现 |
| 中断风暴 | 旧 ES1370 驱动不使能 INTEN；若使能会 IRQ storm | 驱动层已规避 |

## 6. 审计日志

`sec_audit(uid, kind, what, rc)` 写入 48 条定长环形缓冲（tick / uid / 结果 / 类型 / 命令）。
`audit` 打印策略快照与最新条目，`audit -n N` 限制条数，`audit --clear` 清空。
记录类型：`exec`、`usage`（语法错误）、`deny`（权限拒绝）、`deny-exec`（可执行文件被拒）、
`exec-ce`（外部程序执行）。

## 7. 命令语法契约（posix.c）

统一 POSIX 语义，全部在命令体执行**之前**判定：

| 场景 | 输出 | 退出码 |
|---|---|---|
| 未知短选项 | `cat: invalid option -- 'z'` + `Try 'cat --help'` | 2 |
| 未知长选项 | `ls: unrecognized option '--bogus'` | 2 |
| 缺操作数 | `cat: missing operand` | 2 |
| 多余操作数 | `ps: extra operand 'x'` | 2 |
| 文件不存在 | `cat: /no/such: No such file or directory` | 1 |
| 权限不足 | `format: permission denied (need CAP_...)` | 13 |

`--help` 对表中所有命令自动可用（印出 synopsis + 允许的选项 + 退出码约定）。
