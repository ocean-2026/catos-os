# v2.72 补充说明（VMware 反馈轮）

本轮针对 VMware 上反馈的三条渲染现象 + 一条声卡现象做处理，并把 v2.72 里
"sshd 开机自启动"删掉。**能自证的已经自证，不能自证的写明为什么。**

## 1. 字体底色 ≠ 背景色（渲染 #4）

根因不是 alpha，也不是字体缓存：**主题应用得太晚**。

`shell_run()` 的启动顺序原来是
`boot_apply_videomode()` → `pal_apply_scheme()`。前者切到 vbe24 时用当时的
背景色（默认 `#0C0C0C`）清了一整帧；后者随后把 `PAL_BG` 换成注册表里的主题色
（例如 `#0A0E14`）。**之后只有被"写"过的单元格用新底色，没人重画的地方还是旧底色**，
于是字块和背景出现色差，且留下一个矩形边界。

修法两条：
1. 启动顺序改为 **主题先应用，再切显示模式**；
2. `pal_apply_scheme()` 结尾调用新增的 `con_repaint_frame()`：
   `be->clear(s_bg_rgb)` + 全格重绘，文字不丢，整帧同色。

`con_clear()` 不能用——它会把文字一起清掉。

## 2. 开机几秒的频闪（渲染 #2）

同一条链路上还有两次多余的全屏清屏：

| 位置 | 原来 |
|---|---|
| `v24_enter_svga()` / `v24_enter_bochs()` | 切模式后再 `gfx24_clear()` 一次 |
| `v24_set_scale()` | 又被 `size_restore()` 调起，再清一次 |
| `switch_backend()` → `redraw_all()` | 又 `be->clear()` 一次 |

在 VMware SVGA 上每一帧都会被宿主以 25 Hz 重贴（`svga_tick()` → `svga_flush()`
发 `SVGA_CMD_UPDATE` 全屏矩形），所以**连续三次全屏清空=肉眼可见的闪三下**。
现在只保留 `redraw_all()` 那一次，`enter()` 与 `set_scale()` 都不再清屏。

## 3. 分辨率"不严丝合缝"（渲染 #3）

先把事实钉住：`svga_mode_set()` 本来就会回读 `SVGA_REG_WIDTH/HEIGHT` 并在
不一致时 `goto fail`，所以**"要 800x600 却真给了别的尺寸"这条路不存在**。
截图里那块颜色不同、边界正好 640x400 的矩形，是上面第 1 条留下的旧底色
（640x400 = 80×25 文本模式的像素范围，正好是切换前那一帧的大小），不是
"VMware 给的屏幕比要的小"。

因此这一条的修法就是第 1 条：整帧统一重绘，边界自然消失。另外为了以后能从
日志而不是截图定位，启动时多打一行真实几何：

```
[display] boot mode: vbe24 (800x600, 100x37 cells @8x16)
```

`vdiag` 里仍然有 pitch/stride/lfb/bar 的原始值。

## 4. 声卡（VMware ES1371 无声）

**没有盲改。** 现状是拿 ES1370 的寄存器布局去编程 ES1371：DAC1 走
MEMPAGE=0xc 窗口的 `0xc30/0xc34`、采样率走 `CTRL` 的 `WTSRSEL` 两位。
ES1371 的 AK4531 codec 是**只写**接口，读不回来；没有实机读数就写序列，
等于把"没声音"换成"可能是另一组寄存器写坏了"，而且无法验证。

本轮加的是取证工具：`sndregs` 直接打印原始寄存器。

```
snd: ensoniq id=1274 dev=5000 io=0xc000 irq=11 ready=1
  CONTROL=0x100  STATUS=0x60  SERIAL=0x83
  SCOUNT=0x0  FRAMECNT=0x0  PORT20=0xd3
  rate=5512 bufsz=65536
```

判读方法（也已写在命令输出里）：

- 播放时 **FRAMECNT 不动** → DMA 根本没被 arm（寄存器布局/采样率编程错）；
- 播放时 **FRAMECNT 在动但没声** → AK4531 仍处于静音，需要 codec 初始化。

`dev=1371` 时命令返回 `$?=3`（"设备认出来了，通路未验证"），不会假装成功。

## 5. 删除 sshd 开机自启动

- 不再向 `/etc/autoexec/` 播种 `sshd.sh`；
- `@sshd` 的内置守护分支删除（该分支只为开机启动 sshd 而存在）。

`sshd` / `sshd -d` 手动启动仍然可用。理由：一个开机就监听的 :22，加上尚未
做签名校验的 `pkg` 通路，是负债不是特性。

## 6. 其他

- `about` 的 logo：首行与末行各加一个前导空格（按反馈）。
- 启动 banner 的版本号从 `v259` 更正为 `v2.72`。

## 验证

- `-vga std`（Bochs dispi）：整帧 `#0C0C0C` 单一底色，文字区无矩形边界；
  `sndregs` 在 `-device es1370` 下输出上述原始值，无异常。
- `-vga vmware`：QEMU 6.2 的这个 VGA 设备无法完成 GRUB 的 VBE 模式设置，
  开机黑屏，**因此本轮没有在 QEMU 上复现 VMware SVGA 路径的像素结果**。
  需要你在 VMware 里跑一次：看启动行 `[display] boot mode: ...`、`vdiag`、
  `sndregs`，把输出发我，我再据实修正。
